# EvoAgent 整体 Agent 能力核查（2026-09-26）

本核查区分三种结论：**代码存在**、**自动化测试通过**、**真实用户场景通过**。Agent 的基本判定是模型能依据目标选择下一步与工具，观察结果后继续直到完成或移交用户；可靠交付还需要边界、恢复、可观测性和有代表性的效果评测。EvoAgent 的定位是本地受控部署的 Agent Runtime，不是已有账户体系的公网多用户产品。

## 当前结论

配置真实 Provider 时，EvoAgent 已是**可运行的基础 Agent 原型**：网页可提交任务，模型能在循环中选择工具、取得结果并回答，任务/工具状态可追溯。它尚不能称为**充分验收的通用 Agent 或生产级产品**。默认配置仍是 Mock；真实任务样本窄，前四阶段计划中的若干联合故障场景未通过真实页面验收；本地 API 没有多用户认证/授权，不能直接作为公网产品。

## 必须补的证据和产品缺口

1. 按[补完计划](前四阶段补完与用户场景验收计划.md)在最新镜像上联验真实页面 Workspace 操作、长上下文、超时与参数错误、COMMITTED/UNKNOWN 人工处理，以及双 Worker 运行中故障和页面/数据库一致性。现有结果分散在固定 Trace、SQLite 子进程和真实模型专项试验中。
2. 建立覆盖多类型实际任务的冻结任务集与人工/程序判分：成功率、错误率、需要人工接管比例、成本/延迟、工具选择正确性及风险回归；对可客观核对的任务增加目标完成判定。算术与 10 条同域检索样本不足以判断“通用任务 Agent”质量。
3. 改善首次运行体验：默认 `docker-compose.yml` 强制 `EVOAGENT_PROVIDER=mock`，默认搜索也是 Mock、记忆关闭。应在启动说明和页面明确当前模式，并提供可验证的真实 Provider 启动/就绪检查，避免用户把演示回复当成真实 AI。
4. 正式发布前重新构建当前提交的镜像并重做部署检查；当前运行中的 `evoagent:phase4-final` 镜像创建于 2026-09-25 22:32，早于后续 `faadfa6`、`f7906c2`，因此本次实时任务证明的是运行中镜像的核心闭环，不等于最新前端修正已部署。历史模块 14 manifest 的 `real_embedding: pending` 保持冻结，需另做包含后续证据的新版发布清单。

本次没有把“测试全绿”解释成质量合格或生产就绪。详细真实样本和局限见[前四阶段阶段性验收](前四阶段补完阶段性验收-2026-09-25.md)。
