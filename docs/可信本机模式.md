# Windows 可信本机模式

这个模式让 API 和执行 Worker 直接运行在 Windows 用户会话下。网页可创建不绑定项目的普通对话，也可登记 Windows 绝对路径，选择只读或可写，并把项目绑定到会话或仅用于下一条任务。与 Docker 个人模式分别使用数据库、Redis 命名空间和 Workspace；两边的会话和项目不会自动同步。这是可信用户模式，**不是受沙箱保护的 Windows 桌面代理**。

## 启动

需要 Windows、Python 3.12/3.13、Docker Desktop、Node.js 24 和 pnpm 11。先安装仓库依赖，将 `.env.personal.example` 复制为根目录的 `.env.personal`，填写对话模型的 API Key、Base URL、模型名、**真实**上下文窗口。要用付费模型，还须按[个人模式操作手册](个人模式操作手册.md)设置完整 `trial` 额度和输入/输出价格假设。本模式另外要求非空的 `EVOAGENT_PROJECT_COMMAND_ALLOWLIST`，例如 `EVOAGENT_PROJECT_COMMAND_ALLOWLIST='["python","git"]'`；列出的程序必须在 Windows 当前用户的 PATH 中。不要把私有文件提交到 Git。仓库根目录执行：

```powershell
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend run build
.\.venv\Scripts\python.exe scripts/host_mode.py
```

脚本启动独立的 PostgreSQL/Redis（本机端口 `15436`/`16382`），迁移新库，并在同一 Windows 进程运行 API、普通 Worker 与维护 Worker。打开 `http://127.0.0.1:18020/ui/`。前台按 Ctrl+C 退出应用；数据卷保留。需要停数据库时执行：

```powershell
docker compose -p evoagent-host -f deploy/host/compose.yml down
```

不要加 `-v`，否则会删除该模式的数据库卷。Docker 个人模式的 `8000` 端口仍可独立运行。

本机模式有独立付费账本，不会自动把其它 Compose 项目的已花额度相加。若多个部署共用同一模型账户，应按账户剩余额度分别设置各实例上限。`scripts/host_mode.py` 只在 Windows 运行，固定监听 `127.0.0.1:18020`；启动时自动拉起本模式的数据容器并迁移到当前 head。页面打不开时先看启动窗口报错与[运营故障指南](运营故障指南.md)。

## 会话、目录和权限

- 不选项目即可聊天、搜索和使用非项目工具。**不绑定项目的任务没有项目文件/命令工具**；需要操作电脑上的某个目录时，必须先登记它。登记 Windows 目录后，选择“绑定到本会话”或“仅下一任务使用”。后者保持会话不绑定项目，单个 Task 冻结这次的项目授权。
- 目录登记默认只读；切换为可写后，Agent 才看到精确编辑和项目命令工具。撤销或改变授权版本后，在跑任务的下一次工具调用被拒绝。
- `run_command` 只在明确开启本机模式且有白名单时提供。Windows 命令每次都是 R2 审批，审批页显示 argv。命令需要 `allow_network=true`，因为当前没有可靠的 Windows 进程级断网隔离。
- 要使用 PowerShell，在 `.env.personal` 的 `EVOAGENT_PROJECT_COMMAND_ALLOWLIST` 中显式加入 `powershell`。模型可调用 `argv=["powershell","-NoProfile","-Command","..."]`；脚本内容不受项目路径解析器约束，必须逐次核对审批内容。
- Windows 子进程按当前用户身份运行。授权根会限制内置文件工具与工作目录，但用户批准的解释器或构建程序仍可能访问根外文件与网络。当前本机模式只限制 argv 白名单、超时和输出量；不承诺 Linux Landlock/seccomp、进程树内存/CPU 配额或 OS 级文件沙箱。`allow_network=true` 表示承认该事实，不是提供网络目的地白名单。请根据完整命令和目标目录逐次决定是否批准。
- 本机模式不提供鼠标、键盘或任意桌面应用的自动操作；外部发布命令仍由 `run_command` 拒绝。
