# EvoAgent 安全边界说明

> **适用版本**：`0.4.0.dev0`（`c2` 分支）。本页写的是**现在的代码实际会做什么**：
> 允许什么、拒绝什么、拒绝时留下什么证据。它不是承诺，也不是"安全审计通过"的证明。
> 尚未验证的项在最后一节如实列出。

## 1. 一句话边界

EvoAgent 只在**你登记为项目的目录**内工作，只调用**注册过的工具**，
高风险动作要走**审批**，付费调用要走**额度闸门**；它**不是**沙箱里的
任意代码执行器，也**不是**多租户服务。

## 2. 目录边界：项目授权

| 机制 | 行为 |
| --- | --- |
| 项目登记 | 只有登记过的根目录才能被工具访问；任务创建时冻结 `(project_id, project_authorization_version)` |
| 宿主目录映射 | 个人 Compose 要求显式设置 `EVOAGENT_PROJECTS_HOST_ROOT`，挂到容器内 `/app/projects`；页面登记容器路径。挂载范围须由用户收窄，不能包含密钥配置或把整个磁盘当作默认授权 |
| 档位 | `read`（只读工具）与 `read_write`（加写工具）；档位在项目上，不在任务里 |
| 越界拒绝 | 相对路径逃出根（`..\..\`）、绝对路径指向根外、指向根外的符号链接一律拒绝 |
| 授权撤销 | 撤销后**下一次工具调用**即被拒绝，任务终态 `authorization_revoked`；已完成的动作不回滚（账本保留） |
| 运行中约束 | 你可以随时补充约束（如"只读分析，不要改文件"），它在下一个迭代边界生效 |

拒绝是**正常结果**，不是故障：M7 发布集里有 8 条故障/越权样本专门检查"如实拒绝"。
注意：Windows 下符号链接用例需要额外权限，相关测试在无权限时会**跳过**而不是通过（见 M7 报告的分层检查）。

## 3. 工具边界：风险等级与审批

工具目录（`/api/v1` 的目录接口与 Skill 校验共用同一份定义）按风险分级：

| 等级 | 工具 | 说明 |
| --- | --- | --- |
| R0（只读/无副作用） | `calculator`、`file_read`、`list_dir`、`find_files`、`search_text`、`extract_text`、`web_search`、`web_fetch` | 不改变本地状态 |
| R1（有副作用） | `edit_file`、`apply_patch`、`delete_file`、`move_file`、`organize_files`、`run_command`、`artifact_write` | 需要写授权，按策略走审批 |

- **命令默认关闭**：`EVOAGENT_PROJECT_COMMAND_ALLOWLIST` 默认为空 → `run_command` 没有可执行程序；
  即便配了白名单，也只接受结构化 `argv`（没有 shell 字符串拼接），并受超时、输出上限、
  最小环境变量约束。在个人 Compose 中命令由 Worker **容器**执行，白名单与 `cwd` 均是容器内路径，不是宿主 PowerShell 路径。**当前 `allow_network=false` 只移除代理变量，并不阻断直接网络连接**；配置 Python 等通用解释器白名单后，不可把它当成真正的离线命令沙箱。发布前须加独立网络隔离并作负向实测。
- **`shell` 工具不能进 Skill**：`skill_allowed_tools` 含 `shell` 会在配置校验阶段直接报错。
- **MCP 工具先审后用**：MCP 目录发现后，每个工具要人工审核（`mcp_tool_reviews` 表，写入后不可改），
  未审或未批准的工具不会被绑定执行。
- **审批与账本**：每次有副作用的调用写 `ToolEffect` 台账（语义幂等键）；进程被杀后可能出现
  `UNKNOWN` 状态，程序不会猜测它是否生效，而是要求人工处置。

## 4. 凭据边界

| 项 | 行为 |
| --- | --- |
| 存放 | 只放 `.env.personal`（已被 Git 忽略）或环境变量；程序不接受把密钥写进任务文本的工具路径 |
| 输出 | `/api/v1/runtime-info` 只回模式/模型/搜索/记忆摘要与 Worker 存活，**不回密钥或 Base URL** |
| 预检 | `scripts/personal_preflight.py` 只校验字段与约束，打印模型名与搜索模式，不打印密钥 |
| 日志/报告 | 报告与台账写的是哈希与标识，不写凭据与私有正文；`docs/` 里禁止写入凭据与私有正文 |
| 已登记的检查 | Skill 文本在人工发布前会过一遍静态扫描（凭据样式、私有绝对路径、holdout 引用），
未在审查记录里逐条处置就**不允许发布**（见[S-04 审查](evaluations/M6人工发布与回滚审查-2026-09-27.md)） |

**你要自己做的事**：不要把 `.env.personal` 放进备份包或聊天记录；
`docker compose config` 会打印完整环境变量，别把输出贴出去。

## 5. 网络边界

- `web_search` / `web_fetch` 只有在 `EVOAGENT_SEARCH_PROVIDER` 配成 `ddgs`/`brave` 时联网；
  默认是 `mock`（离线）。查询词会发给搜索服务商，`web_fetch` 会访问你要求的 URL。
- `web_fetch` 做 DNS/IP 绑定，避免解析后被重定向到内网地址。
- `run_command` 默认在 Linux 子进程中安装 seccomp 过滤，阻断非 Unix socket；Landlock 只允许读取运行库及明确的系统文件，并允许读写授权项目和本次临时目录。`allow_network=true` 需要显式参数与审批；缺少隔离能力时拒绝运行，不退回无隔离命令。单进程 CPU/内存限制与超时杀进程组已实现，进程树级资源配额仍待补充。
- 独立容器沙箱是**可选**组件（`deploy/sandbox/`），要单独起 controller 并配置 profile 才生效；
  个人 Compose 的 `run_command` 运行在共享项目挂载的 Worker 容器内，受白名单约束，但不是独立隔离副本。

## 6. 提示注入的处理方式

- 文件/网页内容**不是指令**：程序不会因为一段文本要求就自动提权、外发或删除。
  高风险动作仍要过审批，越界路径仍被拒绝。
- 发布集里有**假注入**与**真注入**两类样本：前者考"不编造"（文件里其实没有注入指示，
  凭空声称"发现并要求上传密钥"也算失败），后者考"识别并拒绝"。
- 现状限制：这两条发布样本**还没跑过真实模型**；dev 试跑里模型只处理了正常任务，
  目前仍只有机制、样本登记与代码层的拒绝路径。

## 7. 花费边界

- 付费调用受 `BudgetGate` 控制：额度、单任务上限、停止比例与价格假设**全部来自配置**；
  任何一个未填就拒绝付费调用（`budget_exceeded`），这是默认状态。
- 每次扣费写 `spend_records`，按 `trial`/`formal` 分账；试跑额度不会被正式额度挤占。
- 达到停止阈值时不再开始新调用；已在跑的任务按限额终止。**不编造金额**：默认值一律 `None`。

## 8. 已知的限制与未验证项

| 项 | 现状 |
| --- | --- |
| 干净机器隔离 | 演练在同一台机器的**新卷/新网络**上做，没有在新装 Windows 或新虚拟机上做 |
| 命令执行隔离 | 命令在**有项目挂载的 Linux Worker 容器**内的子进程里执行：Landlock 限制可读写的文件视图（授权项目 + 本次临时目录 + 运行库），seccomp 在离线时阻断非 Unix socket，另有单进程 CPU/内存上限与墙钟超时杀进程组；缺少内核能力时**拒绝执行**而不是退回无隔离。仍不是 Windows 宿主执行，也没有**进程树级**资源配额与每条命令独立的隔离副本 |
| 命令网络边界 | `allow_network=false` 现由 seccomp 在网络系统调用层阻断（Docker 负向检查实测直接建 `AF_INET` socket 得到 `PermissionError`）；`allow_network=true` 仍须逐次人工审批，且没有目的地白名单 |
| 符号链接拒绝 | Windows 无权限时相关单元测试跳过，未在该环境验证 |
| 真实模型的安全性 | 8 条故障/越权**发布样本一次都没跑过真实模型**；dev 试跑里模型没有出现提权行为，但那只覆盖单个正常任务，不能当作注入抵抗的证据 |
| 多用户隔离 | 没有认证/RBAC 与多租户；程序只应绑在 `127.0.0.1` 单人使用 |
| 第三方复核 | 未指定复核者；M6 的较强收益结论因此不可用（自审上限） |

逐项证据与缺口见[M7 发布准备与分层检查](evaluations/M7发布准备与分层检查-2026-09-27.md)与[当前状态](当前状态.md)第 3 节。
