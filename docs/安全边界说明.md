# EvoAgent 安全边界说明

> 适用 `0.4.0.dev0` 候选版。本文说明当前代码的边界，不代表安全审计通过。历史容器实测见[日常任务与安全边界验收](evaluations/M5日常任务与安全边界验收-2026-09-28.md)；未验证项见[当前状态](当前状态.md)。

## 1. 两种模式的边界不同

| 能力 | Docker 个人模式 | Windows 可信本机模式 |
| --- | --- | --- |
| 项目登记 | 页面登记容器内 `/app/projects/...`；宿主父目录由 `EVOAGENT_PROJECTS_HOST_ROOT` 挂载 | 页面登记已有的 Windows 绝对目录 |
| 文件工具 | `read` 可查找/读取；`read_write` 才提供编辑；词法与物理路径校验阻止根外访问 | 文件工具使用同一项目授权和路径校验 |
| 项目命令 | 白名单程序在 Linux Worker 内执行；Landlock 限制文件视图，离线时用 seccomp 阻断网络，另有超时、输出、单进程资源与进程树数量限制 | 白名单程序在当前 Windows 用户身份下执行；每次 R2 审批，限制工作目录、超时和输出量；**没有 OS 级文件/网络沙箱或进程树资源隔离** |
| 网络 | 命令默认离线；联网参数会提升风险并请求审批 | 每条命令必须显式 `allow_network=true`，表示可能联网；没有目的地白名单或可靠断网能力 |
| 数据 | Docker Compose 的数据库与 Workspace 卷 | 独立 PostgreSQL/Redis 卷与 `output/host-mode/workspace` |

**关键区别**：Windows 模式的登记根约束内置文件工具和命令工作目录，**不能限制获批程序自身访问哪里**。即使任务只登记 `D:\project`，获批 PowerShell、Python、构建脚本或其子进程仍能在当前用户权限范围内访问项目外文件和网络。它不是“只允许程序碰登记目录”的硬保证；需要更强隔离时使用 Docker 模式。两种模式都不提供桌面 GUI 自动操作。

## 2. 项目授权与撤销

项目登记要求现存目录；根路径被规范化，根本身是符号链接或 junction 时拒绝。登记默认 `read`，用户显式改为 `read_write` 后才提供项目编辑与 `run_command`。会话可不绑定项目，或长期绑定；也可只给下一条任务指定项目。Task 创建时冻结项目 ID、根和授权版本。用户后来切换页面项目不会改变在跑任务。

撤销或改级会更新授权版本。在跑任务的**下一次工具调用前**重新核对，旧版本被拒绝并留事件；已完成的读取、写入或外部动作不会回滚。已经启动的 Windows 子进程不能保证立即停下，因此“撤销”不是逆转历史动作的开关。目录内的 `..`、根外绝对路径和逃逸链接由文件工具拒绝；项目根不应包含模型密钥、个人凭据或不愿暴露的资料。

## 3. 工具、审批与不确定副作用

工具由注册表、参数校验、风险策略和 ToolExecutor 执行；普通文件编辑按风险等级审批，待审批编辑在页面显示服务端重算的 diff。**自动放行的 R1 编辑没有执行前人工审查**，若任务要求逐项核对，需在实际授权和使用时考虑这一点。Windows 本机 `run_command` 每次强制 R2 审批；批准前应核对完整 argv、脚本正文和项目路径。白名单只限制可执行文件名，不保证该程序做什么。`git push`、`npm publish` 等远端发布命令仍由项目命令工具拒绝。

每次可能有副作用的工具调用写入 ToolEffect 账本。进程故障或超时后若结果不明，状态为 `UNKNOWN` 并等待用户核对；程序不应擅自重放。取消任务只停止后续执行，不能保证已开始的外部动作未生效。通过文件、网页或测试输出注入“忽略规则”的文字不会改变服务端授权，但模型是否正确识别每一种提示注入，仍需真实任务验收。

独立 `shell` 容器是另一条可选执行路径，默认关闭；MCP 工具也需目录审核和执行激活。它们有各自的执行范围和审批规则，不能把它们的隔离或审核结果当作 Windows 本机命令的安全证明。

## 4. 网络、凭据与费用

程序默认搜索 Provider 为 Mock；个人配置样例选无密钥的 `ddgs`，仍会访问公共搜索后端。Brave 需要独立搜索密钥。`web_fetch` 校验 DNS/IP 和重定向，拒绝私网及元数据地址。查询词和目标 URL 可能发往外部服务；搜索结果和网页内容都按不可信资料处理。外部服务限流或不可用时应如实报告失败，不能编造已读取正文。

真实模型凭据放在 Git 忽略的 `.env.personal` 或本机环境变量中。`runtime-info` 不回传密钥和 Base URL；不要把任务文本、日志、报告或截图当作密钥存储。`docker compose config` 可能打印完整环境，不要把输出公开。这个项目没有账户认证/RBAC，API 仅供单人在本机环回地址使用，不应暴露到公网。

付费调用必须配置 scope、总额/试跑额、单任务上限、输入/输出价格假设和停止比例；未配齐就以 `budget_exceeded` 拒绝。试跑与正式评测分账，`spend_records` 留下花费记录。两个独立部署若共用一个模型账户，**各自账本不会汇总账户总花费**，上限需分别保守设置。

## 5. 尚未证实的安全性质

Windows 本机模式缺少 OS 级进程隔离、文件/网络权限约束、进程树 CPU/内存配额及跨多种真实目录的权限/锁/junction 负向验收。Docker 模式的 Linux 隔离测试不能外推到 Windows 本机模式。M7 的 8 条故障/越权样本还没有正式真实模型运行，不能宣称提示注入抵抗或发布级安全通过。新装 Windows 上的干净安装和第三方安全复核也未完成。
