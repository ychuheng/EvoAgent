# ADR-003：任务租约、快照恢复与分类重试

- 状态：已接受
- 日期：2026-09-06
- 范围：阶段二模块 4～8

## 背景

阶段一 AgentRunner 在单进程内一次执行完整任务。进程退出后，消息历史、事件和运行位置都会消失。阶段二需要让 API 快速接受长任务，让 Worker 可以崩溃接管，同时避免把数据库事务、恢复细节和重试循环塞入 AgentLoop。

## 决策

1. API 只创建 Task、Run 和初始事件并返回 HTTP 202，不执行 Agent。
2. Worker 使用 PostgreSQL `FOR UPDATE SKIP LOCKED` 在短事务中领取任务；执行期间使用可过期 Job Lease，不持有行锁。
3. 运行中取消只写 cancel_requested，由租约所有者观察并提交终态。
4. AgentLoop 只依赖 LoopCheckpointWriter 协议，并只在完整模型—工具边界保存 LoopState。
5. LoopState 同时保存消息、iteration、Usage、重复调用状态和不含密钥的配置哈希。
6. RecoveryService 根据快照兼容性和未决副作用决定 RESTART、RESUME 或失败，并记录审计事件。
7. 只有明确分类的瞬时错误和限流可以重试；重试受次数、累计时间、Token 预算与指数退避约束。
8. RETRYING 使用 next_attempt_at 调度，不在 Worker 内长时间 sleep。

## 原因

- 短事务避免长模型请求占住连接和数据库锁。
- 租约允许崩溃后接管，也让错误 Worker 无法在失去所有权后提交结果。
- 合法边界快照避免恢复半段模型流或半次工具执行。
- 配置哈希防止修改运行语义后静默续跑旧状态。
- 分类和预算避免永久错误死循环、重试风暴及成本失控。
- 对未知副作用保守失败，为模块 9 的 ToolEffect 人工确认留下安全边界。

## 后果

- Worker 执行语义是 at-least-once，副作用必须另建幂等和确认机制。
- PostgreSQL 是租约并发语义的事实环境，SQLite 不能替代对应集成测试。
- Snapshot 需要显式版本演进；不兼容版本必须迁移或拒绝。
- API、Worker 和 Runtime 可以分别测试和部署，但进程装配与 SSE 尚待后续模块完成。
