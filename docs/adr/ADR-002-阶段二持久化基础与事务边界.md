# ADR-002：阶段二持久化基础与事务边界

- 状态：已接受
- 日期：2026-09-06
- 适用版本：v0.2 模块 0～3

## 背景

阶段一的事件、消息和运行结果只存在内存中。阶段二需要保存 Task、Run、事件、快照和副作用事实，同时不能让 AgentLoop 直接依赖数据库。

## 决策

### 1. PostgreSQL 是阶段二唯一持久化事实来源

Task、Run、RunEvent、RunSnapshot 和 ToolEffect 的恢复判断只能依据已经提交的数据库记录。Worker 内存、SSE 连接和日志不具有权威性。

### 2. 使用 SQLAlchemy 2.x 异步接口与 Alembic

每个并发任务使用独立 AsyncSession，通过显式 UnitOfWork 管理事务。Schema 的变化必须形成 Alembic migration，不能在应用启动时静默调用 `create_all()` 修改正式数据库。

### 3. 核心契约与 ORM 记录分离

阶段一 Pydantic 模型继续作为 Runtime 契约，SQLAlchemy Record 只表示数据库行。AgentLoop、Provider 和 Tool 不导入 ORM；持久化通过 Repository、PersistentEventSink 和后续 PersistentAgentRunner 接入。

### 4. 事件序号由数据库原子分配

Run 行保存 `next_event_sequence`。追加事件时使用原子 UPDATE/RETURNING 领取序号，再在同一事务插入 RunEvent。数据库唯一约束 `(run_id, sequence)` 是最后防线。

### 5. UnitOfWork 不自动提交

调用方必须显式 `commit()`。发生异常时工作单元回滚并关闭 Session，防止函数返回时不清楚数据是否已经提交。

### 6. SQLite 只用于快速兼容性测试

本地缺少 PostgreSQL 时，可以用 SQLite 测试 ORM、Repository、状态机和 migration 的基本结构；但它不能证明 PostgreSQL 行锁和并发语义。真实 PostgreSQL migration、Schema 差异和跨连接事件序号测试放入 CI。

## 后果

优点：

- 阶段一核心保持独立和可测试；
- 数据库事务边界可见；
- 事件顺序有应用逻辑和唯一约束双重保护；
- Schema 可以升级和回退；
- 后续 Worker、恢复与 SSE 可以复用同一事实来源。

代价：

- Pydantic 与 ORM 之间需要显式转换；
- 调用方必须认真管理 Session 和提交；
- SQLite 测试通过仍不能替代 PostgreSQL CI；
- PersistentEventSink 当前每次 emit 使用短事务，状态与终态事件的原子提交需要后续应用服务复用同一 UnitOfWork。

## 后续要求

- 模块 4 创建 Task 时必须在同一事务创建首个 QUEUED Run 和初始事件。
- 模块 5 的 Job Lease 必须使用真实 PostgreSQL 并发测试。
- PersistentAgentRunner 只能依赖无 ORM 的运行上下文或协议，不能把 AsyncSession 传入 AgentLoop。
