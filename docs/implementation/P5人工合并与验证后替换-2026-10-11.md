# P5 人工合并与验证后替换

## 产品行为与范围

本批新增人工整理方法库的完整控制面。POST `/skills/merge-proposals` 接收 2–4 个不同 Skill 的冻结版本身份（skill_id/version_id/content_hash/lock_version）、明确的 workspace/project、合并后的声明式方法、幂等 ID 与依据，返回持久化 LearningRequest；不调用模型，不创建执行任务，不修改旧正文、不直接启用或删除旧方法。

仅支持同一工作区且最大作用范围完全相同、全个人来源的方法。合并定义沿用个人学习 v2 校验和既有工具、风险、步骤、注释要求。来源图最多 32 节点、200 份来源；全文复查整体 10 秒，在数据库事务外完成。任何父版本/来源失效、身份冲突、来源超限或扫描失败均拒绝；同 Run 的冲突来源身份不静默丢弃。

短事务按来源 Run 排序锁 → Workspace → 父 Skill 排序锁，重新比较来源身份与当前许可。通过 LearningRepository 构造唯一请求，规范 source_key/policy hash；多父 Skill 关系在不可变 policy_snapshot.lineage 中保留，已有 source 关联完整复制。新版本 parent_version_id 保持主线语义（新合并根为 null）。合并根 extraction_key 的 merge 命名空间绑定请求与定义哈希；统一访问门禁只对该命名空间额外查验请求、血缘和来源。普通方法不增加该查询。

## 独立输入与安全采用

候选确认复查完整来源图及额外个人来源许可。独立验证收集所有个人来源的已知输入哈希，正式 TRAIN 祖先仅使用已登记 public_input 的已知结构输入哈希，不读取 holdout。整体扫描 10 秒、最多 200 份；事务内再比较来源图身份，source_input_provenance 参与 validation policy hash/身份。派发和逐步运行复查该身份；已有无此字段的验证记录保持旧兼容路径。精确哈希及人工独立性声明仍不能证明语义无泄漏。

POST `/skills/{skill_id}/supersede` 只有在新方法为包含旧 Skill 的合并根、独立真实配置验证证据有效、同范围 trial active 且健康投影完全就绪时才执行。旧方法/新方法/trial 三个版本 CAS；同一短事务将旧绑定置 replaced、聚合标 deprecated 并设置 superseded_by，追加人工审计事件并使旧索引失效。旧绑定与旧版本分别最多 200 项，超限拒绝，不无限持锁。

访问门禁只允许合并后代沿经过校验的替换路径依赖已被该后代替代的旧聚合；旧根仍不可直接采用，disabled、版本 rejected、来源撤销及隔离均不能借替换关系绕过。提交前再次检验新方法可用；旧检索引用把 deprecation 视为撤销而导致新方法不可用时，整个替换事务回滚，不留下坏替换。弃用沿用既有不可直接重新启用的生命周期；不是跨 Skill 的一键回滚，也不授予未经独立验证的历史 trial。

## 操作界面

Skill 目录可选择 2–4 条同范围方法，读取并冻结版本、展开查看每条原方法，人工编辑第一条方法的起始 JSON 草稿、填写依据并创建候选。复制第一条只提供编辑起点，不冒充自动合并。成功后到个人学习刷新、审查、独立验证、限定试用。

旧方法详情可加载同范围 trial，检查并冻结替换版本，填写依据后明确确认弃用。健康/来源/版本变化被服务器拒绝时清除冻结信息，要求重新检查，不自动重复发送。错误提示解释保留旧方法的原因。普通启用、正式发布指针、删除权限没有因合并放宽。
