# K2 委派 cgroup 硬进程配额

## 行为与部署条件

新增 `projects/cgroup_pids.py`，每个项目命令在部署者委派的 cgroup v2 子树下创建独立随机命名组；只写自己创建的组，不修改父组的控制器，不移动 Worker，不修改宿主配额。可信 runner 在执行用户 argv、加载 Landlock/seccomp 前加入该组，验证成员和当前计数。`pids.max` 控制新建进程/线程；加入组本身可能突破上限，因此加入后另查 `pids.current`。内核语义参见 [cgroup v2 pids 文档](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html#pid)。

配置 `project_command_cgroup_root` 后，无论 `project_command_require_hard_pids` 是否为 true，组创建或加入失败均拒绝，不降级。要求硬限制但缺目录时拒绝。Windows trusted-host 不允许声明此能力。没有配置且不要求硬限制时，保留原会话计数软限制；结果 `process_quota` 明确区分 `trusted_host`、`session_soft`、`cgroup_v2_hard`。

预检在真实 Worker 环境创建独立组，启动固定探针子进程并确认实际加入及可计数；只读挂载、没有委派 pids 控制器或不可创建组，预检失败、Worker 不装配命令工具。每次命令仍复查，不依赖过时预检。

正常完成、超时、取消均清理本次组：写 `cgroup.kill`、最多两秒等成员归零，再删除自己创建的空组。Linux 取消同时收回直属进程、排空有界输出，取消不会提前返回未回收的进程。这里没有声称解决 Worker 被 SIGKILL 后遗留组的自动接管清理：部署者仍须检查遗留组，不能把该组的存在当成副作用可以安全重试的证据。
