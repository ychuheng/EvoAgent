# P6b 任务资源测量补全

本批只扩展离线 benchmark，不修改生产持久化、工具、租约或扫描策略。原先 480 次基准及故障报告保留，新数据另存。

## 计量合同

- SQLAlchemy after hook 读取 SELECT 的 driver rowcount，缺失时另计 unavailable；不读取 bind 参数、不转存查询正文。这是客户端行数，不是网络字节。
- Task 创建提交仍计入原 SQL/事务/总时间；Worker run_once 阶段每 10ms 采样父进程 RSS 和事件循环延迟。RSS 不包括扫描子进程，不是精确瞬时峰值；Windows RSS 明确为 null。
- 完成后独立读取已提交事件、快照和 artifact 元数据；统计事件 payload/快照 state 的规范 UTF-8 JSON 字节与 artifact 的 size_bytes，不把复查查询混进被测任务 SQL。它们不等于 PostgreSQL 行存储量或网络流量。
- 服务端锁等待、查询结果 wire bytes、事件缓冲区峰值仍为 null（未测），不填 0 冒充测过。现有扫描缓存独立对照另见 [缓存记录](P6b扫描缓存计算成本对照-2026-10-11.md)，本矩阵没有缓存命中/淘汰遥测。

480 次父进程采样峰值范围 106,889,216–129,892,352 bytes；每次最大事件循环延迟范围 0.73–64.97ms。事件 payload 每 Run 776–3095 bytes，快照 state 0–20,914 bytes；这些 fixture 没有生成独立 artifact，size 元数据和为 0，不能推广到文件输出任务。SELECT driver 报告行数 76–379。

这不是数据库整体减负达标：普通任务略慢、总 SQL 略增、提交没有下降。其他任务时间改善来自本矩阵启用的扫描结论缓存等路径，不能推论所有场景或付费模型都有收益，也不能将父进程 RSS 上升归因某一个开关。

首次测试错误地断言每个短任务都有快照，实际合法结果为 0；保留失败事实，修正断言为非负，增加规范 UTF-8 字节用例。没有为通过测试改变生产快照策略。故障机制本批未改变，沿用此前独立 12 项故障证据，不把它们记作此次重跑。
