# P4 实际执行、产物证据与自动挂起闭环

产品冻结树：`c4491a45866beb720e232b6c602e6c9e681a9a0e`。本批只有离线注入 Provider 和测试构造的人工判断，没有真实模型费用，也不证明方法有效性。

## 修复

1. 工作区级 trial（project_id 为空）允许被项目任务选择。观察收集此前却要求项目完全相同，造成观察任务失败、health_pending 阻断下一任务。现在按 trial 自己的授权范围检查，项目专属 trial 仍不能跨项目。
2. 普通 file_write 下载产物通常是 unchecked；原证据目录仅列已检查产物，无法形成可靠的人工反馈。新增受控 POST `/runs/{id}/skill-observation-evidence/verify`，每次最多 10 项明确的 ID/hash。仅终结个人任务、实际 Skill 绑定、本 Run 文本产物可检查。读取和扫描复用当前敏感策略、限额、撤销/擦除及 hash 门禁。结果仅元数据；命中敏感规则隔离并返回稳定错误。
3. 检查下载产物不会扩大模型注入权限。`artifact_read` 的类型白名单仍只有 tool_output/context_source。证据目录分页前在 SQL 中过滤当前已检查/已擦除项，待检查与可引用目录各自限制 200 项。
4. 前端显式选择待检查产物并触发检查，检查本身不提交反馈、不调用模型。安全检查通过与业务判断分开。Run 切换清空选择、旧请求返回不覆盖新 Run。
5. 旧 real-validation 契约用例补实际 lease.finalize，证明终结事实持久化，而不只证明 handler 返回 completed。

## 验证

冻结树 Linux 容器 + 独立 PostgreSQL/Redis：Ruff check 和 format 通过（516 文件），60 测试通过，127.16 秒。用例集合包括实际执行安全闭环、真实配置的离线 Provider 契约、产物目录、全部 artifact 注入门禁及修订信号。

代表路径：候选审查 → 四个独立 DEV Task 的离线执行/学习费用账本 → 测试构造的人工业务判定 → trial 激活 → 普通任务实际采用 → 写产物 → 显式安全检查 → 三组不同输入的失败及 Skill 归因反馈 → critical lane 收集 → trial 自动挂起 → 第四个普通任务停止采用。每个普通任务实际两次模型请求，Run 均由 LeaseManager.finalize 终结；候选定义未被覆盖。
