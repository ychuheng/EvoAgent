# P6b 事件缓冲与扫描缓存任务遥测

本批补计划 §11.9 的两个归因缺口，不扩大已选热点范围，不修改租约、权限、扫描判定、事件持久化或默认优化开关。此前报告中的未测项保留为历史事实，新结果另存。

## 计量合同

- `collect_runtime_metrics()` 仅显式开启；默认 ContextVar 值为空，不分配常驻计数器、不写数据库。每个顶层任务独立作用域，子任务继承同一计数对象，嵌套/异常退出恢复前一作用域。
- 缓冲峰值在实际入队后、阈值立即刷盘前记录；统计现有 `_pending_bytes` 的脱敏规范 JSON payload UTF-8 字节。它不是整个事件对象/进程堆内存；关闭事件批量时为真实的 0，而不是未测。
- 扫描缓存命中/未命中只统计通过字节和 deadline 检查后的精确查询；未命中后扫描失败也算一次未命中，失败不写安全缓存。淘汰只统计实际 LRU pop。缓存关闭走原 scanner，不记缓存查询；已有同 loop 安全缓存不因测量被清空。
- 只保存四个整数，不保留输入、hash、规则命中正文、SQL 参数或访问许可。缓存命中仍不能绕过实际 bytes/hash、授权、撤销和隔离检查。
- 基准作用域覆盖 Worker.run_once；Task 创建仍计入原 SQL/提交/总耗时，但不在这四个运行态计数范围。共享 scanner 的相同 loop 数据可以跨任务复用；cold_pool 仍只指新连接池，不冒充冷扫描缓存。
- 缓存数字仅覆盖已选的精确安全扫描缓存，不代表所有缓存；服务器锁等待、查询 wire bytes 仍为 null 未测，不用客户端 SQL 时间或内容字节替代。
