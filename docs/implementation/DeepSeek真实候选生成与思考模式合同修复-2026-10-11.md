# DeepSeek 真实候选生成与思考模式合同修复（2026-10-11）

## 范围与版本

用户批准真实模型总费用不超过 10 元；实际配置已存在于忽略的 `.env.personal` / `.env.deepseek`。根目录默认 Settings() 的 Mock 不能代表这些独立配置不存在。本批不改用户配置、不操作既有服务、不自动审查或启用 Skill。

生产代码冻结树 `e15ddf5f35268a13771782f9416e2763d1dc6cca`；独立 Linux/PostgreSQL/Redis 定向 **84 passed / 1 skipped**（SQLite 专用条件在 PG 不适用），Ruff 540 文件通过。之前树 `a0ec3f0` 的 83 passed 不冒充最终树。真实调用用 git archive 冻结源码和模块路径断言；开始/结束 Git HEAD 都为 `f06b6d1eeb8e95e22ae502df23a80901c4c09dad`，对应功能源码以原始报告的 source_tree 为准。提交后的准确 SHA 完整远端 CI 另行核对，本文创建时未计通过。

## 修复

- `learning/bootstrap.py` 个人提炼及 `api/app.py` 的记忆/旧 Skill 提炼 Provider 均传递 provider_thinking_mode。原先普通任务是 disabled，提炼却回到接口默认模式；一次真实候选输出达 2048 token 上限且解析失败。不能把这一次失败的所有原因都归于思考模式。
- 候选配置与真实验证 profile 纳入明确的思考模式，漂移拒绝继续派发。None 时不额外写 profile 字段，保留旧 profile 的 hash；候选生成合同升级 personal:v3，旧 v2 未完成请求不能悄悄换提示词，需显式新建/重新冻结。没有声称旧生成 identity 不变。
- 提示词提供合法 ToolStep/ModelStep 例子，明确 expected_output 只属 model，tool 禁止额外字段，扩展名只能是无点的小写扩展名。个人完整最小例子由测试实际解析为 SkillDefinition。继续严格拒绝非法字段，不自动删字段、拼接答案或伪造成功。

## 真实结果与失败保留

1. 早期隔离脚本曾把待修改文件也当作不可变输入，触发 input_changed；这是样例设置问题。后改为独立 requirements.json，未修改产品恢复门禁。初始费用未知的两次网络失败仍保守计费，未回填为零。
2. 仅修思考模式后代码任务通过，但候选把 expected_output 放在 tool 步骤，严格拒绝。随后一次候选 applicability 未通过。原始记录保留，不倒算成功。
3. 最终冻结树三类任务：代码和数据机械检查通过，检索任务实际完成但答案夹带解释、未满足整段 JSON 格式，不能计严格通过。代码生成合法 DRAFT；数据候选出现未定义的 depends_on_note 字段，被拒绝。
4. 三类样例那次脚本只启动 learning_propose，漏接 static_validate 使用的 learning_validate，代码候选留在 running；这是验收脚本遗漏，不是生产 Worker 断链。补接后在同一最终源码树重跑代码任务，实际任务完成、代码行为检查通过，真实提炼与静态校验完成，候选 **ready_for_review / draft**，对象 ID、定义和 hash 见原始数据。

最后一次只有代码场景，原始 complete=false 正确保留；没有将其算三类验收完成。检索事实正确性仍待人工逐条审核；本批不替用户填写人工判据。数据候选的严格失败也不因 task completed 而自动采用。

## 费用和隔离

累计 58 次派发尝试（含前述失败）；已知 token 费用按输入 2 元/百万、输出 8 元/百万保守上界约 **0.635510 元**；两次未知用量各保留 0.5 元，累计保守占用 **1.635510 元**。这不是平台账单实扣声明。使用官方价格页 https://api-docs.deepseek.com/zh-cn/quick_start/pricing/ 的高峰上界，不把空闲或缓存折扣当更大额度。

每次派发最多 2048 输出 token，请求体最多 180000 字节；独立全局闸门派发前保留 0.5 元，累计保守占用加新预留不得超过 8 元，另限制最多 64 次尝试。真实脚本跨次读取上次已知/未知费用，不能重置累计计费。普通任务与学习预算同时生效。所有凭据只在进程中读取，原始数据保存前按实际 key 值检查不含密钥。

隔离 PostgreSQL 为自建一次性容器，随机凭据和本机随机端口；退出仅删除本次所有的容器。没有动现有 embedding 容器或生产服务。实验库采用 metadata.create_all，不能代替干净迁移验收；原始记录保存公开样例及候选，但临时数据库已清理，不能继续使用该数据库中的 ID 对生产 API 审查/启用。
