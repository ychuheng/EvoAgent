# 项目命令输出限流与取消回收

`projects/commands.py::run_command()` 原先用 `process.communicate()` 收集全部 stdout/stderr，命令结束后才截断展示；用户设置的输出上限不能限制 Worker 收集缓冲。另外，取消执行协程没有与超时一样终止并回收 Linux 命令进程，可能留下子进程和后台 drain。

改为同时持续读取两个 pipe，每个只保留上限字节，多余数据丢弃但继续排空，保持截断标志和原来的中文截断提示。缓冲不再随全部输出量增长，正常返回码/超时/进程配额证据保留。取消先杀本次命令进程组，等待 drain 与主进程回收，清理完成后再传播 CancelledError；不把取消伪装为成功。

冻结源码树 `6b0470aa0fb252cc7b1a59886e3b5b08c0b6b1d9`，稳定独立 Git 元数据 `ef07eda6141c293e6f07cf62801cbc53867ef184`。Linux 隔离验证 **26 passed / 3 Windows-only skipped**，530 文件 Ruff/格式检查通过；Windows 本地 **14 passed / 11 Linux-only skipped**。新增真实 OS 子进程同时写各 1 MiB 输出、验证各保留 1024 字节并结束；真实 Landlock/seccomp 项目命令保留两侧截断证据；运行中取消后在协程返回前 PID 已回收。既有超时、正常多进程、失控进程组等用例同时通过。

这是输出内存与取消所有权修复，不提供单命令内核 pids/cgroup 硬配额，不把 50ms `/proc` 会话监控称为硬上限。付费模型调用 0，未操作生产服务。完整交付以推送提交 SHA 的五项远端 CI 为准。
