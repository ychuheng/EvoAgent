# P6b 扫描缓存计算成本对照

新增 scripts/benchmark_safe_scan_cache.py：固定无凭据公共文本，默认每组 30 次，禁用、每次冷缓存、预热后热缓存、每次不同内容四组。扫描预算仍是产品默认值；失败单独列出且 CLI 失败退出，不删除超时样本来宣称通过。输出所有成功耗时、扫描执行次数、模块/script SHA256、规则版本与预算，不读取用户正文、不访问数据库或模型。

冻结树 fc151404a94da356a53e67d9da9f8892a5442e27 的脚本/扫描器在 Windows 和隔离 Linux/Python3.13 容器实际执行；Linux 网络关闭。两端各四组 30/30 成功、零失败。Windows disabled P95=95.323ms、cold=105.128ms、hot=0.047ms、changed=91.727ms；Linux 分别为 199.408、112.171、0.062、109.421ms。热缓存计时阶段扫描子进程数=0（此前一次预热），其他各组=30。冷缓存不会降低真实扫描次数；这里未冻结冷启动性能目标，不从不同组运行顺序推导冷缓存提速。

记录见 safe-scan-windows-2026-10-11.json / safe-scan-linux-2026-10-11.json，包含全部样本。测量时另一个隔离全量回归在运行，时延仅描述本机当前条件。只测检测阶段，不含权限、DB、产物读取、并发负载和任务总时间；没有完整四类任务/故障场景性能基线，也不能据此自动打开 runtime_scan_cache_enabled。此前权限/隔离/关闭等价的测试保持原验收来源，非性能脚本代替。
