# DSH 准入链路复核与修复

## 首批确认和修复

1. 同输入的新 Run 的 unknown、模型自判、缺证据或非技能归因，不再覆盖已核实的技能失败。仍保留同 Run 的最新反馈修订；受信用户可以纠正自己先前的断言。只有充分的 verified_success 清空失败序列。
2. 报告收集和人工复核共用业务判定：只汇总 treatment 的业务结果。比较判定逐 case / repeat / criterion 绑定 control 与 treatment；正例业务 control fail + treatment pass 是 improved，全通过为 equivalent。反例或非业务 control fail、任一 treatment fail 均拒绝；unknown、非独立或不可信判断、缺臂、重复、不匹配或不可比保留 pending。
3. real_trial_eligible 与 SkillTrialService._assess 同步修复，避免只改报告却仍被最终门禁挡住。准入重新读取 EvalRun 的 comparable、实验/臂/重复绑定，报告里的布尔值不能取代数据库证据。旧报告缺 comparable 时不得自动开放 trial，需新验证。
4. RecoveryScanner.run 的普通异常均清除 ready、调用 on_failure 并有界退避；取消仍传播，不吞掉停止信号。

## 验证

## 第三批：数据库证据与费用核对

- 新增 0034，PG/SQLite 都在数据库层禁止 v3 选择证据 UPDATE，包括原文 hash、渲染 hash、授权范围、排名、分数、时间与选择策略。legacy→v3 的伪装更新也拒绝。Base.metadata.create_all 与 Alembic 使用同一 SQL；旧数据不回填。0034 在存在 v3 证据时拒绝拆掉保护，空库回滚正常。
- 0026 有 trial/observation 时拒绝降级；0027 有个人数据集/验证/比较绑定时拒绝降级，原碰撞检查保留。0027 upgrade 的 baseline→control / 其他 mode→treatment 映射是为旧双臂身份迁移的必要转换，不删除或伪造验证结果；本次没有撤掉它。
- 学习模型流设置总 model_timeout_seconds，避免“持续发片段”绕过 HTTP 分段超时无限保持 reserved。超时仍通过 finally 结算 known usage 或保留 unknown，不退回零费用。
- 此时限作用于模型流；不机械地定时取消正在提交的派发记账事务。准备和记账仍按原有 guard、租约与数据库事务规则处理，不宣称数据库异常下有相同毫秒级截止保证。
- 单条 unknown 增加受信本机 CLI 复核：预留金额 CAS、使用量凭据 hash、理由、冻结模型/单价；行锁内 Spend + 审计事件原子提交，重放幂等，改变凭据/使用量冲突拒绝。模型工具不注册这个能力。不是批量宽免，也不是平台实扣金额导入；缺少冻结身份/单价或可靠使用量时继续拒绝。

本地第三批：费用/通知/选择证据/迁移合计 112 passed / 1 skipped，135.19 秒；skipped 是 SQLite 分支要求行锁并发，PostgreSQL 分支通过。PG 与 Redis 指向独立验收库和逻辑库，没接触产品数据库。单独迁移/选择证据 50 passed。文档相对链接 1189，0 断链；Ruff lint / format 全部通过。
