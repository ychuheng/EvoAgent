# DSH 准入链路复核与修复

## 首批确认和修复

1. 同输入的新 Run 的 unknown、模型自判、缺证据或非技能归因，不再覆盖已核实的技能失败。仍保留同 Run 的最新反馈修订；受信用户可以纠正自己先前的断言。只有充分的 verified_success 清空失败序列。
2. 报告收集和人工复核共用业务判定：只汇总 treatment 的业务结果。比较判定逐 case / repeat / criterion 绑定 control 与 treatment；正例业务 control fail + treatment pass 是 improved，全通过为 equivalent。反例或非业务 control fail、任一 treatment fail 均拒绝；unknown、非独立或不可信判断、缺臂、重复、不匹配或不可比保留 pending。
3. real_trial_eligible 与 SkillTrialService._assess 同步修复，避免只改报告却仍被最终门禁挡住。准入重新读取 EvalRun 的 comparable、实验/臂/重复绑定，报告里的布尔值不能取代数据库证据。旧报告缺 comparable 时不得自动开放 trial，需新验证。
4. RecoveryScanner.run 的普通异常均清除 ready、调用 on_failure 并有界退避；取消仍传播，不吞掉停止信号。

## 验证

独立数据库 evoagent_codex_review_20261011，真实 PostgreSQL；定向健康、判据、恢复扫描、真实 profile 合同、人工复核和实际健康集成测试：56 passed，0 skipped，110.61 秒。实际模型用 Mock 替身，没有付费调用；端到端回归明确模拟正例 control 失败 / treatment 成功，并实际走过人工判断、readiness、trial、普通任务使用链路。这证明机制合同，不证明真实模型收益。

Ruff 检查通过。远端完整 CI 以随后推送 SHA 的结果为准，不把本地定向测试冒充全量交付。

## 对其余意见的核对

- 状态漂移确实存在：整理提交还改动 .dockerignore 与 scripts/README.md，发布前需要推进基准与 main 分支标注。
- 当前 SkillObservation 的可信生产路径为人工核实；machine 是健康判定支持的来源类型，不能据此声称已有普通任务机器归因生产者。当前状态页收紧措辞。
- reserved 已有 reconcile_stale、每次 learning provider 派发前回收、后台预算核对；以持有者租约/epoch/取消状态为依据。不能仅凭预留年龄释放仍活跃的调用。unknown 已支持有 token 使用记录的 settle，但没有受信用户账单核销入口；不能定时自动释放可能已付费的 unknown。
- 其他配置、隔离与不可变性意见仍需逐项核对，首批不宣称全部关闭。真实 trial 效果、内核委派环境和性能归因缺口维持原有未验收结论。
