# P5 多 Run 冻结经验自动修订聚合

## 实现合同

新增 `learning/revision_aggregation.py`：3–10 条不同 Run 的来源身份，冻结来源 ID、正文 hash、source_revision、撤销 epoch、反馈 ID、观察 ID、观察输入 hash 与独立声明输入 hash。快照合同为 `revision-aggregation:v1`，整体进入原有 policy_hash / source_key；仍由 LearningRepository 唯一收口，不引入另一套请求构造器或新数据库身份命名空间。

`CandidateDiscoveryService.discover_revisions()` 由真实 Worker 周期扫描调用，每次最多 50 条观察、循环 UUID 游标，同一次扫描每个版本/项目只处理一次。读建议继续不启动任务。后台只在 suggest 策略下、同一确切项目范围、同一版本/失败判据/步骤、至少三个独立输入、明确技能相关归因时进入聚合。额外验证声明文件 hash：同数据改提示不算独立；只有提示的任务用声明提示 hash，不能声称语义独立。

所有来源必须已经冻结且仍有效，最新 method/incorrect 或 needs_fix 反馈逐条授权学习，反馈与观察 revision 一致。没有冻结来源则跳过，不回放未经授权的完整历史。旧版本撤销或正文损坏、最新反馈改变、未知来源或已隔离内容拒绝；非 Mock 缺正数每日/单请求额度时不入队。沿用每日自动候选上限、fingerprint 去重和目标版本冷却；已有待处理修订不再排队。

存储/完整敏感扫描在事务外，整批 10 秒预算。准入按 Run UUID 排序锁全部 Run，再锁 Workspace，并在同一短事务复查身份/配额/目标 lock_version 后写请求。处理阶段同样先锁全部 Run，不在取得 Workspace 后补锁次要 Run。目标 Skill 锁下复查 lock_version，过时候选拒绝。

`LearningJobHandler` 在 prepare/generate/static_validate 及付费派发检查中复查全部来源；生成前与结果回来后复查父版本完整来源及所有冻结正文，元数据检查不能替代实际内容校验。生成期一个 200ms watcher 对全批读取有界元数据，包括撤销 epoch、最新反馈、隔离、项目授权、目标版本。不会每条来源再单独重建整个证据 manifest，亦不在模型等待期间持事务。

`SkillExtractionService` 要求传入来源集合与冻结合同完全相同，逐条校验实际 Run/artifact/hash；修复多来源 extraction_key 不应取最后一条 source_revision 的问题。候选保留每条 SkillSourceRecord 与父版本；静态报告带全批来源身份。取消/撤销丢弃迟到结果，候选只能 DRAFT / ready_for_review，active 指针不变，trial_eligible=false。

## 验证与边界

SQLite 定向回归阶段 27 passed / 27 PostgreSQL skipped；它不算 PostgreSQL 准入证据。最终冻结源码树 `c6fc7aec1e47216d1813afa1ce4dcc26f9d711bf`，独立稳定元数据 `940b5ea19c6f0404ec984e6d4e968a58bc76f038`，Linux/PostgreSQL/Redis 定向 **143 passed / 1 SQLite 并发准入不适用 skipped**，531 文件 Ruff/格式检查通过。包含学习控制、来源、生成取消、修订、合并、替换、正式门禁与观察回归。

较早冻结树 `fd7f0c200513eeb47ee440f46117225cec55d333` 为 142 passed / 1 skipped / 1 failed，第二个扫描者把已存在的幂等请求也计为新建候选；不能记为通过。补充持有排序 Run 锁后的 alias 检查，重测同时断言两个扫描者合计新建数为 1、实际请求行也为 1。修复的是返回计数，不能据此前失败断言数据库实际产生两行。

新增用例覆盖三来源生成/持久化/父版本/DRAFT、撤销任一来源后不可访问、不同提示但相同声明数据拒绝、未授权拒绝、冻结后新反馈拒绝、正文破坏拒绝、无数值预算拒绝、重复候选拒绝、目标变化拒绝、次要来源撤销/反馈撤回中断阻塞生成、PostgreSQL 双 Worker 一次准入。合成来源和观察仅证明工程合同，不是真实模型改进证据。

范围有意限制：已有单条明确纠正路径仍可立即生成候选；自动聚合不会与正在审查的单条修订并行抢目标。想聚合已完成审查但被拒绝/取消的来源，须经过冷却并保持逐条授权。会话跨项目不混合学习；付费真实三类任务效果仍需已批准额度。未冻结、缺判据或 uncertain 观察不会自动洗成个人来源。
