# S1 数据与证据合同实施记录

本批以 `cea3d7c` 为父版本，实现反馈和学习请求的数据合同；尚不宣称个人 Skill 已能生成、验证或复用。

## 已实现

- `LearningRepository.append_feedback` 是反馈构造唯一入口。Run 写锁下计算两种 hash，原子分配 revision，按最新语义递增 learning_revision；comment 不影响学习语义，A→B→A 是真实新修订。同客户端键改正文冲突；旧修订重放不受最新 revision 变化影响。敏感正文在分配序号前拒绝。
- propose/validate 的 source_key 由 Repository 统一生成，固定不同 namespace，数据库约束及唯一键保护。父请求、候选 hash、目标/父版本与工作区归属在提交时检查。幂等别名保留所有客户端键，修复语义去重后第二个键丢失的问题。
- Run 的 feedback/context、Skill 的 version/event、Project 的 event 使用原子计数器；Project 授权/撤销先锁聚合。Skill 手动创建与提炼路径均改用计数器。
- Run.data_role 由服务端赋值，普通任务 personal、正式评测 train/holdout、运行评测 runtime_eval；历史不明来源保留 legacy。ORM 与数据库 UPDATE trigger 拒绝改角色；没有重新分类 API。
- 反馈按 method/fact/clarify/none 确定性路由。machine/user 判据分离；没有证据、人工未确认、重复/缺失判据均不能通过。判据执行、来源授权和学习入队由后续 P1/P3 接线，合同函数自身不证明证据真实性。
- 迁移 `20261009_0022` 只创建反馈、请求、来源、策略、付费预留及幂等别名表。旧 Skill 迁入默认工作区、counter 从历史最大值+1 回填。Trial/Observation 和实验 arm/purpose 留给 P3。新业务数据存在时拒绝无声降级丢数据。

## 验证

- 全量后端回归：975 passed / 55 skipped。运行后补充的历史版本计数迁移测试与提炼计数路径另外验证。
- 隔离 PostgreSQL/Redis：43 passed / 1 skipped，包括真实反馈并发、角色不可变、迁移往返、fencing 与崩溃恢复；独立创建验收库，结束后清理，未操作生产服务。
- 追加目标验证：迁移与学习合同 12 passed / 7 skipped；Skill 提炼/审查与学习合同 44 passed / 6 skipped。本机缺 PostgreSQL 环境的跳过由隔离测试覆盖。
- 未运行付费模型。未对用户数据库升级迁移。CI 以对应提交的远端运行结果为最终交付闸门，推送后核对。
