# EvoAgent 运营故障指南

> **适用版本**：`0.4.0.dev0`（`c2` 分支）。按"症状 → 先查什么 → 怎么修"组织，命令都可直接跑。
> 私有配置细节见[个人模式操作手册](个人模式操作手册.md)；安全拒绝是**预期行为**，不是故障。
> 单用户本地部署；公网多租户不在此文档范围内。

## 0. 通用三件套

```powershell
docker compose ps                                  # 容器状态与健康检查
.\.venv\Scripts\python.exe scripts/check_state_drift.py   # 文档基准与产品代码是否漂移
.\.venv\Scripts\python.exe -m pytest -q tests/unit        # 快速单元回归
```

页面右下角的"运行模式"与 `GET /api/v1/runtime-info` 是判断"到底是哪个组件不对"的起点：
它同时给出模型 Provider、搜索 Provider、记忆开关与 Worker 存活（`ready`/`missing`/`unknown`）。

## 1. 页面打不开 / `/health/ready` 失败

| 先查 | 期望 | 不符时 |
| --- | --- | --- |
| `docker compose ps postgres` | `healthy` | 未起就 `docker compose up -d postgres`；反复重启看 `docker compose logs postgres` |
| `.\.venv\Scripts\alembic.exe current` | 等于 `alembic heads` 的输出（当前 `20260927_0019`） | 落后就 `alembic upgrade head`；**不要**手改 `alembic_version` |
| `docker compose logs api --tail 50` | 无异常栈 | 端口占用改 `EVOAGENT_API_PORT`；数据库连不上核对 `EVOAGENT_DATABASE_URL` |
| `http://127.0.0.1:8000/api/v1/runtime-info` | 返回 JSON | 502/连不上说明 API 进程没起或崩了 |

常见根因：**迁移没跑**（`/health/ready` 会明确指出数据库未就绪）、**API 与 Worker 用了不同的
`EVOAGENT_DATABASE_URL`**、**前端产物没构建**（`/ui/` 404，需要 `docker compose build` 或前端 `pnpm run build`）。

## 2. 任务一直 `queued` / 一直没进展

| 先查 | 期望 | 不符时 |
| --- | --- | --- |
| `/api/v1/runtime-info` 的 Worker 存活 | `ready` | `missing`：起 `evoagent-worker`；`unknown`：存活探测失败，看 Redis 配置 |
| `docker compose ps redis` | `healthy` | `docker compose up -d redis` |
| Worker 日志 | 有 `job claimed` 之类记录 | 没有说明唤醒链路断：核对 `EVOAGENT_REDIS_URL` 与 `EVOAGENT_REDIS_NAMESPACE` 是否与 API 一致 |
| 任务租约 | `jobs.lease_expires_at` 在推进 | 租约过期说明 Worker 被杀或卡死；重启 Worker 后由 lease/`lease_epoch` 接管 |

Redis 只是**唤醒**通道，事实来源是 PostgreSQL：Redis 挂了不会丢任务，但新任务可能迟迟不被唤醒。

## 3. 任务失败并提示预算（`budget_exceeded`）

这是**设计行为**：额度或价格假设没填时，付费调用被直接拒绝。

1. 看 `spend_records` 台账里的累计金额与 scope（`trial`/`formal`）；
2. 要花钱就得配齐 `EVOAGENT_BUDGET_SCOPE`、`EVOAGENT_BUDGET_TRIAL_LIMIT_MICROS`（或 `..._TOTAL_LIMIT_MICROS`）、
   `EVOAGENT_BUDGET_TASK_LIMIT_MICROS`、输入/输出价格假设与 `EVOAGENT_BUDGET_STOP_RATIO`；
3. **不要**为了让任务"跑起来"而把额度调成无穷大或删台账：台账是只追加的，删行等于伪造花费记录。

达到 `stop_ratio` 阈值后不再开新调用；已在跑的任务按单任务限额终止。

## 4. 工具被拒绝（这类拒绝通常是正确的）

| 提示/终态 | 含义 | 处置 |
| --- | --- | --- |
| `project_authorization_denied` | 项目档位不够（`read` 想写）或路径在根外 | 确认任务该不该写；需要写就先把项目升到 `read_write` |
| `authorization_revoked` | 授权在运行中被撤销 | 这是预期终态；重新授权后新建任务 |
| `edit_conflict` | 唯一匹配失败或文件在冻结后被改 | 重新读取文件内容，别让模型凭旧内容改 |
| `input_changed` | 任务冻结的输入被替换 | 恢复输入或新建任务；冻结语义不允许"悄悄换输入" |
| `task_operation_conflict` | 并发操作同一任务（比如同时取消/补充约束） | 刷新页面重试 |
| `run_command` 报"命令不在白名单" | 默认白名单为空 | 需要就用 `EVOAGENT_PROJECT_COMMAND_ALLOWLIST` 显式列出**容器内实际存在**的程序 |
| `run_command` 报隔离/内核能力不可用 | 命令子进程必须成功安装 Landlock 文件视图（离线命令另需 seccomp 网络过滤），失败即拒绝执行 | 这是**预期的安全拒绝**，不要去掉隔离来绕过：确认 Worker 是 Linux 容器、内核支持所需能力，或改用不需要命令的做法。**在 Windows 宿主上跑就是这种情况**——项目命令只能在 Linux Worker 容器里执行 |
| `EVOAGENT_COMMAND_SETUP_FAILED: [Errno 13] Permission denied: '.../bin/python'` | 隔离子进程先施加 Landlock、再 `execvpe` 目标解释器，而只读白名单里没有**应用自己的解释器前缀**——Python 装在 `/usr` 之外时就会命中（CI 的 `setup-python` 在 `/opt/hostedtoolcache/Python/...`，2026-09-28 的 CI 全红就是这个原因） | 已由 `command_readable_roots()` 放行解释器自身目录与 `sys.prefix`/`sys.base_prefix`；自定义镜像若仍复现，检查 `sys.executable`/`sys.prefix` 指向的目录对运行用户可读可执行，**不要**关掉 Landlock 绕过 |
| 项目登记报"路径不存在/无法读取" | 个人模式登记的是**容器内路径**（`/app/projects/...`） | 先设置 `EVOAGENT_PROJECTS_HOST_ROOT` 并重建应用容器，再按容器路径登记 |
| 审批一直 `pending` | 有副作用动作在等审批 | 页面审批；确认无误后再批。待审批的编辑会显示服务端重算的 diff，预览失效或截断时页面**不允许**批准 |
| `approval_error` | 审批状态冲突（重复批准/已终结） | 刷新 Trace 看最终决定 |
| 产物列表为空 | 只有**已登记的**产物才会显示（F-04 不读任意路径）。`file_write`/`artifact_write` 现在都会登记 | 确认模型确实调用了写文件的工具；若只用了 `shell` 之类未登记路径的写入，页面看不到，需要让它改用 `file_write` |
| 产物预览/下载 409「内容哈希与登记记录不一致」 | 磁盘上的字节与登记哈希不符（被外部改过，或记录被改写） | **这是防篡改，不是故障**：核对是谁改了文件；确认无误后重新生成该产物 |

**不要**通过关闭审批或放宽白名单来"排障"；如果某个动作确实需要长期允许，改配置并在
[安全边界说明](安全边界说明.md)记录理由。

## 5. 搜索或网页读取失败

| 症状 | 先查 | 说明 |
| --- | --- | --- |
| 搜索返回空 | `EVOAGENT_SEARCH_PROVIDER` 是否为 `mock` | 默认离线 Mock；真实搜索需要 `ddgs`（无密钥）或 `brave`（需 Key） |
| `provider_auth_error` | Base URL/密钥/模型名 | 密钥只放 `.env.personal` |
| `provider_rate_limit` | 服务商限流 | 等一会儿重试，或降低并发 |
| `provider_server_error` / 超时 | 服务商端 | 属外部波动；Trace 里保留原始失败 |
| 网页读到乱码/HTML 噪音 | 该站点结构或编码 | `web_fetch` 只取文本；报告里需注明"仅见摘要"与"已读正文"的区别 |

`ddgs` 的公共后端会限流，失败是**正常现象**；不要把它当成"搜索能力已通过"的证据。

## 6. 编码与 PDF 报错

| 错误码 | 含义 | 处置 |
| --- | --- | --- |
| `unsupported_text_encoding` | 文本不是可识别的编码（自动识别只含 UTF-8/UTF-16/UTF-32，含 BOM） | 明确告诉它编码，或先转成 UTF-8 |
| `unsupported_encoding_declaration` | 文件头声明的编码不认识 | 同上 |
| `encoding_mismatch` | 声明编码与实际字节不符 | 以实际编码为准，转换后重试 |
| `pdf_unreadable` | PDF 结构损坏 | 人工检查；程序不会猜内容 |
| `pdf_scanned_or_empty` | 扫描件/无文本层 | 需要 OCR，本版本不做 |
| `pdf_encrypted` | 加密 PDF | 去密码后重试 |
| `pdf_parser_missing` | 缺少 `pypdf` 依赖 | `pip install -e .` 补齐依赖 |

这些拒绝都是**如实报告**：任务里说"无法抽取"比编一段内容正确。

## 7. 迁移、备份与升级

- **迁移只前进**：`alembic upgrade head`；不要 `downgrade` 到未验证的旧版本。
- 升级前先 `pg_dump`（见[用户手册](用户手册.md)第 7 节），升级后核对 `alembic current`。
- `scripts/phase4_migrations.py` 里有一个**已知缺陷**：它断言写死旧 revision，直接跑必然失败；
  当前以 `alembic upgrade head` + 表计数核对为准（缺陷登记在[当前状态](当前状态.md)第 3.1 节）。
- 恢复演练：把 dump 装进**新库**核对行数，再决定是否切换；不要直接覆盖生产库。

## 8. 维护任务与清理

| 症状 | 原因 | 处置 |
| --- | --- | --- |
| 归档/擦除任务停在 `failed`，重试无效 | **已知缺陷**：`retry` 不重置 `attempts`，用满 3 次后无法恢复 | 手工在数据库里把该行 `attempts` 归零并置 `pending`，并记录这次人工干预 |
| `maintenance_attempts_exhausted` | 同上 | 同上 |
| 强杀 Worker 后出现 `UNKNOWN` 效果 | 进程在提交边界被杀 | **人工处置**：核对账本与磁盘，再决定重试或标记完成；程序不会自动猜 |

## 9. 状态与文档一致性

- 产品代码变更后，[当前状态](当前状态.md)顶部的"产品代码核对基准"会与 HEAD 不一致，
  `scripts/check_state_drift.py` 会非零退出。这是**闸门**，不是脚本坏了。
- 重新核对（确认代码、文档、测试一致且未验证项已登记）后，用
  `scripts/check_state_drift.py --update` 推进基准；推进要求工作树干净。
- 报"基准提交 `<sha>` 在仓库中不存在"时先看**是不是浅克隆**：`git rev-parse --is-shallow-repository`
  为 `true` 说明历史提交没被取下来，闸门根本无法比较（基准按约定总是 HEAD 的祖先，永远不在
  `--depth=1` 的克隆里）。CI 的 `test` 作业已给 `actions/checkout` 设 `fetch-depth: 0`；
  本地浅克隆用 `git fetch --unshallow`，`tests/unit/test_state_drift_gate.py` 在浅克隆下会带
  这条原因跳过而不是误报"基准提交是假的"。
- 文档断链：`.\.venv\Scripts\python.exe scripts/check_doc_links.py`，要求"断链 0 条"。

## 10. 报告问题时要带什么

1. `GET /api/v1/runtime-info` 的输出（**不含密钥**）；
2. 失败的 Task/Run 标识与 Trace 里的工具调用、错误码；
3. `docker compose ps` 与相关容器最近 50 行日志；
4. `alembic current` 与 `git rev-parse HEAD`；
5. 如果你做过配置改动，说明改了哪些变量（值可以打码）。

不要粘贴 `.env.personal`、`docker compose config` 全量输出或私有项目正文。
