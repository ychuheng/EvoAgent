# ADR-009：派生向量索引与检索冻结

- 日期：2026-09-20
- 状态：模块 6～7 已实现；真实 PostgreSQL/容器/模型验收待补
- 关联：[阶段四指南](阶段四-记忆检索与协议扩展架构与实现指南.md)、[ADR-008](ADR-008-上下文压缩与版本化记忆.md)

## 背景

模块 5 已建立人工确认、来源引用与撤销，但关键词只能找到词面重合的资料。增加向量后，最大风险不是少召回一条记录，而是把已经撤销、越作用域或来自错误模型空间的记录当成可用事实；另一风险是同一 Run 恢复后重新检索，导致执行依据漂移。

## 决策一：正文权威与向量索引分离

SkillVersion、MemoryVersion、SessionArchive 继续保存正文和生命周期。RetrievalDocument 使用三个显式可空外键，并用 exactly-one 约束保证只指向一个来源。向量表只保存 document/profile/generation/input_hash/vector，不能自行赋予正文可见性。

固定 `vector(1536)`，模型、距离、预处理版本组成 Profile 身份；ORM 拒绝原地改写身份，活动 generation 可切换。相同维度不代表同一模型空间。以后增加维度必须迁移，不提供任意维度环境变量。

首版一个来源对应一个文档，预处理为 `text-v1`：索引输入取来源检索文本前 12000 字符，保留完整来源 hash。不实现分块合并和 ANN；来源过长导致的尾部语义缺失属于已知召回限制。

PostgreSQL 使用原生 `<=>` 精确距离；SQLite JSON/Python cosine 仅支持本地功能测试。生产迁移创建 vector 扩展，运维账号必须具有相应权限；降级迁移不删除可能被其他表使用的扩展。[pgvector 官方说明](https://github.com/pgvector/pgvector)是类型与算子依据。

## 决策二：索引任务跟随业务事务，模型调用离开事务

确认/撤销事实、发布/回滚/禁用 Skill、完成归档都在自己的数据库事务中入队。来源改变时立即使已有 Document 失效并删除其向量；事实决策不等待外部 Embedding。

Worker 领取 owner/epoch，读取来源并冻结本次计算输入，释放事务后调用 Provider。返回后重新验证租约、来源状态及 hash，才允许写入。每个请求最多 16 条、每条最多 12000 字符、15 秒，整个批次先校验数量、模型、维度、float32 可表示性和非零性；部分成功不落半批向量，取消向外传播。

失败保留错误代码和建议重试时间 `next_attempt_at`。当前维护队列不自动重试 failed；显式 retry 会清空建议时间并重新排队。避免把建议时间误读成自动调度承诺。

重建先保存合法来源 manifest 和新 generation。最多 64 个合法来源，在新代写完并复验后与活动指针同事务提交。失败继续使用旧代；旧代重试不得把活动指针倒退。重建期间发现来源集合变化则拒绝切换，要求重新提交 rebuild。增量任务提交时若活动代改变，失败后可显式重试以获取新代。

## 决策三：权限先于召回，阈值先于融合

所有路径共用 `load_source`。Memory 要求作用域、confirmed/current、有效期和来源有效；Skill 要求 enabled/active、定义 hash、工具和风险兼容；Archive 要求同会话、严格早于 Task 截止点、来源完整且不来自 Eval。

BM25 使用原有 tokenizer；向量 SQL 只接收已经允许的 Document ID，并检查 profile、generation、input_hash。两路各自先按相关性门槛过滤，再取 Top-100，最后等权 RRF，默认 k=60。稳定来源键用于同分排序；RRF 值不表示事实可信度。

向量服务/SQL 查询故障、未就绪或部分索引记录降级原因；向量不可用时只用同一允许集合的 BM25。权限或正文 hash 验证失败不触发放宽过滤。正式检索效果实验尚属模块 12，当前不提供提升比例。

## 决策四：冻结实际选择，发送前仍复验权限

每个启用新链路的 Run 保存一个 Batch，即使命中为零。Selection 保存最终名次、原始来源 hash、冻结渲染文本和文本 hash、两路证据或未注入原因。

Skill 与 Memory/Archive 分别使用 Top-K 和 Token 预算，再检查完整请求预算。Skill 沿用规程区，Memory/Archive 进入低可信 user 资料区；候选被召回不等于已经注入。

恢复读取已冻结文本，不重新请求向量、不因新发布或重建替换来源。仍启用的 Skill 允许使用原冻结版本，即使 active 指针已经切到新版本；禁用、记忆撤销、归档擦除和 hash 变化仍阻止后续模型请求。擦除沿记忆与归档引用闭包清理冻结文本、向量及派生 Run 正文，保留审计骨架。

RunConfigSnapshot 新增完整有序 `selected_skills` 和 retrieval 配置；旧字段缺省时不参与 canonical hash，保持历史记录的可读取性。新配置与旧活动快照不匹配时仍拒绝自动恢复，这与“旧哈希可读取”是两回事。

## 兼容与范围

- 默认 `lexical` 且 Memory/Archive 关闭，保留旧 Skill 检索路径；新路径要求 Snapshot v2。
- baseline、pinned Skill 评测不自动注入记忆，避免改变原配对变量。
- Mock 特征哈希验证协议和排序闭环，不能证明真实语义召回。
- API 继续遵守项目现有本地受控部署边界，不新增公网认证体系。
- 不增加 MCP、Redis、ANN、管理前端或跨主机 Artifact 访问能力。

## 验证

测试覆盖向量契约、同义查询的人工向量示例、作用域过滤、撤销竞态、旧 epoch、重建失败、零命中冻结、预算遗漏、降级、持久化 Runner 实际 user 消息和归档擦除。真实向量类型/余弦/过滤/维度拒绝测试以 `postgres` 标记接入 CI。具体本地执行数字与环境限制见[模块 6～7 验收说明](阶段四-模块6至7验收与运行说明.md)。
