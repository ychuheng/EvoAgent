# ADR-015：阶段四交付证据与发布门禁

- 日期：2026-09-23
- 状态：已接受并实现
- 范围：模块 14 验收与可复现交付，不更改 Agent 权限或自动发布策略

## 背景

阶段四同时包含 Mock、SQLite、真实 PostgreSQL、Redis、MCP fixture、Docker、浏览器和付费模型验证。把这些结果压缩成一个“全部通过”会掩盖跳过项及实际环境差异。已经出现的记忆无收益、上下文预算拒绝、字面验证器误判，也不能在收尾时删除。

## 决策

1. 四个 Demo 复用实际业务服务和回归断言，提供 CLI 分组执行与 JSON 证据；正常路径和失败/阻断路径必须同时保留。运行失败、收集失败或 skipped 的组为 incomplete。
2. 新增 PostgreSQL Demo 使用随机独立 schema，显式使用 public.vector，清理仅作用于自己创建的 schema。旧回归中会清空表的测试只能使用专用测试库，不能指向运行数据库。
3. 迁移分别验证全新库和含旧消息的 0005 库；两者都要求 head=0012 且 alembic check 无结构差异。脚本拒绝已有表的入口，避免重跑时覆盖业务数据。
4. 真实 Skill 实验使用两个真实 TRAIN 来源、预先固定人工 SOP、冻结 HOLDOUT 和旧严格配对规则。候选运输使用 MockCandidateGenerator，但执行 Provider 是真实 DeepSeek；不把人工 SOP 写成模型自动提炼。门禁结束停在 review_required/rejected，不自动发布。
5. 原始模型报告和验证判定冻结。对 Unicode 负号的字面匹配误判另存分析，不更改原始分数。更好的数值验证器应作为新版本实验，不为当前分数补丁。
6. 交付 manifest 记录报告文件 SHA256、结果类别、范围和未完成项。release_check 默认遇到 pending 返回 2，证据缺失或哈希不一致返回 1；只有证据齐全且无 pending 才返回 0。--allow-pending 仅用于审计现有文件，不代表正式发布。
7. 未配置真实 Embedding 时明确 pending，版本保留 0.4.0.dev0，不创建 v0.4 正式标签。

## 边界与代价

报告哈希只验证内容完整性，不能替代人工评估测试是否充分，也不是签名或供应链证明。Demo 中旧回归子场景仍可能使用 SQLite；连续新增场景使用 PostgreSQL，报告和运行手册分别说明。小样本、确定性 fixture 和真实语义效果不能互相替代。
