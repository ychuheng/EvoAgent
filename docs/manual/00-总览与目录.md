# EvoAgent 源码手册：从整体系统读懂代码

这是一套针对**当前项目整体**的四册源码教材。它从用户的一次任务出发，沿页面、API、任务队列、模型循环、工具、数据库、结果回到用户；再讨论记忆、Skill 和评测。章节按因果关系组织，读者可以先建立总图，再深入某条路径。它解释代码怎样工作，不承担部署操作说明或发布验收结论。

| 分册 | 读完应能回答 | 主要对象 |
| --- | --- | --- |
| [第一部分：系统全景与任务主线](01-系统全景与任务主线.md) | 用户发一条任务后，哪些对象和进程参与？ | Workspace、Project、Session、Task、Run、Worker、AgentLoop、Trace |
| [第二部分：执行内核与可靠性](02-执行内核与可靠性.md) | Worker 中断、审批等待或重复投递时，结果为何不被写乱？ | 状态机、事务、租约、检查点、审批、ToolEffect、预算 |
| [第三部分：工具、项目与安全边界](03-工具项目与安全边界.md) | Agent 实际能读改跑什么？两种模式边界在哪里？ | 项目工具、精确编辑、Linux/Windows 命令、产物、网页与 MCP |
| [第四部分：知识进化与质量验证](04-知识进化与质量验证.md) | 经验怎样进入上下文、记忆和 Skill？如何证明它有益？ | ContextResolver、Memory、Skill 提炼、配对评测、发布门槛 |

## 推荐读法

第一次阅读按四册顺序走一遍，不要求记住全部类名。每册都使用同一条“读项目 → 跑失败测试 → 修改 → 复测 → 交付报告”的任务，先画出数据流，再到链接的函数中核对。第二遍可以按问题跳读：

| 问题 | 从哪里开始 |
| --- | --- |
| 为什么页面刷新后任务还在？ | 第一册第 3～4、8 节 → 第二册第 2、7 节 |
| 为什么 Worker 强杀后不会任意重复写文件？ | 第二册第 3～5、9 节 |
| 项目只读、可写和本机命令如何区分？ | 第一册第 2 节 → 第三册第 1～4 节 |
| 为什么 `completed` 不等于任务内容正确？ | 第一册第 2 节 → 第二册第 6 节 → 第四册第 5 节 |
| Skill 选中了，为何还不能宣称自进化有效？ | 第四册第 3～6、9 节 |

每个关键源码链接指向仓库内的实际文件。遇到文中“已实现”的机制，请在[当前状态](../当前状态.md)区分代码存在、自动化验证和真实任务验证；运行命令见[用户手册](../用户手册.md)与两种模式的操作手册。按目录找类和脚本见[源码地图](../源码地图.md)。

## 版本与历史章节

这套四册在 2026-09-29 从当前 `c2` 的代码和原阶段手册重写。原手册第 1～112 章完整保留在[旧版逐模块手册](../archive/manual-legacy/README.md)，包括[旧章号目录](../archive/manual-legacy/00-总览与目录.md)。旧文档里“手册第 N 章”的引用仍指旧版对应章节；原文中的“当前尚未实现”等句子按写作当时理解。现行四册使用主题章节，不继续继承旧章号。

维护本教材时，先核对函数入口与行为，再同步[源码地图](../源码地图.md)、[当前状态](../当前状态.md)和本目录。历史验收报告不因为教材重写而获得新的证据等级。
