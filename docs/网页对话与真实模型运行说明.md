# 网页对话与真实模型运行说明

网页对话已经接入现有 Session、Task、Worker 和持久化消息链路，无需等到第五阶段。入口是 `/ui/` 的“对话”页。发送消息会创建或复用 Session，提交 Task；页面轮询任务状态，完成后读取已提交的回复。刷新页面会恢复本机上次选中的 Session，左侧也可切换到其他 Session。`新对话` 只切换到新会话，不删除历史记录。

新版本会从 `/api/v1/runtime-info` 显示“Mock 演示”或“真实模型已配置”；该接口不返回 API Key/Base URL，也不请求远端模型。真实配置可否连通及 API/Worker 是否一致，以实际 Task 为准；不一致会以 `provider_configuration_mismatch` 失败，不能由 Mock Worker 假装执行真实模型任务。对可客观核对的任务，可展开输入框设置回答必须包含的文本、必须成功调用的工具或必须生成的文件。Worker 在完成前检查，失败记 `acceptance_failed` 且 Trace 保留模型原答；不填写条件时，页面明确提示回答未独立核验。具体契约见[运行模式与任务验收说明](Agent运行模式与任务验收条件-2026-09-26.md)。

这条基本对话路径已用真实 DeepSeek 做多轮验证；真实工具、审批恢复、Skill、记忆及 MCP 的具体联验见[阶段性报告](前四阶段补完阶段性验收-2026-09-25.md)。仍缺的用户路径也在报告中逐项列出。页面可显示完成后提交的答复，当前不提供逐字流式输出。

2026-09-25 补完后，选择一条消息可查看该任务的当前状态、模型、工具名称/输入参数/结果、待处理审批及 Skill/检索证据。未完成任务可在此请求取消；`ask_user` 需在审批框填写回复。取消的待审批任务会将原审批记为 cancelled，旧决定不能重新启用任务。对话可直接进入当前 Session 的 Memory 页面和当前 Run 的上下文证据；命中 Skill 时可进入版本评审。所有展示来自持久化 Task/Trace/检索 API，不从聊天文字猜测工具是否执行。

## 本机运行

当前验收环境使用专用 Compose 项目 `evoagent-v04-final`，API 只监听本机 `127.0.0.1:18000`。仓库根目录的 `.env.deepseek` 已由用户本地配置并被 Git 忽略。`compose.deepseek.yml` 只引用此文件，不包含密钥；API 和 Worker 都必须使用同一真实 Provider 设置。

```powershell
docker build -t evoagent:phase4-final .
docker compose -p evoagent-v04-final `
  -f deploy/acceptance/compose.yml `
  -f deploy/acceptance/compose.deepseek.yml `
  --profile app up -d --wait
```

打开 `http://127.0.0.1:18000/ui/`，在“对话”中输入问题。Enter 发送，Shift+Enter 换行。若服务停下，使用同一命令重启；不要删除 Compose 卷，Session 与消息存在 PostgreSQL 中。仓库默认 `docker-compose.yml` 的端口为 8000，使用该部署时入口相应为 `http://127.0.0.1:8000/ui/`。

对话左侧可选择 Workspace，也可输入名称创建新 Workspace；“新对话”放入当前选中的 Workspace，旧会话按所属 Workspace 过滤。服务端 Session 创建请求保存 `workspace_id`；省略它的旧客户端继续进入默认本地 Workspace。此部署是本机可信界面，没有账户认证，不应把 Workspace 下拉框当成访问控制：真正的记忆召回隔离由服务端按 Session 的 Workspace 身份执行。跨 Workspace 真实任务证据见[阶段性报告](前四阶段补完阶段性验收-2026-09-25.md)。

若要在同一验收环境启用记忆、受信 MCP fixture 和本地多语语义检索，使用以下覆盖层。首次启动 Embedding 会下载模型到独立卷；服务健康后 API、Worker 与维护 Worker 才启动。数据库需先执行 `alembic upgrade head` 至 `20260925_0013`。真实模型密钥只留在 Git 忽略的本地环境文件。

```powershell
docker compose -p evoagent-v04-final `
  -f deploy/acceptance/compose.yml `
  -f deploy/acceptance/compose.deepseek.yml `
  -f deploy/acceptance/compose.memory.yml `
  -f deploy/acceptance/compose.mcp-fixture.yml `
  -f deploy/acceptance/compose.embedding.yml `
  --profile app up -d --wait
```

本地 Embedding 是独立于 DeepSeek 对话接口的 ONNX 服务，模型为 `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`，原生 384 维。该部署覆盖层将此模型的向量阈值设为 0.7；默认配置仍是 Mock/1536 维，不能用于真实语义质量结论。网页 Memory 页先选已完成任务的用户消息，复制原话片段并建候选；人工确认后新任务才可召回。Scope 为 Session 或 Workspace，撤销后新任务不再使用；旧任务保留可审计历史。MCP 页需要审核目录、明确激活执行；卸载后新任务不再获得该工具。聊天任务详情链接到对应证据页面。

聊天页不保存或显示 API Key。真实 DeepSeek 调用会使用用户的 API 额度。本机语义服务占用 CPU/内存，未计量 Token 成本；具体样本、失败和时延见[阶段性报告](前四阶段补完阶段性验收-2026-09-25.md)。此验收部署仅供本机使用，没有公网认证入口。

## 执行与上下文

页面使用 `POST /sessions`、`POST /tasks`、`GET /tasks/{id}` 与现有 `GET /sessions/{id}/messages`。消息接口新增 `task_id` 和 `created_at` 字段供页面恢复任务，保留原有 `sequence`、`role`、`content` 等字段。任务未完成时页面显示状态；成功或失败后显示已提交的终态消息。工具过程取自 `GET /runs/{id}/trace`。需要人工确认时，任务详情显示风险、原因和工具参数，由用户明确批准或拒绝；不确定副作用须先核对外部状态，再按原协议提供 `retry` 或 `committed:<结果>`。取消运行中的任务先提出请求，Worker 收尾后才进入终态。当前页面按任务完成轮询，并非逐字流式输出。

普通任务的 Worker 在模型请求前，按任务创建时冻结的 `history_before_sequence` 读取本 Session 已提交的历史提问和终态回复，插入系统提示与当前问题之间。不同 Session 不互相读取。Runtime Eval 继续只使用其固定样本历史，不从普通 Session 回退读取。这修复了“页面能展示上轮消息，模型却说看不到上文”的缺陷。

## 验证范围

浏览器测试覆盖发送、完成回复、刷新后恢复 Session 和第二轮提问；后端测试覆盖消息排序、缺失 Session、Worker 第二次请求的实际消息序列及跨 Session 隔离。2026-09-25 本机用 `deepseek-flash` 通过网页连续执行三轮：第二轮暴露了普通任务未注入历史的旧缺陷；修复后第三轮根据首轮消息正确回答 `EvoAgent`。旧错误回复仍保留在验收会话中，不改写为成功。测试用的公开项目名不会把本地 API Key 写入仓库。

本轮后端全量 **412 passed、13 skipped**，新增隔离断言另行复测通过；前端 **12 组件测试、7 浏览器流程**通过，TypeScript/生产构建和构建产物路径校验通过。13 项跳过仍为独立 Linux Docker 专项 11、SQLite 行锁语义 1、Windows 符号链接权限 1；本轮未改动 Docker 沙箱实现。
