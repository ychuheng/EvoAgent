### 模块 0：工程初始化与配置

- 建立标准 `src` layout 和 Python 包。
- 使用 `pyproject.toml` 管理构建、运行依赖、开发依赖、pytest 和 Ruff。
- 使用 `pydantic-settings` 从 `EVOAGENT_*` 环境变量或本地 `.env` 读取配置。
- 默认使用 `mock` Provider；只有选择 `openai_compatible` 时才要求 API Key、Base URL 和模型名。
- 为轮次、模型/任务/工具超时、Token 软预算、重复调用、工具结果长度和 Workspace 建立类型化限制。
- 加入本地 pre-commit 配置和 Python 3.12/3.13 CI。
- `tmp/` 上游参考仓库和个人简历 PDF 已加入 `.gitignore`，不得提交到公开仓库。

### 模块 1：核心数据契约与运行事件

- 定义 Message、ToolDefinition、ToolCall、ToolResult。
- 定义 ModelRequest、ModelResponse、ProviderEvent、TokenUsage。
- 定义 RuntimeEvent、RunResult 及相关枚举。
- 强制 ToolCall 与 ToolResult 使用关联 ID。
- 强制 Token 总数等于输入与输出 Token 之和。
- ProviderEvent 根据事件类型检查所需字段，拒绝混入其他事件类型字段。
- InMemoryEventSink 在并发环境中统一分配单调递增 sequence。
- EventSink 在记录前递归脱敏，并截断过大字符串；拒绝非 JSON 值和非有限浮点数。
- RunResult 检查 run_id 一致性和从 1 开始的连续事件序号。

### 模块 2：Tool、ToolRegistry 与 Calculator

- BaseTool 声明名称、描述、参数模型、风险、副作用和并发元数据。
- ToolRegistry 只负责注册、查找和输出稳定排序的 ToolDefinition，不执行工具。
- 重名工具、未知工具和不满足 BaseTool 契约的对象都有明确错误。
- Calculator 使用 Python AST 解释有限算术表达式，不使用 `eval`。
- Calculator 拒绝函数调用、变量、容器、布尔值、过大指数、过大结果、非有限结果和复杂表达式。

### 模块 3：ToolExecutor

- 所有模型生成的 ToolCall 统一经过 ToolExecutor。
- 通过 ToolRegistry 查找工具，并使用工具自己的 Pydantic 模型校验参数。
- 将未知工具、参数错误、超时和 ToolExecutionError 转换为一一对应的 ToolResult。
- 非预期工具异常继续向上传播，`asyncio.CancelledError` 不会被包装成普通错误结果。
- 对 ToolResult 实施严格长度限制，并用 RuntimeEvent 记录开始、完成和失败。
- `execute_many()` 首版按原始顺序执行并返回；安全并发仍留到模块 9。

### 模块 4：ModelProvider 与 MockProvider

- ModelProvider 以 Protocol 定义统一的异步 ProviderEvent 流接口。
- 建立 ProviderError、ProviderTimeoutError 和 ProviderProtocolError 错误层次。
- MockProvider 每次消费一个预设步骤，可以展开 ModelResponse、回放显式事件流或抛出预设错误。
- MockProvider 记录收到的 ModelRequest，并在脚本耗尽时返回明确错误。
- ModelResponse 会稳定展开为文本增量、工具调用增量、Usage 和 completed 事件。

### 模块 5：ContextBuilder

- 使用默认或自定义 system prompt 构造初始消息。
- 外部上下文作为不可信 user 资料置于 system 和最终用户任务之间。
- 拒绝空系统提示、空用户任务和空外部上下文块。
- 每次构建都返回新的不可变消息快照，不保存或修改循环历史。

### 模块 6：AgentLoop

- AgentLoop 通过 ModelProvider 获取事件流，通过 ToolRegistry 提供 Schema，通过 ToolExecutor 执行工具。
- assistant 工具调用消息先写入历史，ToolResult 再按原顺序转换成 tool 消息。
- 带文本的工具调用仍会先执行工具，不能被误判为最终答案。
- 只有无 ToolCall 且 finish_reason 为 stop 的非空回答才能成功。
- Provider 错误、协议不完整和非正常 finish_reason 返回类型化失败结果。
- 达到最大轮次或累计 Token 软预算时返回 limit_reached，并且不再发起下一次模型请求。
- Provider 未报告完整 Usage 时结果明确记录为未知，不伪造 Token 数字。
- AgentLoop 不吞掉取消；任务级超时、取消和终态 RunEvent 由 AgentRunner 负责。

### 模块 7：AgentRunner

- 每次 Run 创建独立的 run_id 和 InMemoryEventSink。
- 使用 ContextBuilder 生成初始消息，再组装 ToolExecutor 与 AgentLoop。
- 用任务级总超时包裹完整循环，并区分完成、失败、限制、超时和取消。
- 将 AgentLoopResult、Usage 和事件快照汇总成 RunResult。
- 每个 Run 只由 AgentRunner 写入一个终态事件，Loop 和 Executor 不越权写入。

### 模块 8：OpenAICompatibleProvider 与 CLI

- 实现 OpenAI-compatible `/chat/completions` SSE 流式适配器。
- 将文本、交错 ToolCall 分片、Usage 和完成响应转换成统一 ProviderEvent。
- 对鉴权、限流、服务端、网络、超时和协议错误进行分类，不在 v0.1 自动重试。
- 提供 `evoagent` 命令行入口，支持普通任务、外部上下文、Mock 演示和事件查看。
- 演示模式无需 API Key，可确定性打通“模型—工具—模型—最终答案”。

### 模块 9：安全只读工具与阶段一收尾

- 新增 file_read，仅允许读取 Workspace 内、大小受限的 UTF-8 普通文件。
- 新增 web_fetch，仅允许公开 HTTP/HTTPS 文本地址，并逐跳校验重定向。
- URLGuard 拒绝凭据、localhost 和非公网 IP；WorkspaceGuard 拒绝路径穿越和符号链接逃逸。
- ToolExecutor 将权限拒绝规范化为 permission_denied，并只对整批无副作用且 parallel_safe 的工具安全并发。
- AgentLoop 检测连续相同的工具调用及结果，达到阈值后以 repeated_tool_calls 停止。
- 新增完整集成测试和阶段一架构决策记录。

### 阶段二模块 0：基线冻结与工程配置

- 项目版本进入 `0.2.0.dev0`，加入 FastAPI、Uvicorn、SQLAlchemy asyncio、Alembic、asyncpg 和测试用 aiosqlite。
- 新增数据库、API、Worker、租约和 Artifact 类型化配置；数据库 URL 使用 SecretStr。
- Artifact 根目录必须是 Workspace 的子目录，heartbeat 不得超过 lease 的三分之一。
- 增加最小 PostgreSQL Docker Compose 服务和 CI PostgreSQL Service。

### 阶段二模块 1：数据库基础设施与 Alembic

- 建立统一命名约定、AsyncEngine、async_sessionmaker 和显式资源释放。
- 创建异步 Alembic 环境和首个可升级、可回退 migration。
- 应用正式运行不调用 `create_all()` 修改 Schema，数据库变化必须经过 migration。

### 阶段二模块 2：持久化模型与状态机

- 建立 Session、Message、Task、Run、Turn、ToolCall、RunEvent、RunSnapshot、ToolEffect、ToolApproval 和 Artifact 记录。
- 加入外键、联合唯一约束、事件序号、语义幂等键、索引、UTC 时间和 lock_version。
- Task 与 Run 使用独立纯 Python 状态机，终态不能再次迁移。

### 阶段二模块 3：Repository、Unit of Work 与 Trace

- Repository 封装 Task、Run、RunEvent、RunSnapshot 和 ToolEffect 查询。
- UnitOfWork 统一持有同一 AsyncSession，要求调用方显式提交，异常自动回滚。
- PersistentEventSink 复用阶段一脱敏规则，通过数据库原子 UPDATE/RETURNING 分配事件 sequence。
- TraceService 可以按 run_id 返回 Run 当前状态和有序事件时间线。

### 阶段二模块 4：Task Service 与最小 FastAPI

- TaskService 在同一事务创建 QUEUED Task、首个 QUEUED Run 和 `task.queued` 事件。
- FastAPI 提供 Session 创建/列表、Task 创建/查询/取消/暂停/恢复接口。
- Task 创建返回 HTTP 202；API 请求不直接运行 Agent。
- liveness 与 readiness 分离，业务错误和请求校验使用统一错误结构。
- 运行中取消只设置 cancel_requested，由租约所有者观察并提交终态。

### 阶段二模块 5：PostgreSQL Job Lease 与单 Worker

- 使用 `FOR UPDATE SKIP LOCKED` 在短事务中领取队首任务。
- lease_owner、lease_expires_at 与 heartbeat_at 表示可过期所有权。
- 心跳只能由未过期租约的拥有者刷新，错误 Worker 不能提交结果。
- 过期运行进入 RECOVERING；Worker 通过 TaskHandler 协议与具体 Agent 解耦。
- 真实 PostgreSQL CI 验证两个 Worker 只能有一个领取成功。

### 阶段二模块 6：Artifact、Snapshot 与 LoopState

- LocalArtifactStore 在受控根目录按 Run 保存内容，拒绝路径穿越并记录 SHA-256。
- LoopState 显式保存消息、iteration、Usage、重复调用状态和配置哈希。
- AgentLoop 支持从 LoopState 续跑，只在完整模型—工具边界调用检查点写入器。
- PersistentCheckpointStore 将 `snapshot.saved` 事件与版本化 Snapshot 同事务提交。
- 不兼容 schema 或运行配置默认拒绝恢复。

### 阶段二模块 7：PersistentAgentRunner 与 RecoveryService

- PersistentAgentRunner 把 JobLease、PersistentEventSink、CheckpointStore 和阶段一 AgentLoop 连接起来。
- RecoveryService 区分 RESTART、RESUME、FAIL_UNSAFE 和 FAIL_INCOMPATIBLE。
- 恢复过程记录 started、decided、completed 或 failed 事件。
- 模块 7 当时只自动恢复无副作用路径；模块 9 已把未决 ToolEffect 改为 UNKNOWN 人工确认。

### 阶段二模块 8：分类重试与预算

- RetryPolicy 区分瞬时、限流、永久、需要用户、不确定副作用和预算耗尽。
- 自动重试使用有上限的指数退避和抖动，并支持 Retry-After。
- 次数、累计时间和 Token 三类预算中任一耗尽都会停止重试。
- RETRYING Task 使用 next_attempt_at 调度，到期后写入 retry.ready 并回到 QUEUED。

### 阶段二模块 9：Permission Policy、Approval 与 ToolEffect

- ToolExecutor 通过可选 Middleware 统一接入持久化权限判断，不把数据库依赖写入阶段一工具抽象。
- PermissionPolicy 根据工具及本次参数计算有效风险，并返回 ALLOW、DENY 或 REQUIRE_APPROVAL。
- 审批通过数据库进入 WAITING_USER；ApprovalService 决策后把 Task/Run 重新放回 QUEUED。
- Worker 续跑后 call_id 可能变化，已作出的审批按 Task 内的工具名和规范化参数语义复用。
- ToolEffect 使用“任务范围 + 工具名及规范化参数”的语义键；COMMITTED 复用结果，EXECUTING/UNKNOWN 必须人工确认。
- RecoveryService 遇到未决副作用时不再直接失败，而是标记 UNKNOWN、创建审批并等待用户。

### 阶段二模块 10：Sandbox 与新增工具

- RunSandbox 限制每个 Run 的写入目录，拒绝路径穿越，并使用同目录临时文件加原子替换。
- 新增 file_write、web_search、ask_user 与受控 shell；覆盖写会动态提升到 R2。
- SearchProvider 隔离搜索厂商，Mock 搜索保证核心测试不访问公网，Brave 为可选真实实现。
- ask_user 复用持久化审批恢复，不在 Worker 进程调用同步 input。
- Shell 默认关闭；启用后只接收 argv 和显式可执行文件白名单，并限制 cwd、环境、超时和输出。

### 阶段二模块 11：SSE、完整 Trace 与 Viewer

- SSE 只投影已提交 RunEvent，以 sequence 作为事件 ID，支持 Last-Event-ID 断线续传。
- 空闲连接发送 heartbeat，终态历史发送完毕后关闭；客户端断开不取消任务。
- TraceService 聚合 Run、事件、Turn、ToolCall、ToolEffect、Approval、Snapshot 和 Artifact。
- 新增 Trace API 与最小本地 Viewer，只服务于学习和排障，不扩张为完整聊天前端。

### 阶段二模块 12：容器装配、故障注入与收尾

- ConfiguredTaskHandler 按 Run 装配 Provider、工具和 PersistentAgentRunner，并提供独立 Worker 命令。

## 已固定的接口决策

1. Python 支持范围暂定为 `>=3.12,<3.14`。
2. Pydantic v2 是所有跨模块数据契约的基础。
3. 数据契约禁止额外字段，顶层字段不可重新赋值；包含的 dict/list 仍应被调用方视为只读值。
4. AgentLoop 未来同时依赖 ToolRegistry 获取模型 Schema、依赖 ToolExecutor 执行 ToolCall。
5. ToolRegistry 永远不增加 `execute()`；执行、超时、错误转换和结果截断属于 ToolExecutor。
6. Tool 实现只接收已经校验的参数模型，公开异步 `invoke()`。
7. Calculator 是 R0、无副作用、可并行工具，但模块 2 的测试直接调用它；模型生成的调用从模块 3 起必须经过 ToolExecutor。
8. RuntimeEvent 是运行时对象；第二阶段的 RunEvent 是其数据库持久化表示。
9. ProviderEvent 与 RuntimeEvent 分离，Provider 的流式传输细节不能直接成为数据库事件模型。
10. v0.1 不做 Provider 自动重试。
11. ToolExecutor 只把可恢复工具失败转换成 ToolResult；实现缺陷和取消必须向上传播。
12. ToolResult 的文本包含严格长度上限，截断状态同时写入工具完成或失败事件。
13. ContextBuilder 只构造初始消息，AgentLoop 独占一次 Run 内后续消息历史的追加职责。
14. 外部上下文使用 user 角色并标记为不可信资料，不能获得 system 优先级。
15. AgentLoopResult 和 RunResult 使用 `usage=None` 表示模型未提供完整 Usage；字段仍必须显式提供，不能用零冒充未知。
16. AgentLoop 不产生 run.completed、run.failed 等 Run 终态事件，这些事件由 AgentRunner 统一产生。
17. 重复 Tool Call 的判断同时包含工具名、参数和结果；只有连续相同达到配置阈值才停止。
18. ToolExecutor 只有在整批工具都无副作用且声明 `parallel_safe` 时才并发，并始终按原 ToolCall 顺序返回结果。
19. file_read 的安全边界是配置的 Workspace；解析普通路径和符号链接后都必须仍在边界内。
20. web_fetch 会在请求前和每次重定向后校验 URL 与解析出的全部 IP，但 v0.1 尚未把已校验 IP 绑定到实际网络连接，DNS 重绑定的竞态由后续网络隔离层解决。
21. AgentRunner 独占 Run 终态事件；每次 Run 只能出现 completed、failed、limit_reached、timeout、cancelled 之一。
22. PostgreSQL 是 v0.2 持久化事实来源；SQLite 只用于快速兼容测试，不能证明租约或并发正确性。
23. Pydantic Runtime 契约与 SQLAlchemy Record 分离，AgentLoop 不导入 ORM 或 AsyncSession。
24. UnitOfWork 不自动提交，应用服务必须显式决定事务何时生效。
25. RunEvent.sequence 通过 Run 行的原子计数器分配，并由 `(run_id, sequence)` 唯一约束兜底。
26. 正式数据库 Schema 只通过 Alembic migration 演进。
27. API 只提交和控制 Task，不在请求协程内执行长任务。
28. 数据库行锁只用于领取短事务；执行所有权由可过期 Job Lease 表达。
29. 运行中取消由 API 记录意图，由租约拥有者提交 CANCELLED 终态。
30. LoopState 只在完整模型—工具边界保存，并同时保存 Usage 与重复调用状态。
31. Snapshot schema 与运行配置哈希不匹配时禁止静默续跑。
32. 模块 9 前 RecoveryService 对未决副作用采取保守失败；模块 9 起改为 UNKNOWN + WAITING_USER，仍不自动重放。
33. 只有明确分类的瞬时错误或限流可以自动重试；重试必须经过次数、时间和 Token 预算。
34. ToolExecutor 通过可选 Middleware 接入持久化安全机制；未注入时保持阶段一纯内存行为。
35. 默认策略允许 R0/R1，R2/R3 要求审批；工具可以根据已校验参数提升本次有效风险。
36. ToolEffect 的语义幂等范围是 Task；COMMITTED 保存结果用于复用，UNKNOWN 只能由明确人工决定解除。
37. ask_user 是持久化暂停协议，不在 Worker 中读取标准输入。
38. Shell 默认关闭；argv allowlist 只是应用层限制，不能冒充生产级进程沙箱。
39. SSE 是已提交 RunEvent 的数据库投影，Last-Event-ID 等于最后处理的 sequence。
40. Trace 同时聚合时间线和当前事实表；Viewer 只做本地排障，不承担产品前端职责。
41. 每个 Run 创建独立 Provider 与工具装配；Compose 只运行单 Worker，阶段二不引入分布式队列。
42. Approval 的授权语义由 Task、工具名和规范化参数确定；Provider call_id 只标识一次 Trace 调用。
43. Skill 是声明式数据而非可执行代码；所有模型候选都必须重新经过结构与语义验证。
44. 只有 passed TRAIN EvalRun 能成为来源，HOLDOUT 和私有验证参数不得进入 CandidateGenerator。
45. CandidateGenerator 只能创建 DRAFT，发布权限属于后续评测门禁与人工审批服务。
46. Skill 选择是 Run 的持久化事实；恢复不得因索引变化重新选择。
47. v0.3 小规模检索使用可解释 BM25，不提前引入向量数据库。
48. 每个 HOLDOUT Case/repeat 必须创建 BASELINE 与 PINNED_SKILL 配对；候选版本仍不能由普通 Task API 指定。
49. Experiment lease 与普通 Job lease 分离；Eval Worker 只编排，普通 Worker 仍执行 Agent。
50. Pair 的第一运行顺序按 repeat 交替，第二条先暂停，避免固定顺序和同时资源竞争。
51. Provider 未报告 Usage 时指标必须为 null；未知不能用零代替。
52. 只有公共配置可比较且两边都通过时才讨论效率；失败样本仍进入正确性统计。
53. 正确性、安全、来源和可比较性是硬门禁；效率不参与抵消，也不会单独自动拒绝。
54. 通过 QualityGate 只能进入 REVIEW_REQUIRED，自动评测永远不能直接发布 ACTIVE。
55. EvaluationReport 与 GateReport 用规范 JSON 哈希绑定；首次写入后不得替换。
56. 冻结报告和推进门禁是显式 POST 写操作，GET 报告接口保持只读。
57. 发布在一个事务内退休旧版本、激活新版本、更新 active_version_id 并写审计事实。
58. Skill 聚合写操作必须携带 expected_lock_version；行锁与 CAS 一起防止陈旧覆盖。
59. 回滚目标必须同 Skill、RETIRED、曾通过门禁且仍满足当前工具与 Schema 兼容性。
60. reviewer 当前只是本地审计标签，不代表认证身份或 RBAC 权限。
61. React 页面以服务端为事实来源，写操作成功后重新加载，不用乐观 UI 假装发布成功。
62. 阶段三 Demo 的模拟指标只证明生命周期契约；真实效果数字必须来自真实 Provider 的冻结报告。
63. v0.3 完成后冻结必做范围，不顺手加入长期记忆、MCP、多 Agent 或自动发布。
