## 2. 闸门已实现为**会拒绝的代码**（不只是文档）

`src/evoagent/runtime/budget.py` 是这道闸门的执行体，配置项在 `Settings` 里（`config.py`）：

| 配置项 | 含义 | 默认 |
| --- | --- | --- |
| `budget_trial_limit_micros` | 试跑额度上限（微元整数） | `None`（未填） |
| `budget_total_limit_micros` | 全计划总上限 | `None`（未填） |
| `budget_milestone_limits_micros` | 各里程碑额度；与总额度取**更小者** | `{}` |
| `budget_task_limit_micros` | 每 Task 限额；`0` = 关闭付费路径 | `None`（未填） |
| `budget_input_price_micros_per_million` / `budget_output_price_micros_per_million` | 价格假设（每百万 token 的微元单价） | `None`（未填） |
| `budget_stop_ratio` | 停止阈值比例（默认 100% = 触及上限才停） | `1.0` |
| `budget_scope` | `trial` 走试跑额度，否则走正式额度 | `formal` |

行为（`tests/unit/test_budget_gate.py` 逐条覆盖）：

1. **未填数值即拒绝**：默认配置下任何付费模型调用都会被拒绝，错误信息写明"未填数值不得启动付费评测"
   ——这是计划原话的代码化，而不是"文档提醒"。
2. **价格假设缺失也拒绝**：没有单价就无法计算费用，因此不启动。
3. **接近上限即停止新调用**：每次调用前查该 scope 与 Task 的累计花费，达到 `stop_ratio` 或
   每 Task 限额即拒绝。
4. **试跑与正式分账**：`SpendRecord` 按 scope 累计，试跑花掉的钱不挤占正式额度。
5. **逐次留痕且不可改写**：每次调用记 token 与费用（微元），账本 append-only，报告可据此核对，
   不能只报告便宜的成功样本。
6. **可查状态**：`GET /api/v1/budget-status` 返回当前 scope、是否放行、原因、已花费与阈值，
   便于在启动前就看出"还差哪些数值"，而不是等到付费调用才失败。

金额一律用**微元整数**（1 元 = 1 000 000 微元）并向上取整，避免浮点误差与少算。

## 5. 执行与停止规则

1. **执行器接近上限时停止新任务**；已有任务按限额终止，不允许"再跑一个看看"。
2. **预算不足以覆盖预定 holdout 时，不启动正式评测。**
3. 超支或服务涨价时**暂停**并记录已完成样本；先优化非正式试验或复用已有结果，再决定是否增加
   **已批准**预算。
4. 不得事后删减正式样本、改变阈值或只报告便宜的成功样本。
5. 若确需改设计：发布**新的预注册版本**，并把旧运行标记为**不完整**（不是"失败"，也不是"通过"）。
6. 每次正式运行记录：提交、镜像摘要、配置摘要、Task/Run ID、成本、脱敏差异；密钥与私有正文不入库。

## 6. 价格假设的写法

价格假设必须写成可核对的四元组，不能只写"大约多少钱"：

```text
计费单位：              输入 token / 输出 token（分开）
单价：                  输入 <X> / 输出 <Y>（币种、单位：每百万 token）
单价来源与生效日期：
汇率假设（如涉及）：
单任务 token 估算：      输入 <A>、输出 <B>（来自 dev 试跑实测的中位数与最大值）
单任务费用 = A × X + B × Y（按实测最大值另算一个上界）
```

## 7. 状态漂移闸门

**目的**：防止报告写着"已核对到某提交"，而产品代码此后又改过，结论却沿用旧口径。

`docs/当前状态.md` 的"代码核对基准"一节记录一个提交号。漂移检查的做法：

1. 取出该提交号；
2. 比较它到 HEAD 之间**产品代码、配置、迁移与测试**的改动；
3. 有改动即视为漂移，**阻断里程碑关闭**，必须先重新核对并更新基准提交。

检查命令（脚本见 `scripts/check_state_drift.py`）：

```powershell
python scripts/check_state_drift.py            # 漂移即报错
python scripts/check_state_drift.py --update   # 核对完成后更新基准提交
```

豁免路径：仅 `docs/`、`README.md` 下的改动不算漂移（文档更新不改变产品行为）。
**注意** `scripts/` 属于产品交付面（评测脚本是验收证据的一部分），不豁免。

脚本行为由 `tests/unit/test_state_drift_gate.py` 覆盖（路径分类、基准行解析、
以及"真实仓库的基准与 HEAD 一致"这一条）。基准推进记录见[当前状态](../当前状态.md) §3.2：
2026-09-27 复核后把基准从 `78674c3` 推进到复核时的 HEAD，推进后闸门通过。
