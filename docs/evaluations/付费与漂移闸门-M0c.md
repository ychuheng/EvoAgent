## 4. 执行与停止规则

1. **执行器接近上限时停止新任务**；已有任务按限额终止，不允许"再跑一个看看"。
2. **预算不足以覆盖预定 holdout 时，不启动正式评测。**
3. 超支或服务涨价时**暂停**并记录已完成样本；先优化非正式试验或复用已有结果，再决定是否增加
   **已批准**预算。
4. 不得事后删减正式样本、改变阈值或只报告便宜的成功样本。
5. 若确需改设计：发布**新的预注册版本**，并把旧运行标记为**不完整**（不是"失败"，也不是"通过"）。
6. 每次正式运行记录：提交、镜像摘要、配置摘要、Task/Run ID、成本、脱敏差异；密钥与私有正文不入库。

## 5. 价格假设的写法

价格假设必须写成可核对的四元组，不能只写"大约多少钱"：

```text
计费单位：              输入 token / 输出 token（分开）
单价：                  输入 <X> / 输出 <Y>（币种、单位：每百万 token）
单价来源与生效日期：
汇率假设（如涉及）：
单任务 token 估算：      输入 <A>、输出 <B>（来自 dev 试跑实测的中位数与最大值）
单任务费用 = A × X + B × Y（按实测最大值另算一个上界）
```

## 6. 状态漂移闸门

**目的**：防止报告写着"已核对到某提交"，而产品代码此后又改过，结论却沿用旧口径。

`docs/当前状态.md` 的"代码核对基准"一节记录一个提交号。漂移检查的做法：

1. 取出该提交号；
2. 比较它到 HEAD 之间**产品代码、配置、迁移与测试**的改动；
3. 有改动即视为漂移，**阻断里程碑关闭**，必须先重新核对并更新基准提交。

检查命令（脚本见 `scripts/check_state_drift.py`）：

```powershell
python scripts/check_state_drift.py            # 漂移即报错
python scripts/check_state_drift.py --update   # 核对完成后更新基准提交
```

豁免路径：仅 `docs/`、`README.md` 下的改动不算漂移（文档更新不改变产品行为）。
**注意** `scripts/` 属于产品交付面（评测脚本是验收证据的一部分），不豁免。
