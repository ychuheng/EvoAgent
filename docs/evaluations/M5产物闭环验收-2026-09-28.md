# M5/步骤1 产物闭环验收（2026-09-28）

> 对应本轮任务第 1 项：**先修可取回产物**。用户验收标准是"从网页提交文件任务 → 看到产物预览 →
> 下载后哈希与内容一致"，并覆盖损坏输入、输入中途变化与越权下载。
>
> 离线性：本轮**没有任何付费模型调用**；下面的真实部署演练用的是离线 Provider
> （`WorkerDemoProvider`：`web_search` → `file_write`），它走的是**与真实模型相同的工具链、
> 账本、产物出口与页面接口**，但**不构成 Agent 能力或真实模型证据**。

## 1. 问题：文件写了，产物却是空的

2026-09-28 的 dev 试跑里，模型用 `file_write` 写出了 `meeting-summary.md`，Trace 里能看到工具调用，
磁盘上也有文件，但页面的"产物（F-04）"一节什么都没有——而 F-04 的预览/下载**只读 `artifacts` 表里
已登记的记录**。也就是说：

| 工具 | 写入位置 | 是否登记 `artifacts` | 页面可见 |
| --- | --- | --- | --- |
| `file_write`（修复前） | `<artifact_root>/<run_id>/…`（与产物同一棵树） | **否** | **不可预览、不可下载** |
| `artifact_write` | 同上 | 是（不可覆盖） | 可预览、可下载 |

所以"产物出口"对用户实际不可用：文件在服务器上，但拿不到。

## 2. 修复

| 改动 | 位置 | 说明 |
| --- | --- | --- |
| `file_write` 写出后登记产物 | `tools/builtin/file_write.py` | 返回 JSON：`path`/`bytes`/`downloadable`/`artifact_id`/`content_hash`；没接 ArtifactService 时如实报 `downloadable=false` |
| 同名覆盖**就地更新**同一条记录 | `trace/artifacts.py::ArtifactService.create_or_replace` | 按 `(run_id, uri)` upsert。否则旧记录会指向新字节，下载时哈希校验必然失败——页面上会出现一条永远打不开的产物 |
| 产物允许**子路径** | `trace/artifacts.py::LocalArtifactStore` | `reports/summary.md` 这类路径可登记（此前只允许纯文件名，会先落盘再在登记时抛错）；仍然拒绝 `..`、绝对路径与越界解析 |
| 工具说明写清分工 | `file_write` / `artifact_write` 的 description | 普通文件输出用 `file_write`（可覆盖）；"绝不能被后续步骤替换"的交付件用 `artifact_write`（同名第二次被拒） |
| 明确终态 `input_changed` | `runtime/persistent_runner.py` | `InputChangedError` 被兜底 `except Exception` 吃成了通用码 `persistent_runtime_error`；现改为原样抛出，交给 bootstrap 落成 `input_changed`（与计划 §10 F-02 一致） |
| 页面预览 | `frontend/src/pages/TaskInspector.tsx`、`api/chat.ts` | 产物行新增"预览"按钮：按需 `GET /api/v1/artifacts/{id}`，显示正文、截断提示与"二进制无预览"说明；失败（如 409 哈希不一致）显示原因 |

## 3. 证据

### 3.1 后端端到端（真实 Worker + 离线 Provider，`tests/e2e/test_task_artifacts.py`）

| 检查 | 结果 |
| --- | --- |
| 文件任务终态 `completed`，Trace 列出 1 条 `report.md` 产物（`text/markdown`） | 通过 |
| `GET /api/v1/artifacts/{id}` 预览 == 下载字节，`preview_truncated=false` | 通过 |
| 下载响应头 `X-Content-SHA256` == 登记哈希 == 对下载字节重算的 SHA-256 | 通过 |
| 存储内容被替换 → 预览与下载都 409（拒绝导出对不上哈希的文件） | 通过 |
| 登记记录被改成指向产物根之外 → 409（Store 拒绝越界解析） | 通过 |
| 不存在的产物 id → 404；产物接口不接受任意路径参数 | 通过 |
| 冻结输入被中途替换 → 终态 `failed` / `input_changed`、**零产物**、零工具调用 | 通过（本轮修复的 `input_changed` 映射） |

### 3.2 单元与组件层

- `tests/unit/test_artifact_service.py`（5 项）：登记哈希与磁盘字节一致、同名覆盖只留一条记录且哈希更新、
  未加 `overwrite` 时拒绝覆盖、子路径允许而 `..`/绝对路径被拒、后缀→媒体类型推断。
- `frontend/src/App.test.tsx`（+2 项）：产物列表显示登记哈希与下载入口；点"预览"才请求详情并渲染正文；
  二进制产物如实说"没有文本预览"；预览失败（409）显示原因。

### 3.3 浏览器流程（Playwright，`frontend/e2e/chat.spec.ts`）

新增"文件任务在页面上可预览产物并下载核对哈希"：页面显示产物、登记哈希、点"预览"渲染正文、
下载链接指向 `/api/v1/artifacts/{id}/download`。**14 项浏览器流程通过**、前端 **26 项组件测试**通过。

## 4. 未关闭与边界

| 项 | 现状 |
| --- | --- |
| 真实模型写出可下载产物 | dev 试跑里模型选了 `file_write` 后又去申请 `shell`，任务被取消；**修复后的同一任务尚未用真实模型重跑**（需要新的费用授权） |
| 损坏输入 × 产物 | `extract_text` 的损坏/加密/扫描件错误码与 M5 验收的 `corrupt.pdf` 用例（7/7）已覆盖"如实报告、不编造"；产物层面本轮补的是"输入中途变化 → 零产物" |
| 越权下载 | 当前是**单用户本机**部署，没有认证/RBAC：产物接口按 id 读取已登记记录，防护是"只认登记记录 + 根目录限定 + 哈希校验"，不是"按用户鉴权" |
| 子路径产物 | Store 现在接受运行目录内的相对子路径；`..` 与绝对路径仍被拒绝（单测覆盖） |
