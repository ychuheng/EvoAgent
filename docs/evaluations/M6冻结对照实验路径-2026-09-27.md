## 1. 计划要求与本路径的对应

| 计划 §11 S-03 的要求 | 落地位置 | 检查方式 |
| --- | --- | --- |
| 使用 M0 未暴露、与开发 fixture 不同家族的 holdout | `available_holdout_samples()` 只认台账里 `set=m6-holdout` 且未被使用、未曝光的样本 | 冻结检查 `holdout_set_membership` / `no_holdout_reuse` / `holdout_inventory_sufficient` |
| 同模型、同工具、同预算 | 两臂各自声明 `model`/`tools_revision`/`budget_micros`/`max_total_tokens`，除 `skill_injection` 外必须逐项相同 | 冻结检查 `arms_identical_except_skill`、`arms_config_frozen` |
| 随机化两臂顺序 | 顺序 = `sha256(seed + sample_id)` 的奇偶，逐样本固定且与结果无关 | 冻结检查 `arm_order_randomized_and_recorded`；`plan` 输出可复现的顺序清单 |
| 记录任务成功、时间/token、错误与越权 | 每臂一条 `ArmOutcome(success, wall_seconds, total_tokens, errors, privilege_violations, source, run_id)` | 分析报告逐项汇总；缺可比结果直接判"不可声称" |
| 按样本量规则预注册；样本不足只给探索性结论 | `pairs_required` 必须等于按失配率精确计算出的 `N`；实际配对数不足即降级 | 冻结检查 `sample_size_matches_power_calculation` / `pairs_at_least_floor`；判定 `exploratory_only` |
| 留出集不参与改写 | 样本与 fixture 只在运行前登记；台账只追加 | `check_sample_ledger.py`（正式使用一行一次、候选只能用一次、已曝光不得再当 holdout） |
| 报告配对差异与不确定性 | 精确配对检验 p 值 + 精确条件置信区间 + 不一致对原始计数 | `analyze_pairs()` / `render_analysis()` |

实现位置：

- `src/evoagent/skills/experiment.py`：冻结检查、两臂顺序、配对结果记录、精确判定与渲染。
- `scripts/m6_pair_experiment.py`：`check` / `plan` / `analyze` / `record` 四个子命令；
  `check`/`plan`/`record` 都会先跑一遍 M0b 台账检查。
- `evals/datasets/m6-experiment-001.json`：**预注册草稿**（`status: draft`），记录当前意图参数。
- `tests/unit/test_skill_experiment.py`：19 项，覆盖冻结拒绝路径与判定规则（输入均为合成数据）。

统计口径与[预注册记录](M6预注册-2026-09-27.md)一致：只用**不一致对**，`K = b + c`，
精确双侧 McNemar `p = 2·min(P(X≤d), P(X≥d))`（`X ~ Binomial(K, 0.5)`，`d = min(b, c)`）；
配对差异 `δ = (c − b)/n`，区间用不一致对比例的 Clopper–Pearson 精确区间反推
（等尾，与 `binom.test` 一致；`K = 0` 时不给区间，只写"不可估计"）。

## 2. 判定规则：什么情况下**不许**说收益

这不是"建议"，而是代码里的硬判定（`analyze_pairs` 的 `verdict`），任一条命中即
`not_claimable`，报告里只会出现"不构成效果证据"：

| 触发条件 | 判定 | 为什么 |
| --- | --- | --- |
| 任一臂结果 `source != "real_model"` | `not_claimable` | mock/合成结果不能作为效果证据 |
| 存在缺可比结果的对（一臂成功与否未知） | `not_claimable` | 记录不完整时比较不成立 |
| 任一臂超出冻结预算上限 | `not_claimable` | 超预算的比较已不是预注册的对照 |
| 记录到任何越权 | `not_claimable` | 安全退化必须先处理，不能被平均掉 |
| 可比对数 < 预注册 `N`（且无明显越权等） | `exploratory_only` | 如实写出"本样本量只能检出至少 X 个百分点"，或"没有任何效应可检出" |
| `p > α` | `inconclusive` | **未达显著不等于 Skill 无效** |
| `p ≤ α` 且差异 ≥ 10 个百分点 | `positive_confirmed` | 报告配对差异与区间，不写"证明" |
| `p ≤ α` 且 Skill 臂显著更差 | `negative_confirmed` | 结论是禁用或回滚 |

## 4. 当前阻断项与解除条件

| 阻断项 | 现状 | 解除条件 |
| --- | --- | --- |
| holdout 库存不足 | 家族 `code_comprehension` 只有 4 条，计划需要 78 条（`N × K`，K=1） | 按计划补足样本并在**首次正式运行前**登记进 `manifest.json`；样本制作属于单独排期与成本项 |
| 失配率未实测 | 0.10 是候选假设，`N=78` 由它推出 | 用 dev 试跑实测失配率，重跑 `scripts/m6_preregistration.py` 并同步更新预注册草稿 |
| 模型/工具版本未冻结 | `model`/`tools_revision` 是 `unset` | 确定候选与运行镜像后填入，两臂保持一致 |
| 预算额度未填 | `budget_micros`/`max_total_tokens` = 0 | 由用户给出 M0c 批准的额度数值；未填时预算闸门本来就会拒绝付费调用 |
| 第三方复核者未指定 | 预留比例 M6 1/3（≥20%）已记录，复核者未指定 | 指定未参与实现的人；否则 M6 结论上限为"带自评限制的探索性结果" |

## 5. 明确不声称的事

- **没有任何 Skill 效果结论**：本文只有机制、冻结检查结果与判定规则。真实模型运行一次都没跑。
- **测试里的"结果"都是合成输入**：`tests/unit/test_skill_experiment.py` 用合成配对数据验证判定
  规则（含"mock 证据被判为不可声称"），它们不是实验数据，也不能被引用为收益证据。
- **不能靠加样本以外的办法绕过**：`pairs_required` 必须等于精确计算值，把 10 个百分点改成 20、
  或事后减少配对数都会让冻结检查失败。
- **真实模型端到端与人工评审仍未做**：这与 M1～M5 的结论上限一致，属第 3 节登记的缺口。

## 6. 拿到样本与预算后的操作顺序

1. 补足 holdout（`N × K = 78` 条）并登记：`python scripts/build_m0b_holdout.py --check`、
   `python scripts/check_sample_ledger.py`；
2. 用 dev 试跑实测失配率，重跑 `python scripts/m6_preregistration.py`，按实测值更新
   `evals/datasets/m6-experiment-001.json` 的 `mismatch_rate_assumption` 与 `pairs_required`；
3. 填入 `model`、`tools_revision`、`dataset_sha256`、两臂预算，把 `status` 改为 `frozen`；
4. `python scripts/m6_pair_experiment.py check`（必须全项通过）→
   `... plan`（产出可复现的两臂顺序清单）；
5. 由真实模型执行器按该顺序运行两臂，产出带 `source: "real_model"` 的结果文件；
6. `... analyze --results ...`：得到判定、配对差异与区间；把结论写进带日期的新报告；
7. `... record --confirm-formal-run`：把这次正式使用追加进 `run_ledger.jsonl`（只追加，
   同一次配对实验记一行、两臂共用同一批样本）。
