本次补完针对 [现行计划](../EvoAgent-项目设计与分阶段实现计划.md) 的 E-02 与 X-01/X-03。它不代替 M1～M7 的真实模型任务验收。

## 改动与验证

| 能力 | 具体行为 | 验证 |
| --- | --- | --- |
| 编辑审批预览 | 待审批的 `edit_file`、`apply_patch` 从冻结的工具参数重新执行 `dry_run`，向页面返回逐文件路径、diff、增删行数与截断标志；预览失败或截断时不能从页面批准 | 集成测试验证未写盘、文件变化后预览拒绝；前端测试验证 diff 可见后才可批准 |
| 文件边界 | 每条命令子进程先安装 Landlock：只读运行库和必要的系统文件，只允许写授权项目及本次临时目录；不能读取 Worker 的 `/proc/1/environ` 或其他项目文件 | `scripts/check_project_command_isolation.py` 在实际 Linux Docker 容器中通过 |
| 默认离线 | `allow_network=false` 另安装 seccomp，禁止非 Unix socket；过滤器或 Landlock 不可用时拒绝启动，不退回普通子进程 | Docker 负向检查中直接创建 AF_INET socket 得到 `PermissionError`；项目内写入仍成功 |
| 资源上限 | 单进程 `RLIMIT_CPU`、`RLIMIT_AS`，墙钟超时杀整组进程 | 原命令单元测试与 Docker 负向检查；进程树总内存仍未单独限制 |
| 命令风险分档 | 从真实 argv 判定常见测试/静态检查、构建、安装、通用命令与发布；仅可识别的离线检查自动放行，其他命令逐次审批；远端发布命令拒绝 | 单元测试覆盖类别、审批动作与 `git push` 拒绝 |

这套命令隔离运行在 **Worker 的 Linux 容器**中，不会执行 Windows 宿主 PowerShell。项目写入仍由授权挂载直接回写；部署者须避免把密钥目录登记为项目。`allow_network=true` 仍需单独人工审批；命令分档目前是逐次风险判断，没有长期授权或目的地白名单。常规 R1 项目编辑可能自动放行，新增的审批 diff 只覆盖进入待审批状态的编辑。
