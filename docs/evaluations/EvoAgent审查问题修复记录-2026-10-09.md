## 扫描合同与兼容性

inline 默认 8 MiB、检测 CPU 250ms、含读取/启动/排队 wall 1000ms，并发 2、队列 16；Settings 和 .env.example 已接线到 Runner、Checkpoint、ContextResolver、ToolOutputStore、Worker 和人工 API。offline 为显式单件请求，64 MiB、CPU 2000ms、wall 5000ms；通过后按相同 hash/当前策略缓存结论，后续仍有界读取并复验授权与完整性。规则升版会使缓存失效。尺寸上限不等于保证该尺寸内一定能在 CPU 预算内完成。

Windows 直接启动真实解释器，避免 venv launcher 的 CPU/PID 与实际扫描子进程不一致。Linux 有 /proc CPU 计量和 RLIMIT_CPU 秒级兜底，父进程以约 10ms 轮询执行更细预算；阈值超过后拒绝和终止，不能把轮询说成硬实时精确到 1ms。冷启动 CPU 不计入检测 CPU，但仍受总 wall 约束。普通文件读取的 bytes 与返回截止时间有界，操作系统底层阻塞 I/O 的线程不能承诺被瞬间强杀；可终止的是 CPU 检测进程。

旧复核事件没有 request_body_hash 时，同请求 ID 不能证明请求完全相同，返回 409；用户应以新 ID 和最新条件发起新复核。历史回放的 cleared 只代表当次结论，当前可能已再隔离；响应及页面以当前状态为准。旧冻结 Run 继续用 v1，因此旧 Run 不会凭空获得 v2 新提示；重新开始的新 Run 才获得完整边界。
