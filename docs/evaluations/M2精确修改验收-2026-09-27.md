## 2. 逐项实现与证据

| 任务卡 | 实现 | 验证证据 |
| --- | --- | --- |
| E-01 编辑契约 | `edit_file`（单文件）+ `apply_patch`（多文件）：以 `expected_sha256` 或唯一 `old_text` / 行范围为输入；保留编码、BOM、行尾与权限位；同目录临时文件 + `os.replace` 原子替换 | `tests/unit/test_project_editing.py`；`projects/encoding.py` 的 `DetectedText.encode_like` |

| E-03 多文件事务边界 | 先对全部文件做前置条件校验，再逐个原子替换；中途失败按已写文件的原始字节**逆序回滚**，异常上抛因而**不会**报告为全成功 | `test_patch_rolls_back_when_a_later_file_conflicts`、`test_patch_applies_all_files_when_preconditions_hold` |
| E-04 文件操作 | 新建需显式 `create=true`；`move_file` 拒绝覆盖已存在目标；`delete_file` 只接受单个文件、**拒绝目录**（不做隐式递归清空） | `test_edit_creates_new_file_only_when_declared`、`test_move_and_delete_refuse_unsafe_targets` |
| E-05 账本衔接 | 写工具 `has_side_effects=True`/`parallel_safe=False`，经既有 Policy → ToolEffect 账本；规范化参数构成语义幂等键，重放直接复用已提交结果 | `tests/integration/test_project_edit_ledger.py` |

## 3. 并发与冲突（验收明确要求）

| 检查项 | 结果 | 证据 |
| --- | --- | --- |
| 人工并发改同一文件 | 报 `edit_conflict`，**不覆盖**人手修改 | `test_edit_requires_matching_hash_when_given`（哈希不一致）、`test_conflict*`（采集器注入并发写入后仍拒绝） |
| `old_text` 不唯一 | 报冲突，要求更长上下文或改用行范围 | `test_edit_rejects_ambiguous_or_missing_old_text` |
| 行范围越界 | 报冲突 | `test_edit_reports_out_of_range_line_range` |
| 只读授权 | 写工具**根本不注册**（模型看不到），直接调用也被拒绝 | `test_edit_tool_requires_read_write_authorization`、`test_read_only_project_has_no_edit_tools_registered` |
| 符号链接目标 | 拒绝编辑 | `test_edit_rejects_symlink_target` |
| 不支持编码 / 非 UTF-8 | 拒绝并有可读原因 | `test_edit_rejects_unsupported_encoding` |
| 目录删除 | 拒绝 | `test_move_and_delete_refuse_unsafe_targets` |

**未做**：审批取消与执行中断留证（需要 API/审批链路联调）不在本机 Mock 采集器范围内，见第 5 节。

## 4. 采集链路证据

`scripts/m2_project_edit.py` 在临时 Git 副本上跑 4 条 dev 任务：

| 用例 | 工具序列 | 结果 | 说明 |
| --- | --- | --- | --- |
| `m2-single-file-behavior` | file_read → edit_file（带 `$read_sha` 哈希前置条件） | 成功 | diff 含 `--- a/…` 与 `@@` |
| `m2-cross-file-refactor` | apply_patch（两文件） | 成功 | 报告 `文件数：2` |
| `m2-patch-rolls-back-on-conflict` | apply_patch（第二文件哈希故意错误） | `edit_conflict` | 第一个文件**未留下改动** |
| `m2-conflict-detected` | file_read → （注入并发写入）→ edit_file | `edit_conflict` | 文件保持并发写入后的内容，人手修改未被抹掉 |

- **4/4 `harness_passed`**，报告 `output/m2-project-edit.json`（不进仓库）。
- 报告内 `agent_edit_planning_verified=false`：`steps` 是脚本预设的调用序列，
  它证明编辑契约与冲突处理，不证明模型会自己定位该改哪里。
