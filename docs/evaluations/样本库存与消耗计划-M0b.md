## 2. 正式使用规则

1. 每个候选版本对封存 holdout 只做**一次**正式运行；同一次配对实验的两臂写进
   `run_ledger.jsonl` 的**同一行**，视为同一次正式使用。
2. 只追加、不覆盖：已写出的行不得修改；改写会被 `check_sample_ledger.py` 拒绝。
3. 看过结果后再改 prompt / 工具 / 评分规则 → 产生**新候选**；已看过的样本标记
   `retired_after_viewing=true` 降为 dev，另取未暴露 holdout，原结果永久留档。
4. 每条正式运行记录冻结 `candidate_revision`、`model`、`tools_revision`、`dataset_sha256` 与两臂样本列表。
5. 正式运行使用独立数据库、Redis 与目录；报告提交、镜像摘要、配置摘要、Task/Run、成本及脱敏差异
   （执行计划 §5.7）。

## 3. M7 发布集规模

- 目标（执行计划 §5.6）：**至少 24 条正常 + 8 条故障/越权 = 32 条**，与 dev 小集**不得复用同一批样本**。
- 当前进度：4 / 32（增量第一批）。后续批次按同一预注册版本补足，每一批在**该批首次正式运行前**冻结，

## 4. M6 样本量：方法与待填数值

执行计划 §5.3/§5.9 与 §5.4 要求：先为主要任务家族选定"任务成功率绝对提升至少 **10 个百分点**"这一
最小有意义效应，再从 dev 试跑估计配对两臂的**失配率**，用配对二分类检验求双侧显著性水平 0.05、
至少 80% 检出力所需的**配对数**。

- 配对设计的检出力主要来自两臂结果**不一致**的样本；失配率低时计算值可能达到 100～200 对或更高。
- **每个要单独声称有效的任务家族不得少于 30 对**；实际计划数取 30 与计算值中的较大者。
- 30 对只防止极小样本，**不保证**检出 10 个百分点。
- 若计算值超过可承受预算：可重选确有业务理由的主要任务家族，或转为样本量受限的探索性试验；
  **不得**为适应预算把最小有意义效应从 10 改成 20 个百分点。

| 待填项 | 取值来源 | 当前状态 |
| --- | --- | --- |
| 主要任务家族（唯一） | 由 M6 开工前的预注册决定 | **待填** |
| 最小有意义效应 | 固定 10 个百分点绝对提升 | 已定 |
| dev 试跑实测失配率 | dev 样本上的试跑结果 | **待填**（M6 开工前） |
| 计算所需配对数 `N` | 精确计算或模拟 | **待填**（由上一行推出） |
| 计划正式候选轮数 `K` | 首轮默认 1 | **1**（默认） |
| 需准备 holdout 对数 `N × K` | 计算 | **待填** |

> 「失配率 → 所需配对数 / 可检出效应 / 功效曲线」的完整候选值表已由
> [M6 预注册记录](M6预注册-2026-09-27.md) 给出（脚本 `scripts/m6_preregistration.py` 生成）：

> 不是测量结果，不能当作已冻结的样本量使用。

**首轮默认只承诺 `K=1`**：第二轮只有在新增样本与预算**事先封存**后才能启动，不得临时借用 M7 发布集。

## 5. 缺失数值前的约束

在失配率与 `N` 未实测填出前：

- **不启动 M6 正式评测**（避免"先跑再补预注册"）。
- 可以继续 dev 调优，或报告探索性结果；探索性报告必须给出实际样本量、假设失配率、功效曲线，
  并明确写出"本样本量在 80% 检出力下只能检出至少 X 个百分点的绝对提升"。
- **不得**把未达显著写成"Skill 无效"。

holdout 用尽时**暂停 M6 门槛判定**，等新一批样本在未看结果前登记并封存后，再开启新候选。
