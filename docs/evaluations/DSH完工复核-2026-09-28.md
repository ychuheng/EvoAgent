## 本次发现及处理

1. **浏览器对话被可选项目接口阻断**：项目列表接口返回错误时，`Promise.all` 让会话与 Workspace 也无法加载；页面显示 `Not Found`，既有对话消失。本次把项目列表故障降级为空列表，对话浏览器测试从 4 失败恢复到 13/13 通过。
2. **个人部署看不到宿主项目**：原个人 Compose 只有内部 Workspace 卷，手册却要求登记 Windows 项目路径。本次要求显式配置 `EVOAGENT_PROJECTS_HOST_ROOT`，将它映射到所有应用容器的 `/app/projects`；页面应登记容器路径。验收时临时把仓库根作为测试挂载，Compose 配置检查通过，Worker 容器以非 root 用户实际读写该映射成功。实际使用须选择不含凭据的项目目录；现有容器须重建后才获得新挂载。
3. **维护任务人工重试无效**：耗尽 3 次尝试的任务点 retry 后会再次立即失败。本次人工 retry 重置尝试计数，集成测试覆盖耗尽后的重试并通过。
4. **递归查找误报零命中**：`find_files` 的 `src/**/*.py` 在跨级目录中匹配失败。本次改为按路径段匹配 `**` 的任意层数，单元测试覆盖。
5. **阶段四迁移验收断言过时**：脚本仍要求旧 revision。本次改为读取 Alembic 当前 head，并在全新数据库与含旧消息的升级数据库上实际通过，见 `docs/reports/phase4-final-migrations.json`。
6. **沙箱响应上限的旧判断不准确**：现行控制器先保存原始产物，返回 Worker 的只是产物 ID、名称与哈希；8 MiB 原始产物不会在控制器 HTTP 响应中再次以 Base64 发送。因此“8 MiB 文件必然触发 Worker 8 MiB 响应限制”的说法不能成立。尚未做极限体积专项测试，不能进一步声称无任何输出上限问题。
7. **命令的离线声明不成立**：`projects/commands.py` 在 `allow_network=false` 时只删代理环境变量，并以环境变量标记 `denied`；子进程仍在可联网的 Worker 容器中，直接 socket 连接未被系统层阻止。这是 M3 的安全验收阻断项。本次修正了手册与当前状态，不把清代理误报成断网；后续须为项目命令建立独立无网执行视图，验证直接连接、DNS、代理及恢复行为后才能关闭。
