## 1. 本轮新增的关键证据：持久化运行时里的"跑→改→复测"

既有两套离线采集器（`scripts/m2_project_edit.py`、`scripts/m3_failure_fix.py`）直接驱动
`ToolExecutor`，**不经过持久化运行时**；而 2026-09-28 真实试跑暴露的缺陷
（相同 argv 的第二次 `run_command` 被 ToolEffect 账本复用第一次结果）只在
"账本 + 租约 + 事件"这条路上出现。本轮补的就是这条：

`tests/integration/test_task_loop_acceptance.py`（用 `JobWorker + PersistentAgentRunner + 脚本化 Provider`）：

| 检查 | 实测 |
| --- | --- |
| 完整链路 | `run_command(python -m pytest -q)` 退出非 0 → `file_read` → `edit_file` 修实现 → `apply_patch` **一次改两个文件**（渲染分隔符 + 测试期望）→ **同一条 argv** 再跑 `pytest -q` 退出 0 |
| 相同命令真的重跑 | 两次 `run_command` 的 `return_code` 分别是非 0 / 0；两次调用的 `tool_effects` 是**两条独立记录**且都 `committed` |
| 文件与参数一致 | `cli.py` 不再含 `"saved!"`；`render.py` 与 `tests/test_fieldnotes.py` 都是补丁后的内容；另用宿主 `pytest` 直接复跑副本确认退出码 0 |
| 事件与页面一致 | 5×`tool.started` + 5×`tool.completed` + 末尾 `run.completed`；Trace 里两条 `run_command` 记录的 `argv`/`network=isolated`/`return_code` 与账本一致，两次调用 id 不同（页面不会把第二次显示成"复用第一次结果"） |

**在哪跑、为什么**：项目命令只在 Linux 容器里可执行（见第 3 节），所以这两条测试在 Windows
宿主上按既有约定 `skipif(sys.platform == "win32")`，并在**应用镜像**里用真实
PostgreSQL 实跑（Windows 宿主上的跳过会在全量回归里如实计为 skipped）：

```powershell
docker exec evoagent-m7-postgres-1 psql -U evoagent -d postgres -c "CREATE DATABASE evoagent_verify"
docker run --rm --network evoagent-m7_default `
  -v "D:\EvoAgent\src:/app/src:ro" -v "D:\EvoAgent\tests:/app/tests:ro" `
  -v "D:\EvoAgent\evals:/app/evals:ro" -v "D:\EvoAgent\pyproject.toml:/app/pyproject.toml:ro" `
  -e PYTHONPATH=/app/src `
  -e EVOAGENT_TEST_DATABASE_URL="postgresql+asyncpg://evoagent:evoagent@postgres:5432/evoagent_verify" `
  evoagent-m7-api:latest python -m pytest tests/integration/test_task_loop_acceptance.py -q
# 本轮实测：2 passed
```

## 3. 本轮发现的实际边界：项目命令只在 Linux 容器里跑

在 Windows 宿主上直接驱动 `run_command` 会**拒绝执行**，工具结果与账本记录是：

```
项目命令需要 Linux Landlock/seccomp 隔离环境   (error_code = tool_execution_error)
```

这不是缺陷，是上一轮"缺少隔离能力即拒绝"的设计在宿主侧的表现。对使用者与文档的含义：

- **Windows 宿主上的 EvoAgent 不能直接跑项目的 `pytest`/构建命令**；要跑命令就得用
  `docker compose` 起的 Linux Worker（个人模式默认就是这样）。
- 因此凡是"项目命令 + 失败修正"的验收，都必须在容器里做（本轮已按此执行）。
- 该边界已写入[安全边界说明](../安全边界说明.md)与[运营故障指南](../运营故障指南.md)。
