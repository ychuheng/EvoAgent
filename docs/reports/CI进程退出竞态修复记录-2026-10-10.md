# CI 进程退出竞态修复（2026-10-10）

## 故障与复现

K3 提交 `0d8ea6296cd90836cd9fd21f179139f52c8f65c0` 的远端 CI #37962910948 中，Python 3.12 正常多进程命令用例被 `CommandUnobservableError` 拒绝；3.13、frontend、sandbox 通过，container 因依赖失败而跳过。这一提交的完整远端验收没有通过，不能以此前本地通过代替。

Linux 实际复现：打开子进程 `/proc/<pid>/stat` 描述符，等待该进程退出并由父进程 wait 回收，再读取同一描述符，返回 `ProcessLookupError(errno.ESRCH)`。原计数函数只允许 FileNotFoundError/ENOENT；open→read 之间的退出被误判为可观测性丢失。远端日志没有保存底层 errno，故不能把 ESRCH 冒充当时直接采集到的日志；本次用真实描述符确定性复现证明该路径存在，且新增回归在旧代码上失败。

## 修复与边界

仅在逐项读取 stat 时，允许 FileNotFoundError 和 ProcessLookupError 这两类已消失条目。枚举 /proc 不可读、PermissionError、其他 I/O 错误、格式解析错误仍拒绝；自身启动预检不忽略失踪。没有返回 0 掩盖目录不可读，也没有关闭监控或放宽配额。

新增一项跨平台模拟：open 成功但 read 抛 ESRCH，另一个有效会话条目仍被计数。新增真实 Linux 用例：子进程等待 stdin，先打开 stat，再关闭 stdin 并 wait 回收，实际读取验证 ESRCH，再通过计数函数读该描述符，不依赖随机 sleep 或重跑概率。保留全部已有不可读/越界/超额终止用例。

Windows 定向 16 passed / 3 skipped；真实 Linux 描述符用例仅在 Linux 执行。Linux 定向 38 passed / 3 skipped；实际旧 HEAD 文件挂载回测试源码路径后，确定性回归失败，修复后通过（仅覆盖 site-packages 会被 pytest 的 src 路径优先级覆盖，故不采用该初始错误对照）。冻结树 `d3a8cf3ed979d927391388b52217e8894787ea95` 的 Linux/Python 3.13/隔离 PostgreSQL/Redis 全量 1267 passed / 18 skipped（500.58s），Ruff check/format 441 files 通过。推送后的完整 exact-SHA CI 尚待核对。

本批仅修复进程退出计数竞态，不声明补齐 K2 内核 pids/cgroup 强制配额或后代会话逃逸防护。未开放 personal trial、未进行付费模型调用。
