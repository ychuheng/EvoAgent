## 实现与边界

宿主代码注册六个小型公开 fixture，覆盖数据、文档与代码文件。`GET /personal-validation-fixtures` 返回可审查内容、相对路径、初始清单和数据指纹，不返回宿主路径；页面可明确选择两份样例并审查。冻结服务拒绝未知 ID、同内容别名，以及与已知来源输入 hash 相同的文件；冻结真实 manifest，纳入 validation policy/hash 与请求去重身份。仍要求用户审查独立性，不把不同文件字节解释为统计独立或收益证据。

新增迁移 `20261010_0029` 与 `ValidationReplicaBindingRecord`，每个 request/case/arm/repeat 唯一，绑定真实 EvalRun/Run、workspace、初始清单 hash 和输入指纹。运行绑定不随任务文件变化更新；ORM 拒绝改写/删除，有绑定数据时迁移拒绝破坏性降级。没有声称它能防数据库管理员直接 SQL 修改。

后台先在无数据库锁期间创建受限副本，再在既有来源锁和维护租约栅栏下，同事务登记实验、两臂 Task/Run、绑定及阶段推进。编排拒绝缺失/多余副本；持久恢复从绑定清单恢复，不复制用户项目、不重写合法产物。`PersonalValidationRunGuard` 在每个模型/工具边界核对来源、策略、请求、身份和副本清单；来源失效、请求取消或清单篡改即拒绝。

首次配置冻结前还核对完整初始文件库存与字节 hash，拒绝未登记文件、链接或替换；配置冻结后的恢复则不把任务自己的编辑误当成初始输入损坏。这是全量运行期间发现的额外边界，已加回归，必须在新树重跑，不使用早一轮结果覆盖新代码。

本切片只支持 workspace 来源、宿主公开 fixture。执行复用 `ActiveProject` 文件工具对象，根来自私有绑定目录；不把它登记为用户项目、不修改 Task.project_id，也不赋予原用户项目权限。恢复授权由学习请求/来源/绑定联合控制，不建立第二套可改级的项目授权记录。这是原方案“复用项目登记”在公开 fixture 子切片中的具体收窄；项目来源方法仍保持拒绝，后续必须明确 source scope 与 execution scope 的投影后才能开放。

收集报告必须再次核对真实 EvalRun 对应绑定。初始输入身份与运行后文件分开；Mock 完成以及人工确认均不能获得 trial 资格。
