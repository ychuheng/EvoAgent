# P3 个人验证身份与报告隔离实施记录（2026-10-10）

本提交是 P3/P4 的第二个基础提交，不是个人 Skill 自进化闭环的完成证明。

## 实现与约束

- `learning/validation_schema.py`：由用户冻结正例、反例和 machine/user 判据。禁止客户端提交结果；输入、判据大小和敏感内容有界。具体输入为空、仅换标题或复用相同具体输入的正反例均拒绝。
- 迁移 `20261009_0027`：历史数据集/实验 purpose 默认 formal；历史 arm 按实际 mode 回填。新的对照身份为 experiment/case/arm/repeat，同一实验可比较两个 pinned 版本，保留其实际 mode，不把旧 Skill 伪装成 baseline。含双 pinned 数据时拒绝无法保真的旧结构降级。
- `EvalCoordinator.create_personal_validation()`：必须由有效后台租约和 validation-only 请求进入；请求、候选、旧版、数据集 hash、配置、独占实验身份互相核对；重放返回原实验，配置变化拒绝。仅允许冻结 personal_dev 集与 TRAIN 编排字段，拒绝正式 HOLDOUT，实际普通 Run 的 data_role 为 dev。
- 数据集与实验用途、比较旧版、学习请求关联属于不可变身份；purpose 有数据库 CHECK。不允许把个人数据用途就地改为 formal 来获取正式训练资格。
- `TraceEligibilityChecker`、`SkillAccessPolicy` 的正式训练分支均拒绝 personal_dev/personal_validation；`QualityGate` 与 `SkillEvaluationService.finalize()` 拒绝个人实验。个人实验不会改变正式生命周期或 gate。
- `EvaluationReportService` 的新版个人报告记录 control/treatment 的真实版本和控制组模式；个人报告冻结须等实验 completed，不覆盖 SkillVersion 的正式 evaluation_report_hash。冻结报告可校验 hash 重读。旧 formal 数据集、报告序列化形态不变，固定旧实现 oracle 哈希覆盖兼容性。

## 未完成边界

当前没有开放个人验证/启用 API；普通任务尚未采用新的 trial 选择器。`create_personal_validation()` 只允许 mock，真实付费任务的租约/预算预留适配未接线，因此不能解释成“代码都已完成，只等额度”。

本轮实验测试中的候选由真实 P2 后台链生成；用于报告持久化测试的终态行是明确标注的 fixture，不证明真实任务执行、业务验收或净收益。后续仍需 PersonalValidationService 的独立素材/判据冻结、受控副本、执行与收集、用户判断证据、后台阶段接线、真实付费预留，以及 P4 的统一选择/版本冻结/撤销边界和观察自动刹车。尚未满足这些条件时 trial 保持关闭。
