# P3 个人验证输入冻结（2026-10-10）

## 实现与验收

新增 `learning/validation.py::PersonalValidationService.prepare_cases()` 和严格 `ValidationAdmission`。候选必须已完成用户审查；提交绑定父请求 CAS 版本、审查过的来源 hash 及明确输入独立性说明。来源整份正文经过当前策略复查，短事务重新核对源状态/epoch/hash、产物隔离/擦除、当前工作区学习策略、权限与候选 DRAFT/正文/来源/静态报告。

验证子请求仍只由 LearningRepository 构造、计算 validate:v1 语义身份和客户端别名。数据集 import_in_session 与请求/事件在同一事务写入；客户端幂等冲突会回滚新数据集。冻结 personal_dev/TRAIN 用例、正反例类型、输入指纹、逐项判据、用户审查依据和 Mock 配置；不把机器检查与用户判定混为一谈。

未登记验证器拒绝；空列表/未知参数/错误类型/结构检查冒充业务检查拒绝。当前内置验证器不校验真实代码/数据/文档产物的业务语义，相关家族仍要求用户业务判据。报告预计项数（双臂×次数×判据）最多100。候选提炼输入中已知精确 hash 与新输入相同则拒绝；未知、投影后的输入不能靠 hash 差异证明独立，policy 显式标记为用户审查加已知 hash 对照，没有宣称机器证明了全部独立性。

## 当前边界与剩余工作

这是内部可信控制面服务，未注册 HTTP/模型工具，不自动创建执行 job，不启用 trial。当前只接受非项目的明确结构化输入；项目场景要求独立受控副本，未接通的 fixture 拒绝。不能把已经冻结案例当作执行完成或业务验证通过。真实付费验证仍未接通，没有付费调用。

`learning/validation_execution.py` 的执行/收集草稿是下一批工作区内容，不在本冻结树，也没有执行/验收证据。后续需要源授权运行边界、受控任务作用域、维护阶段/评测完成可靠派送、实际 Run 与逐项结果收集、独立用户判定、就绪报告/指标报告分别绑定，再接选择、观察、自动挂起、启用与回退。缺这些环节不开放试用。
