# P2 后台提炼与反馈修订实施记录（2026-10-09）

本批次的交付边界是“个人任务 → 显式方法授权 → 冻结经验 → 生成或修订 DRAFT → 静态报告 → 人工审查”。确认审查不会启用版本。个人任务验证、trial、统一选择、观察与自动挂起仍须 P3/P4 联合交付，不能把候选审查版称为已完成自进化。

## 代码和事务合同

- `learning/worker.py`：prepare、generate、static_validate 三个持久阶段；每阶段分配独立 maintenance job，产物、请求版本更新、下一阶段 job 与当前 job 完成同事务。新进程可以接续阶段；owner/epoch/expiry、取消、请求 lock_version 和来源状态共同决定提交权限。
- `workers/background.py` 与 `memory/maintenance.py`：复用维护租约和 SKIP LOCKED/CAS，注册新 handler；保留旧归档、Memory 擦除、索引分支。学习失败只允许显式重试，已失去租约的执行者不提交候选或覆盖新 owner 的请求状态。耗尽领取尝试会收敛请求为失败。
- `workers/bootstrap.py`：学习开启时独立单并发 learning lane；critical lane 负责撤销和预算对账，不被长模型调用占住。学习关闭后不领取 propose/validate，但已有撤销清理仍可执行。不为普通任务建立学习请求或正式实验。
- `SkillExtractionService.extract_sources()`：冻结来源的公共草稿写入入口。正式 `extract(eval_run_ids)` 仍作 TRAIN-only 包装；个人来源要求请求和维护租约 fence、scope、来源有效性及 schema v2。后台 handler 在事务外负责生成、取消监测和费用管理，随后把已校验候选交给公共写入入口；使用 caller-owned session 和 complete_stage 回调保证同事务交付，不在此函数内再次调用模型。
- `learning/planner.py`：显式目标/父版本校验、确定性正文 hash 去重；不依模型 name 为已有 Skill 追加版本。用户方法纠错只有唯一冻结选择时才推导修订对象，多对象先请求澄清。新建 slug 冲突明确拒绝。修订生成新 DRAFT 并保存 parent_version_id，不替换 active 指针。
- `skills/access.py`：来源图、workspace/project、版本正文 hash、当前敏感检测、个人来源撤销、正式 TRAIN 身份、Memory 引用与项目授权版本复查；来源图最多 32 个版本、单版本 200 条关联，拒绝循环。修订上下文、候选去重和个人经验的父版本引用共用此检查。它不是 P4 的新 Run 选择入口，旧运行注入接线须在 P4 完成。
- `learning/sources.py`：同时收集新选择记录和旧 config_snapshot 选择身份；去重并限定数量，不以模型猜测版本号。撤销后派生来源文件由 critical handler 擦除，历史 Skill 正文不原地改写。后续 trial/索引禁用仍属 P3/P4。

## 预算与外部调用

`learning/budget.py`、`learning/provider.py`、`db/learning_accounting.py` 和迁移 `20261009_0025`：

1. 冻结生成配置、价格、预算 scope 和用户批准的个人日/请求上限；当前策略收紧立即生效，旧请求未批准额度不会因后续策略更新自动得到授权。生成配置变化要求新请求。
2. 工作区锁保证同工作区只有一个在途预留；PostgreSQL 事务 advisory lock 串行化跨工作区学习总额度检查。已有普通任务付费调用尚未统一预留，不能宣称全系统并发硬封顶。
3. 调用前持久写发送意图；稳定 call_key 包含请求、job 和调用正文 hash。已发送身份不重发，未发送预留才可释放并转交新租约。数据库提交到实际网络发送之间的崩溃窗口保守按 unknown 处理。
4. provider 返回用量时按 reservation_id 幂等结算。没有 usage、冲突 usage 或失联不得伪造零费用；reserved/unknown/不完整 settled 的上界都计入闸门。历史 scope 无法证明时迁移为 legacy，不猜成 trial。
5. UTC 日预算按实际发送日重查；旧日 unknown 仍计原请求与总额度，不永久占新日额度。每次真实派发前有界对账，后台每分钟仅在存在预留时排对账 job。
6. 使用 UTF-8 请求字节和输出上限估算预留，不冒充 provider token 用量。真实提炼需要明确额度和价格，本批没有启动付费模型。

## Schema、兼容和界面

新个人候选 schema v2 包含有限事实条件、适用任务家族、文件类型、简短依据、停止条件及标注 hypothetical/observed 的反例；观察反例必须有引用。拒绝 Python 表达式和静默把 v2 字段塞进 v1。v1 序列化保持原字段集合；使用旧提交生成的固定 golden hash 对照，而非新实现自算期望值。v1/v2 渲染可以显式选择，旧 Run hash 不因此重写。

界面新增预算等待、重复跳过及阶段中文说明；混合/不确定反馈仍请求澄清，审查不显示为已启用。Mock 提炼器是可重复的离线模板，用于证明流程，不证明模型提炼质量或 Skill 效果。
