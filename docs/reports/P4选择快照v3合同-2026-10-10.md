# P4 选择快照 v3 合同

本批只交付可验证的配置合同，不切换生产 Runner、不开放 trial，不代表“反例实验已能跳过 Skill”。后续装配必须同时冻结真实文本与选择记录。

## 合同

新增 `SkillSelectionSnapshot` / `SkillSelectionScope`，含版本、正文与渲染哈希、formal/trial/pinned 来源、工作区/项目范围和 trial 身份。trial ID 与 trial 来源互相约束；数据合同本身不授予访问权限或 trial 资格。

`RunConfigSnapshot` 支持 schema_version=3，要求 selector_version、renderer_version、skill_selection_hash 和真实 selected_skills。第一版最多一条，集合与子对象冻结。真实版本/正文/渲染哈希必须与顶层实际注入字段一致，拒绝伪造或过时身份。旧 schema 不得携带新选择元数据。

`under_test_skill_version_id` 独立表示 pinned 实验目标；v3 允许目标存在而实际选择为空。普通任务不能携带 pinned 目标或 pinned 注入，实际 pinned 注入必须等于目标。两臂比较仍只排除 Skill 实验变量，运行身份会区分“指定但没注入”和“实际注入”。

v1/v2 序列化分支省略新字段；原 canonical_dict 及 content_hash 逻辑保留。新黄金输出在改动前从提交 `52b2c176ff0c31814347281c12d59774f57b1a8f` 捕获，存于 `tests/fixtures/run_config/pre_v3.json`，不是用新实现自行生成后宣称等价。
