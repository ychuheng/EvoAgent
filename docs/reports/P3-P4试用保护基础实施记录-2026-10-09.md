## 已实现的基础

- `20261009_0026` 与 ORM：skill_trials、skill_observations；选择记录预留 trial_id/origin/scope/rendered_hash。同 Skill/scope 的 active 部分唯一索引；观察追加不可改写，试用绑定的来源、报告、健康策略身份冻结。旧选择 origin 标 legacy，不把未知历史记录猜成正式发布或个人试用。
- `skills/applicability.py`：确定性有限条件，无工具调用或模型调用；未验证事实、缺少排除条件事实、类型错误返回 unknown，不把未知当作可以使用；成员比较不以模糊子串匹配工具名称。
- `skills/health.py`：24 小时窗口，最新反馈/Run 去重，重复输入去重，以首次完成时间和 Run ID 排序；3 次明确 skill_related 验证失败才建议挂起，verified_success 重置、unknown 不冒充成功。模型自评、无判据/引用/步骤关联不计数；策略未知和扫描超预算返回 health_pending。
- `skills/trials.py`：独立于正式发布的准入/激活/挂起/回退服务；静态候选审查不足以准入。个人报告必须绑定独立 validate 请求、候选正文/输入/判据 hash、静态父报告及个人实验；有明确正例、反例和业务判定。当前个人实验接口尚未实现，因此不会因这份基础代码误放行真实试用。
- 自动挂起在 Workspace → Skill → Trial 锁内重读观察与健康策略，复核证据 ID，原子更新状态并写一次审计事件；来源失效不等待三次失败。关闭有费用学习也不关闭已有绑定的安全挂起。
- `SkillExtractionService` 后续复核修复：公共个人写入入口原先默认 R1，导致已批准的 R2 来源被错误拒绝；现在取冻结/当前政策中更严格的 risk，并再次检查当前 mode。测试同时验证批准 R2 可生成候选、政策收紧至 R1 阻止交付。
