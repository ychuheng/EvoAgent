# P6a O3：心跳状态合并与取消通知

## 范围与状态

本批保留 PostgreSQL 事实来源、租约、心跳、fencing 和原领取/恢复合同。新增 `runtime_heartbeat_status_merge_enabled`，默认 false。关闭时保持原续租事务与独立取消查询；不能把合并事务视为允许减少取消检查的授权。

代码、定向验证和冻结树完整 Linux 验证已完成；推送后完整 CI 仍需核对。个人学习、候选提炼和 trial 尚未交付，本批不代表 Skill 自进化目标完成。

## 为什么合并后还需要通知

单纯把取消读取合并进续租，会遗漏“续租已提交，取消随后提交，原第二次查询尚未执行”的窗口。开启 O3 时每个 Worker 进程持有一个专用 PostgreSQL LISTEN 连接，迁移 `20261009_0023` 为取消标志 false→true 的提交添加 UUID 通知。通知只提示重新查询，不是取消授权；执行者通过 `LeaseGuard` 校验实际数据库状态、owner、epoch、到期时间和 Run 状态。

订阅健康时 `heartbeat_and_status()` 在一个短事务中续租并返回取消状态，只读取一次数据库时钟。订阅未就绪、SQLite、触发器缺失或连接断开时恢复原续租与独立取消查询；断开同时唤醒现有等待者，避免静默遗漏已提交取消。重连退避 1/2/4/8 秒，提示不推迟原心跳截止时间。通知队列按 Task UUID 合并，最多 1024 个等待者，未知或非法 UUID 忽略。

代价必须计入：开启后每个 Worker 进程多一个 PostgreSQL 连接，有启动时 LISTEN/触发器检查和取消时一次重新查询。迁移安装后的取消事务会产生固定 UUID 通知；通知既不携带任务正文，也不依赖 Redis。健康心跳的 SQL 降幅不包含该连接启动成本，不能据此宣称所有任务都变快。短于心跳周期的 P0 任务未必受益。

## 代码落点

- `tasks/lease_guard.py`：`check_with_time()` 返回本轮校验使用的时钟，保留原 `check()` 合同。
- `tasks/lease.py`：`HeartbeatStatus` 与 `heartbeat_and_status()`；原 `heartbeat()` 路径保持关闭对照。
- `tasks/cancel_notifications.py`、迁移 0023、ORM 建表 DDL：事务性通知及对称卸载，不改旧任务历史数据。
- `workers/cancellation.py`：进程共享订阅、退化原因、断连唤醒、重连和资源释放。
- `workers/heartbeat.py`、`workers/main.py`、`workers/bootstrap.py`：按冻结启动配置接线；所有提示仍走受保护查询。

## 验证与测量

隔离 PostgreSQL/Redis 下，心跳、通知、迁移和 fencing 定向组合为 **32 passed / 1 skipped**；跳过项为 SQLite 不具备行锁的合同。验证包括提交后才通知、回滚无通知、合并读取后取消、不可信提示、触发器缺失、真实订阅连接断开，以及真实 Runner 的流关闭、仅一次模型派发、无新增工具调用、Task cancelled。O1 批量开关与 O5 已退避到 8 秒的维护 lane 均纳入 Runner 取消组合。

健康心跳测得：原路径 2 个事务开始、3 次数据库时钟读取、8 条 SQL；合并路径 1 个事务开始、1 次提交、1 次时钟读取、4 条 SQL。正常取消通知产生的重新查询是额外成本，不能算进“零额外查询”。

[原始同相位测量](P6a-O3同相位PostgreSQL取消测量-2026-10-09.json) 每组 30 个样本，10 秒心跳，独立预领取任务、本地 ASGI 取消入口、同一 PostgreSQL、reference 与开启组配对覆盖整个心跳相位；无付费模型调用。

## 推送前全量检查发现及修复

1. 第一份冻结树（`4406e55c1df61b451f5fbd125fd1225be6a41f0d`）Linux 全量为 1112 passed / 18 skipped / 1 failed：直接执行 Runner 的恢复测试使用真实一秒租约且无后台心跳，繁忙机器上越过到期时间。测试改为显式固定时钟、失败后再推进；生产租约校验不放宽。
2. 第二份冻结树（`99d993aa7f9a1704696462e8ad2d08ee3151f3b7`）为 1114 passed / 18 skipped / 1 failed：沙箱取消清理写入偶发 SQLite 锁冲突。连续 20 次单独运行均通过，因此不把重复运行作为修复证据。新增可控连接 ping 中断测试，旧路径确定性失败；`SandboxService.check()` 改为等待短检查及会话释放后传播取消，阻止在读连接尚未释放时开始清理写入。沙箱与取消合同定向 **27 passed**，不增加 SQLite 超时或削弱 fencing。

第三份冻结源码树 `8276de81a9438b1caf8701f26111171baff58deb` 的完整 Linux/PostgreSQL/Redis 验证 **1116 passed / 18 skipped**（398.84 秒），Ruff check 与 format check 均通过；Windows 本地沙箱定向 27 passed、状态文档合同 21 passed。源码通过 Git archive 固定，验证数据库和 Redis 均为一次性隔离资源，不将并发工作区变化算作该版本证据。

## 放行边界

默认继续关闭；只有本批完整 CI 与专用环境组合验证通过后才扩大启用。订阅断开时仍受原 10 秒心跳约束；数据库本身不可用时不能承诺快速取消。PostgreSQL 通知队列、部署权限与连接容量须符合部署条件，本批不声称任意数据库故障下取消请求都能提交。取消派发延迟和沙箱清理完成分别计量。
