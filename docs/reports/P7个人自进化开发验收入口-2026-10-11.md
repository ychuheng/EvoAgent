# P7 个人自进化开发验收入口

新增计划中的 `scripts/personal_skill_evolution_dev.py`，必须显式传入 dev manifest；只允许两类固定开发场景，不接受任意 pytest 参数、holdout、真实 Provider 配置或用户项目路径。每次子进程清除 EvoAgent 配置/数据库地址，使用 fixture 创建的临时 SQLite 数据及注入 Provider；不调用产品服务、不做付费评测。

脚本运行真实 API/服务/Worker/选择/观察链路，不以静态 JSON 冒充执行。输出实际 Run/Request/Experiment/Version ID、版本/输入/配置/策略 hash 和审查状态。人工业务判断、真实费用账本测试额度仍是合成 fixture，actual paid_calls=0。开始/结束记录源码摘要，变化则 complete=false，不能把跨版本结果当成稳定证据；Git SHA 和开发源码摘要分别记录。

## 两个场景

1. `reuse-revision-brake`：两臂验证与任务费用账本机制 → 人工合成判据 → 普通任务真正采用 → 三个独立技能相关失败 → trial 自动挂起 → 显式纠正/学习同意 → 新候选审查。保存原定义、父版本和新修订 hash；审查不自动激活、旧 trial 保持挂起。
2. `repeat-failure-aggregation`：三个已冻结且逐条同意的独立失败 → 后台 discovery 幂等入队 → 实际后台生成 → 三条来源均保留 → 候选仍 DRAFT → 撤销其中一条后访问被拒。自动生成候选与自动授予使用资格明确分开。
