# P0 固定任务与运行成本基线

Runtime 基准：`fa99ba348f5e617e69ede4cf04d266951096b69c`。采集脚本内容指纹与平台信息保存在 [原始 JSON](P0运行成本基线-PostgreSQL-2026-10-09.json)。本批未修改 Agent 的执行行为。

固定任务家族为 project_read：临时项目中读取一个 README，脚本化 Mock 先调用一次 file_read，再流式输出 32 个 delta；固定两个模型请求。每次创建新会话，避免历史增长污染比较。1 次预热，20 次测量；使用独立 PostgreSQL 验收库，完成后清理。全部调用为 Mock，费用为零。

| 指标 | 当前基线 |
| --- | --- |
| 每任务 SQL | 523（SELECT 407 / INSERT 56 / UPDATE 60），20 次完全一致 |
| 每任务事务 | begin 70 / commit 56 / rollback 14 |
| 每任务事件 | 48 |
| 每任务快照 | 2，规范 JSON 共 4914 bytes |
| 完成时延 P50 / P95 | 1978.727 / 2628.112 ms |
| Python heap 峰值 | 7447465 bytes，包含采集与运行开销 |

这些数据定位的是受控任务的持久化成本：大量查询和提交与进度事件有关，适合在 P6a 逐项降低。SQL 和事务计数包含 Task 创建、领取、执行、心跳与收尾，排除样本前的新会话创建及结束后的证据查询。`parameter_repr_bytes` 是参数表示长度的近似指标，不称为 PostgreSQL 网络/磁盘实际字节。

`queued_event_ack_ms` 只测 TaskService 提交首个队列事件并返回的时间，不冒充浏览器 SSE 可见性。Mock、tracemalloc 和本机 Docker PostgreSQL 都是限定条件；20 个样本的百分位只作描述，不证明生产 SLO，不证明真实模型吞吐或 Skill 收益。

复测使用 `scripts/runtime_performance_baseline.py --repeats 20 --deltas 32 --output <报告>`；设置 `EVOAGENT_PERF_DATABASE_URL` 为独立、空的 `evoagent_perf_*` PostgreSQL 库。SQLite 要求全新且同此前缀的文件。脚本不读取产品 `.env` 或 EVOAGENT_DATABASE_URL。比较时固定任务/fixture/script 指纹、平台、数据库、运行参数和测量开销，另记优化开关值。

Renderer v1/v2 与旧 Run config/hash 兼容已由 S0 修复及其完整 CI 验证，本批不再改动渲染语义。新增采集器验收：3 项测试通过（真实持久化任务成本、拒绝产品连接、拒绝覆盖已有 SQLite 数据）；Ruff 通过。后续 P6a 仍必须验证取消延迟、恢复积压和开关关闭等价，不能只凭 SQL 降低放行。
