# P4 显式任务类型与三态适用性接线

这是统一选择之前的一个合同切片，不等于 P4 完成或实际 Skill 自进化闭环。

## 行为与实现

- `Task.family` 是用户创建任务时可选的有限类别；API、TaskService 和数据库约束分别限制合法值，ORM 更新禁止修改。前端只用于本次任务，提交成功后清空。模型的目标文字、猜测不提供这个事实。
- `0031` 迁移增加可空字段。旧记录仍为 NULL，不从旧 goal 推断类别。已有非空类别证据时拒绝降级，避免静默丢失冻结事实。
- `VerifiedSkillFacts.from_runtime` 从注册工具实现和显式输入 manifest 取得事实。项目可用性只确认实际 ProjectFileReadTool 已注册；不代替项目授权复核。扩展名只是输入元数据提示，不表示解析或内容格式认证。混合扩展名、未指定输入与未指定类别均保持未知。
- 保留已有 `compare` / `assess` 三态合同及 missing_facts/reasons；不将 `general` 擅自视为通配符。未知反例条件也拒绝自动注入。
- `SkillRetrievalService` 普通 BM25 入口与 `ContextResolver` 的候选读取、最终冻结复验使用同一判断原语。v1 不新增任务类别要求；已冻结选择按原恢复合同读回，不根据新目标/新分类再排序。
- 这一切片不新增每轮、每次工具调用的事实数据库查询：BM25 首次选择读取 Task，混合入口使用已加载 Task；冻结后按原路径恢复。

## 验证与发现

初次新测试有三个 Settings 参数错误（lexical threshold=0 非法），已改为合法正数；这是测试错误，不改产品配置约束。新增 nullable family 使旧迁移夹具的当前 ORM INSERT 向旧表发送不存在的列，已将历史夹具改为显式 Core INSERT，让旧表继续真实升级；不能用“先升级再伪造旧表”的方式绕过。

Windows 定向回归 48 passed / 10 skipped（PG 没有配置，不能作为 PG 通过证据）；追加迁移证据后 migration 单独 5 passed / 1 skipped。前端类型检查、38 单元用例、构建、16 浏览器用例通过。Linux 冻结树 `b5f04952f6a5e65df442886f278ce1bd5233d037` 的 Ruff/格式 468 文件通过，独立 Linux/Python 3.13/PostgreSQL 回归 **89 passed / 1 skipped**（唯一跳过为 SQLite 无行锁语义用例；对应 PostgreSQL 分支已通过）。本批完整远端 CI 待提交后核对。
