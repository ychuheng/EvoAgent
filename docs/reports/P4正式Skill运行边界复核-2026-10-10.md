# P4 正式 Skill 运行边界复核

`FormalSkillReader.check_run_bindings` 对普通 retrieval Run 的实际选择重新检查范围/停用、拒绝状态、正文哈希与敏感内容，以及已冻结的正文身份。替换活动版本不会静默改写已冻结选择；明确越范围/停用/正文失效返回 `skill_source_revoked`。

模型请求在 `PersistentEventSink.emit(MODEL_REQUESTED)` 的短事务中复核；工具执行前复用 Runner 的 `_load_owned_records` 租约检查。复核不会进入 MODEL_DELTA 或进度批次提交。MemoryError 保留到 Runner 的业务错误出口，避免变成通用 persistent_runtime_error。前端增加对应中文提示。

## 实际复现

- 第一轮模型完成之后改变 Skill 范围：工具未执行，第二次模型调用也未发起。
- 第一次工具完成后改变范围：已完成动作保留，第二次模型调用未发起，终态保留明确错误码。
- 同一次请求生成 40 个进度片段：绑定检查只在 MODEL_REQUESTED 执行一次，flush 和 MODEL_COMPLETED 不增加该检查。

这些均用合成 Mock Provider 和专属测试库，不调用付费模型。

## 验证与失败记录

初次补丁放错到进度 flush 分支，Ruff 在提交前检出 undefined event_type；已移回 MODEL_REQUESTED 出口并增加上述查询边界用例。首次冻结树 `ef2f88ca20a7a41b4b185ae396f8e8882468b56a` 的 Linux 检查 129 passed / 1 failed / 1 skipped：批量进度 event_db 夹具未清理 PG 元数据表，之后初始迁移创建 sessions 冲突。保留原始失败日志，补夹具 finally 清理，没有改迁移或移除失败测试。

最终冻结树 `dbac62b077a9893f4cbdb7d9ff536cafe98a1cbe` 在独立 Linux/Python 3.13/PostgreSQL/Redis 环境 **130 passed / 1 skipped**，471 文件 Ruff/格式检查通过；唯一跳过是 SQLite 行锁分支，对应 PG 分支通过。前端类型检查与 38 单元用例通过。完整远端 CI 待按准确提交核对。

## 明确的限制

此处只是正式选择的范围/状态/正文绑定检查，不代表已接完整来源图、trial 来源撤销或健康闭环。pinned 内部实验继续由其原 guard 授权，不用此入口授予 DRAFT 或 trial 访问。

新增读取发生在模型/工具边界：有实际选择时通常两次读取（选择与版本/Skill 联表、调用者工作区），无选择时一次空选择读取；没有新增逐 delta 访问。未测最终 P6b 延迟和全局 SQL 减负，不据此声称性能已达标。

本批还确认一个需要接着修的现有隐私问题：POLICY_VERSION=2 的原始文本规则对带引号的 JSON password 字符串不命中（仅使用合成 fixture 值复现），与结构化 redact_value 路径不一致。后续扩容必须升策略版本、登记预期差异并验证旧 artifact 重新注入，不能悄悄改规则或宣称任意未知秘密都能识别。
