# P6a O1：流式进度批量提交

本次只交付 O1；O2～O5 和个人反馈学习、候选生成、验证与 trial 闭环仍待实现。S1 `fa99ba3` 和 P0 `7610cd5` 的完整 CI 均已通过。

## 行为与边界

`Settings.runtime_event_batching_enabled` 默认 false。新 Run 显式开启时把 `progress_write_mode=batched_v1` 写入冻结配置；恢复时使用已存模式，关闭开关不会改变旧 Run 的配置/hash。旧 manifest 不加入空字段，旧 hash 保持一致。

`AgentLoop` 只把 MODEL_DELTA 交给独立的 `append_progress(ProgressEventType.MODEL_DELTA)`。传普通 EventType（包括同值 MODEL_DELTA）或字符串都拒绝；关键事件继续走 `emit`。返回 ProgressReceipt 只有接收水位和 durability，不把未提交 sequence 暴露给 SSE。关闭模式立即提交，返回 committed；批量模式返回 buffered，不能据此宣称已经耐久。

进度先脱敏，再放入内存。100ms / 32 条 / 64 KiB 任一边界触发写入；单条超过累计预算拒绝。内存缓冲直接限制为 64 KiB，严于方案 256 KiB 总预算，满时等待短事务提交形成背压。计数为脱敏载荷的规范 JSON 字节，不宣称包含 Python 对象全部内存。第一次保留已有完整耐久事件列表，后续有界 trace/投影优化不在本次交付内。

一批在同一短事务内重新检查租约 fencing、来源有效性、原子分配连续序号和追加事件；审批、工具结果、模型完成/失败等 emit 都先提交已有进度。检查点写入前同样先 flush，快照自身仍沿用原有事务合同。flush 在互斥锁内提交调用前已经接收的有限水位，不追赶后续无限生产者。

后台提交失败会主动取消执行任务；同步写失败直接停止调用链。提交结果不确定时清空本地待提交队列并锁定错误，close 不自动重放。租约丢失时 abort 丢弃未提交进度，关闭后拒绝迟到写入。正常、取消、审批、超时、来源变化和异常都由 Run 执行生命周期统一关闭 sink；关闭等待正在进行的事务结束，不先取消 COMMIT 再重放同一批。工具审批和副作用恢复语义未降级。
