# P3 人工判定与报告修订（2026-10-10）

## 实现范围

新增 ValidationJudgmentService 和严格 HumanCriterionJudgment/HumanJudgmentSubmission。这是内部可信用户控制面，未注册模型工具或 HTTP 路由。actor 固定 local-user，不接收客户端/模型提供的权威来源。判定必须绑定实际 EvalRun、冻结判据、候选、当前报告 hash 和请求 CAS 版本；不能替换机器判据。来源整份正文先在数据库锁外经过当前策略检查，短事务复核来源 epoch、策略、候选 DRAFT/作用域/来源图、实验与指标报告身份。

迁移 20261010_0028 增加 validation_judgments 表。工作区客户端键和请求修订分别唯一；ORM 拒绝改写已有判定。每批保存正文 hash、原报告 hash、逐项意见、结果报告快照/hash、用户身份和修订；同事务写审计事件并更新请求当前报告。客户端重试返回原判定记录，改正文冲突；用户纠正另追加记录，不覆盖旧报告历史。报告增长超过128KiB或出现敏感内容拒绝。空表允许降级；存在人工证据时拒绝破坏性降级。本批不声称数据库管理员直接 SQL 无法修改或删除记录。

修正 SkillTrialService 的指标报告/审查报告 hash 绑定，要求明确 trial_eligible=true 且排除 Mock 证据。即使用户认可离线结果，也没有试用资格。另补运行守卫核对 request.validation_experiment_id、收集阶段检查候选仍为 DRAFT。
