# 阶段四模块 8：MCP 连接、发现与目录版本验收

版本 `0.4.0.dev0`；实现于 2026-09-20～21。原理见[手册第 74～77 章](EvoAgent-源码讲解与学习手册.md)，取舍见 [ADR-010](ADR-010-MCP发现连接与目录版本.md)。

## 1. 已交付与当前边界

| 能力 | 当前实现 |
|---|---|
| 官方 SDK | 固定 mcp==1.30.0，项目接受协议 2025-11-25 |
| stdio | 部署者预设绝对执行文件/argv，限受信 fixture |
| Streamable HTTP | 预设 HTTPS 端点、公网解析、固定连接 IP、Host/TLS SNI、禁止重定向 |
| 本地例外 | 明确命名且 local_fixture=true 的字面 loopback profile |
| 生命周期 | 连接专属任务开关 SDK，初始化重试有界，ping/健康 TTL，退出清理 |
| 发现 | 完整分页、名称/大小/Schema 校验、通知触发刷新 |
| 目录 | 不可变修订、hash、diff、配置版本绑定 |
| 审核 | 默认未批准/R3，人工决定追加历史，CAS 拒绝旧请求 |
| API | 配置、显式发现/断开、目录/审核/健康读取，无 tools/call |

当前管理 API 进程持有连接。普通 Worker/Run 不自动连接 MCP，也不因为工具被审核就可以调用。ToolAdapter、Run 目录冻结和统一 Policy/Approval/Effect 执行属于模块 9。

## 3. 离线 stdio fixture 运行

下面在 Windows PowerShell 中配置项目自带的受信 fixture。使用绝对 Python 路径，固定运行 `evoagent.mcp.fixture`；API 请求不传执行命令。

```powershell
$mcpPython = (Resolve-Path '.\.venv\Scripts\python.exe').Path
$env:EVOAGENT_MCP_LAUNCH_PROFILES = @{
    fixture = @{
        command = $mcpPython
        args = @('-m', 'evoagent.mcp.fixture')
        trusted_fixture = $true
    }
} | ConvertTo-Json -Depth 5 -Compress
```

若本机没有 PostgreSQL，可以为演示使用独立 SQLite 数据库，在同一终端迁移后启动 API：

```powershell
New-Item -ItemType Directory -Force -Path '.\workspace' | Out-Null
$env:EVOAGENT_DATABASE_URL = 'sqlite+aiosqlite:///./workspace/mcp-demo.db'
.\.venv\Scripts\alembic upgrade head
.\.venv\Scripts\evoagent-api
```

API 将占用当前终端；在另一个终端进行后续 HTTP 操作。这里无需启动普通任务 Worker，也无需模型密钥。fixture 提供两页工具元数据，没有远端业务执行能力。

## 4. 创建、启用和发现

```powershell
$mcpApi = 'http://127.0.0.1:8000/api/v1/mcp'
$mcpConfig = @{
    name = '本地受信 fixture'
    transport = 'stdio'
    launch_profile_id = 'fixture'
    enabled = $true
}
$mcpServer = Invoke-RestMethod -Method Post -Uri "$mcpApi/servers" `
    -ContentType 'application/json' -Body ($mcpConfig | ConvertTo-Json)
$mcpCatalog = Invoke-RestMethod -Method Post `
    -Uri "$mcpApi/servers/$($mcpServer.id)/discover"
$mcpCatalog | ConvertTo-Json -Depth 12
```

省略 enabled 时默认 false，discover 会返回 mcp_server_disabled。创建 enabled 配置也不会立即启动进程；只有显式 discover 才连接。

应看到 fixture_echo、fixture_health，revision=1、content_hash 和 diff，以及 execution_enabled=false。再次 discover 无变化会复用同一个目录；GET catalogs/health/reviews 只读取，不连接 Server。

```powershell
Invoke-RestMethod -Uri "$mcpApi/servers/$($mcpServer.id)/health"
Invoke-RestMethod -Uri "$mcpApi/servers/$($mcpServer.id)/catalogs"
Invoke-RestMethod -Uri "$mcpApi/catalogs/$($mcpCatalog.id)/reviews"
```

健康观察有效 60 秒；过期或配置版本不同为 stale。记录 ready 不代表进程重启后存在同一个 Session。

## 5. 本地审核与目录变化

初始审核全部为 approved=false、risk=R3、effect=non_idempotent_write，即使 Server 自报 readOnlyHint=true。

```powershell
$mcpReview = @{
    expected_lock_version = 0
    tool_name = 'fixture_health'
    approved = $true
    risk = 'R0'
    effect = 'read_only'
    reviewer = 'local-developer'
    reason = '核对了项目内置 fixture 源码'
}
Invoke-RestMethod -Method Post -Uri "$mcpApi/catalogs/$($mcpCatalog.id)/reviews" `
    -ContentType 'application/json' -Body ($mcpReview | ConvertTo-Json)
```

审核版本从 0 增加到 1，旧记录保留。后续审核须读取最新 lock_version；重发旧版本返回冲突。审核只保存元数据，不使工具立即可调用。

支持 list_changed 的 Server 发送通知后，连接任务重新分页发现，变化写成新的目录 revision；所有新目录工具重新进入待审核状态。分页期间发生变更会整批重读，最多三次。测试通过 fixture 的原子状态文件更新实际验证通知链；默认无状态文件的演示 fixture 目录固定。

## 6. 持久禁用与暂时断开

暂时断开：

```powershell
Invoke-RestMethod -Method Post -Uri "$mcpApi/servers/$($mcpServer.id)/disconnect"
```

这会关闭当前进程的连接和子进程，但不修改配置 enabled。之后显式 discover 可以重连。

持久禁用使用配置 CAS；本例自创建后未修改，expected_lock_version 仍为 0：

```powershell
$mcpConfig.enabled = $false
$mcpUpdate = @{ expected_lock_version = 0; config = $mcpConfig }
Invoke-RestMethod -Method Put -Uri "$mcpApi/servers/$($mcpServer.id)" `
    -ContentType 'application/json' -Body ($mcpUpdate | ConvertTo-Json -Depth 6)
```

配置先提交新版本再等待关闭，迟到发现无法覆盖新的禁用决定。若此前更新过配置，应先 GET servers 读取当前版本，不手工绕过冲突。

## 7. HTTP 与秘密配置

生产 HTTP profile 通过 `EVOAGENT_MCP_HTTP_PROFILES` 设置，例如命名 profile 对应一条已经审核的 HTTPS `/mcp` URL。ServerConfig 使用 transport=streamable_http、endpoint_profile_id，不能同时指定 launch_profile_id。

普通 profile 拒绝 URL 凭据、query、fragment、私网地址、代理环境与重定向。需要秘密时，部署者设置：

```dotenv
EVOAGENT_MCP_SECRET_REFS={"service-auth":"EVOAGENT_MCP_SECRET_SERVICE"}
```

再通过本地秘密环境配置 `EVOAGENT_MCP_SECRET_SERVICE` 的实际值；ServerConfig 只写 secret_ref=service-auth。不要把秘密值放进文档、profile 参数、URL 或 Git。缺失秘密会在连接时明确失败。

本地 HTTP fixture 需要专门命名的 profile，且显式 local_fixture=true、主机为字面 127.0.0.1 或 ::1。集成测试会临时启动真实 TCP Server，自动使用随机端口并关闭；不需要长期打开测试服务。

## 8. 资源与兼容边界

- connection_timeout/call_timeout 默认各 10 秒，范围 0.1～30 秒；max_concurrency 首版固定 1。
- Manager 默认最多 8 个连接；人工建连/刷新串行，后台通知合并后刷新。
- 初始可恢复传输错误最多两次尝试；后续断线记 degraded，下一次显式 discover 才重新建连。
- 目录最多 16 页、128 工具、1 MiB；名称 128 字符、描述 4096 字符、Schema 64 KiB/深度 16。
- Schema 采用 Draft 2020-12，根 object，禁止远程引用/改变引用基址；参数实例验证留给模块 9。
- HTTP 流限制 2 MiB，拒绝压缩响应；stdio 仅受信 fixture，不能据目录限制宣称敌对进程资源隔离。
- stderr 丢弃，SDK 原始报文日志抑制；健康只保存稳定错误码，不提供远端 stderr 查看接口。
- API 沿用本地受控部署边界，本模块没有增加公网认证或跨用户 RBAC。
