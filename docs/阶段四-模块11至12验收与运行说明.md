## 1. 安装与迁移

在项目根目录执行；Windows 使用 `.venv\Scripts\` 下对应命令。Docker 装在 D 盘不改变 Compose 文件中的容器路径。本机 CLI 为 `D:\Docker\Docker\resources\bin\docker.exe`。

```powershell
.venv\Scripts\python.exe -m pip install -e ".[dev]"
docker compose up -d postgres redis
.venv\Scripts\alembic.exe upgrade head
.venv\Scripts\alembic.exe check
```

## 2. Worker 与配置

```powershell
$env:EVOAGENT_REDIS_URL='redis://127.0.0.1:6379/0'
$env:EVOAGENT_REDIS_NAMESPACE='evoagent-development'
$env:EVOAGENT_WORKER_CONCURRENCY='2'
.venv\Scripts\evoagent-worker.exe
```

再开一个终端运行同一命令即可启动第二个真实进程，标签可以相同。另一个终端运行 `evoagent-maintenance-worker`，处理 archive、erase、index_source、index_rebuild。普通 Worker 已不再串行捎带维护任务。API、普通 Worker、Eval Worker、维护 Worker 应使用同一个数据库和 Artifact 根目录。

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| WORKER_CONCURRENCY | 1 | 单进程最大活动 Run |
| WORKER_POLL_SECONDS | 1 | 无通知时的数据库扫描周期 |
| REDIS_URL | 未设置 | 显式启用共享请求配额和唤醒 |
| REDIS_NAMESPACE | evoagent-local | 环境隔离；不能仅依赖 Redis DB 编号 |
| SERVICE_CONCURRENCY | 4 | 每进程、每服务同时调用上限 |
| SERVICE_REQUESTS_PER_SECOND | 2 | Redis token bucket 补充速度 |
| SERVICE_BURST | 4 | 最大突发请求数 |
| RATE_WAIT_SECONDS | 2 | 单次配额等待预算 |

变量统一加 `EVOAGENT_` 前缀。删除 REDIS_URL 或设为空字符串可运行无 Redis 模式；这表示不启用跨进程请求限额。配置了 Redis 而它断线时，任务仍可通过 DB 被发现，但模型/MCP/Embedding 请求不会无限放行。限流产生的 RETRYING 与网络重试次数分开，超过 retry_max_elapsed_seconds 后终止。

Compose 可执行 `docker compose up --build --scale worker=2`。Worker 的 Linux SIGTERM 停止新领取，当前 Run 仍有心跳，Compose 给出 310 秒退出宽限。强制 kill/Windows TerminateProcess 使用租约接管路径，不能当作优雅退出测试。

## 3. Runtime 实验

固定数据集在 `evals/datasets/phase4-runtime-v1.json`，包含长历史、记忆、检索三个家族，每个家族四个正常/边界/失败/恶意样本。文件中的公开输入与 private_validators 分开；风险标注用于报告，不发送给模型。

在专用验收数据库上迁移后执行：

```powershell
.venv\Scripts\python.exe -m evoagent.evals.runtime_cli `
  evals/datasets/phase4-runtime-v1.json `
  --variable context_policy --repeats 1 `
  --output output/runtime-context-mock.json
```

可选变量为 context_policy、memory_mode、retrieval_backend、worker_count。CLI 默认每 Case 重复 3 次；演示使用 1 次会产生 24 个 Run。worker_count 对照为 1/2 个真实进程，每进程并发固定 1；其他变量两臂都使用单进程。运行时实验有专用领取过滤，日常 Worker 不会抢走它们。

memory_mode 两臂拥有独立但内容相同的固定记忆，区别只有是否读取。retrieval_backend 两臂都允许读取记忆，区别只有 lexical/hybrid。检索索引由维护 Worker 处理；未就绪会报告 index_not_ready，不能把该报告当作真实向量效果对比。真实 Embedding 必须使用独立配置及索引，Mock 特征哈希不具备同义语义能力。

API 接口：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | /api/v1/runtime-experiments | dataset_id + spec 创建 PAUSED 实验任务 |
| POST | /api/v1/runtime-experiments/{id}/release/{arm} | 放行 control 或 treatment |
| POST | /api/v1/runtime-experiments/{id}/collect | 幂等收集终态，未完成返回 pending |

API 创建不负责自动启动 Worker。使用 API 调度时，专用进程设置 WORKER_RUNTIME_EXPERIMENT_ID、WORKER_RUNTIME_ARM；需要自动启动进程和导出文件时使用 CLI。超时保留数据库中的实验、Task、Run 和 Trace，便于定位，不静默丢弃样本。

## 4. 报告怎么读

`report_kind` 区分 mock/real；spec_hash 绑定数据集 hash、变量、模型和环境。samples 保留每个失败样本、验证结果、RunConfig 和用量；summary 提供已知样本数、均值、中位数；pairs 提供实际配置可比性。

主模型 usage 为 null 时，不把它计作零。known_main_tokens 保存已知调用的小计；摘要器为本地 extractive-v1，实验记忆生成关闭，因此这两项为零调用；Embedding 从检索事件单列。context estimate 是估算，不是账单。报告是描述性结果，不自动声称统计显著或质量提升。

已保存的 Mock 报告见 [context 对照](reports/phase4-runtime-context-mock.json)、[1/2 进程对照](reports/phase4-runtime-workers-mock.json)和[词法/混合检索](reports/phase4-runtime-retrieval-mock.json)。确定性演示 Provider 只会搜索、写报告和给固定答案，因此质量约束失败属于保留的有效负面证据，不是要通过修改 Validator 隐藏的失败。

### DeepSeek 真实小样本

[真实记忆报告](reports/phase4-runtime-memory-deepseek.json)使用 phase4-real-memory-smoke-v1，6 Case × 2 臂 × 1 repeat，均为 deepseek-flash、thinking=disabled，输出上限 128、最多 2 轮。6 对实际配置全部可比；control 与 read_only 两臂均 5/6 通过，模型总用量 **16,616 Token**。有效预算记忆已召回但模型仍回答“无法确认”，这是报告保留的失败，不能宣称质量改善。

最初真实运行暴露了 MetricsCollector 只读 Turn 表的缺口：直接回答没有工具 Turn，却已有 model.completed usage。修复为优先读取模型完成/失败事件，兼容旧 Turn fixture，并新增回归测试后，重新运行得到上述报告。首次运行的数据库记录仍保留，用量 16,617 Token；最小连通探针 10 Token。这三批调用合计 **33,243 Token**，报告中的 16,616 仅指最终记忆样本，不包含排障重跑。

[真实上下文报告](reports/phase4-runtime-context-deepseek.json)另有 2 对、4 个运行：legacy 两个样本通过，bounded 两个样本在 4096 Token 的配置预算下以 context_budget_exceeded 拒绝，未向模型发送请求。实际两个完成请求用量 **5,944 Token**。这份报告证明预算边界与失败保留，不证明压缩质量改善；它与完整 32K 环境不能混在一起比较。加上该批，本轮已知真实模型用量共 **39,187 Token**。这里记录 Token，不按未知账单价格推算费用。

当前官方模型列表及本次 GET /models 均返回 deepseek-flash、deepseek-v4-pro。项目选择 Flash，并使用显式非思考模式，以适配不保存 reasoning_content 的消息契约；不会假装支持思考模式下的多轮工具调用。配置说明参考 [DeepSeek 模型文档](https://api-docs.deepseek.com/quick_start/pricing/)与[思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。provider_thinking_mode 进入 RunConfig/Spec 哈希；默认 None 不改变旧快照哈希。

密钥仅在本地 Git 忽略的 .env.deepseek 中；该文件也被 Docker build context 排除。常规 pytest 和默认 .env 不加载此文件，因此不会意外消费真实 API。需要手动复现时，通过 python-dotenv 加载该文件，再运行 Runtime CLI 并使用上述小样本与预算参数；不要把密钥直接写在命令参数或报告里。

## 6. 故障矩阵与后续边界

| 现象 | 应检查 | 行为 |
| --- | --- | --- |
| 队列延迟但 Redis 正常 | namespace、订阅、poll 周期 | DB 扫描最终领取 |
| rate_limited | Redis 可达性、服务配额、等待预算 | 有限重试，不自动关闭配额 |
| 任务接管后旧结果丢失 | owner、epoch、expiry | 旧进程不得提交 |
| 维护任务不再执行 | attempts、error_code、next_attempt_at | 三次后保留 failed |
| 实验一直 pending | 专用 Worker 过滤、Task 终态 | 不生成缺样本的完整报告 |
| hybrid 与 lexical 相同 | embedding_model、索引、degraded | 先区分降级与语义效果 |
| comparable_pairs 不足 | 两臂实际 RunConfig | 保留差异，不放宽 Skill 比较 |

MCP 漂移/卸载/UNKNOWN、租约接管、执行容器限制对应已有 `test_mcp_execution.py`、`test_lease_fencing.py`、`test_unknown_effect_recovery.py`、`test_docker_sandbox.py`。这些是故障注入证据，与自然语言质量数据集分开。

真实模型和真实 Embedding 质量报告需要模型身份、成本预算和稳定资源环境。DeepSeek 小样本已补齐；默认运行仍为 mock，真实 Embedding 语义对照、完整 Skill 效果门禁仍待补。模块 13 前端、模块 14 最终交付不在本次范围。
