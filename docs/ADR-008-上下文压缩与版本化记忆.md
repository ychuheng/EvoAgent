# ADR-008：上下文压缩与版本化记忆

状态：已采用。日期：2026-09-19。对应阶段四模块 3、4、5。

## 背景

模块 2 能在发送请求前控制窗口，却不能让不断增长的工具历史继续运行。截断工具输出会丢失原文，会话表也尚未形成可引用、有顺序的对话历史。直接把模型摘要当作事实，会同时破坏恢复一致性和记忆可信度。

## 决策

1. 默认上下文摘要采用 `extractive-v1`，不做生成式改写。只替换旧完整工具组；system、用户原始目标与约束、最近两组保留。80% 输入预算触发，候选必须低于 60% 且确实变短。完整被压缩上下文先脱敏归档，摘要中的摘录带来源索引与组哈希。辅助模型调用和成本均为零，避免压缩过程递归调用自身。
2. 摘要作为低可信 user 消息。`completed_steps`、`pending_steps` 留空，不从摘录推断执行状态；ToolEffect 和 Approval 仍是执行事实。摘要不写进长期记忆。
3. 文件先排他写入，随后在 LeaseGuard 保护的同一事务内写 ArtifactRecord、ContextRevision、事件和 v2 Snapshot。失败可能留下未登记文件，不能留下“新摘要＋旧快照”。未登记文件没有可读取的 Artifact ID。
4. RunConfigSnapshot 未显式声明版本仍为 v1，canonical hash 不新增默认字段。新持久化运行使用 v2；没有实现活动 v1 到 v2 的隐式转换。旧终态 Trace 仍可查询。
5. Workspace 是逻辑归属，不是文件系统路径。默认本地 Workspace 由迁移和测试建表分别初始化；记忆 scope 从 Session 解析，不接受模型指定任意 workspace_id。
6. Session 内通过数据库原子 UPDATE 分配消息序号。任务 goal 与 Task/Run 同事务创建，`history_before_sequence` 等于自身 goal 序号，历史读取使用严格小于。终态投影有 `(run_id,kind)` 唯一键；序号可以有空洞，不允许重复。
7. MemoryEntry 表示同一事实身份，Version 表示不可原地修改的内容，Source 表示可复验的证据，Event 只保留审计元数据。当前版本使用复合外键绑定同一 Entry；确认使用 entry lock_version 做 CAS。
8. 默认从明确的“请记住”等用户长期意图提取原话；可选 Model 提取器也只能返回原话候选。它没有工具，最多一次调用、3 条候选、8000 字符输入/输出、1000 输出 Token、10000 本地估算总预算和 10 秒期限。估算不是服务商真实计费上限证明。
9. 来源暂限定为已完成、非评测任务的用户 goal 消息。全部 EvalRun（包括 TRAIN/HOLDOUT）均排除；这比只拒绝 HOLDOUT 更保守。助手自述、旧 backfill 和 Artifact 中的未经验证事实不能成为来源。
10. 归档与 erase 使用持久化 Job；固定范围、来源哈希、配置及去重键。claim 增加 epoch，提交校验 owner/epoch/expiry；failed 通过显式 POST 重试，GET 不触发维护。
11. revoke 立即停止后续查询与已绑定 Run 的新请求。erase 先撤销，随后清除版本正文及受影响派生内容，保留哈希与墓碑。已经发给外部 Provider 的请求无法撤回；原始用户对话、远端系统、数据库备份/WAL/旧文件备份有独立保留策略，不宣称物理介质安全擦除。

## 影响与边界

摘录摘要比生成式摘要保守，可能无法达到压缩目标。此时记录降级事件，并由原有预算策略判断原上下文是否还能发送，不能强行删除原始约束。

运行时自动检索与记忆注入留给模块 7；本次 `bind_version()` 和发送前检查提供其持久引用基础。词法查询只是大小写无关的词项包含匹配，不宣称 BM25、语义召回或向量搜索。

文件先写策略可能产生孤儿文件。孤儿未登记、不可通过 artifact_read 访问；本次不自动扫描删除存储目录，运维清理必须核对数据库引用、运行状态和保留期。

当前 API 沿用本地可信管理面的授权边界，不包含认证、RBAC 或多租户访问控制。PostgreSQL 并发与真实模型质量仍需独立验收。
