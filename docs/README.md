## 3. 阅读与维护约定

1. **先看现状，再看历史。** “当前状态”和“当前计划”是唯一权威来源；阶段指南、模块验收说明和带日期的评测报告描述的是当次交付时间点。
2. **历史材料不改写。** 原文件连同原始结论和日期整体归档；发现与现行不符时，在[当前状态](当前状态.md)中说明差异，不改写历史报告。
3. **数字只写一处。** 新的测试数字写进当次报告和[开发进度与决策记录](开发进度与决策记录.md)；本页与操作手册不重复抄写历史回归数字。
4. **规划不等于实现。** 计划文档中的任务是计划状态；只有[当前状态](当前状态.md)中列入“已在真实环境验证”的条目才算已验收。
5. **源码手册按分册维护。** 手册已按阶段拆成四个分册（见 2.4 节），并已对 109 章完成一轮现行代码校对；后续代码变更应同步修订受影响的章节，校对范围与仍需修复的代码缺陷见[源码地图](源码地图.md)第 5 节和[当前状态](当前状态.md)第 3.1 节。
6. **移动文件后跑链接检查。** 在仓库根目录执行 `.\.venv\Scripts\python.exe scripts/check_doc_links.py .`，确认“断链 0 条”；发现断链时脚本会输出文件名与行号。链接总数会随文档增减，不作为验收数字。
7. **文档不参与 Ruff 检查。** `pyproject.toml` 的 `extend-exclude` 含 `docs`：手册里的 ```` ```python ```` 片段是刻意保留缩进的讲解示例，`ruff format --check` 会把它们当成待格式化代码而失败（整理前该失败已经存在）。文档的机械校验只由第 6 条的链接检查负责。
