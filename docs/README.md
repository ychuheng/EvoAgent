## 文档维护约定

1. 当前行为只以代码和[当前状态](当前状态.md)为准。计划条目是目标，历史验收数字属于它记录的提交与环境。新证据须说明模型/Mock、项目、运行模式、样本和限制。
2. 操作步骤各有归属：公共任务流程在用户手册；模式特有的端口、路径、部署命令在各自模式手册；错误码排查在故障指南。不要在多个入口复制相互独立的“当前能力表”。
3. 历史材料不为迎合现状而改写结论；若与现在冲突，在当前文档说明时间差。`docs/reports/` 有脚本直接读取的固定文件名，移动前须检查调用方。
4. 移动或改名后在仓库根目录运行 `.\.venv\Scripts\python.exe scripts/check_doc_links.py .`。`scripts/check_state_drift.py` 检查产品改动与状态页基准，但不能替代人工核对。文档正文不参加 Ruff 格式化。
