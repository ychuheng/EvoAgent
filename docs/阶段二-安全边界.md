# 阶段二安全边界

## 已实现

- API 默认只绑定本机回环地址；未实现认证，不应暴露到公网。
- 事件递归脱敏 API Key、Authorization、密码、Secret 和推理内容。
- PermissionPolicy 在所有持久化工具执行前给出 ALLOW、DENY 或 REQUIRE_APPROVAL。
- R2/R3 默认需要审批；运行中审批通过数据库完成，不使用同步 `input()`。
- file_read 和 file_write 解析路径后必须仍位于各自 Workspace/Run Sandbox。
- file_write 使用临时文件和原子替换，覆盖会提升到 R2。
- web_fetch 保留逐跳 URLGuard，拒绝 localhost、私网和非公网地址。
- web_search 密钥使用 SecretStr，结果使用统一 DTO。
- Shell 默认关闭；启用后也只接受 argv，使用 `create_subprocess_exec`，禁止 `shell=True`、管道和命令替换；可执行文件必须在部署者显式配置的 allowlist 中。
- 子进程使用受限工作目录、最小环境、超时和输出上限。
- ToolEffect 使用语义键与数据库唯一约束；COMMITTED 复用结果，UNKNOWN 等待人工确认。
- 容器使用非 root 用户，Workspace 使用命名卷，密钥不写入镜像。

## 尚不等于生产级沙箱

- URLGuard 的 DNS 检查结果尚未与实际连接 IP 强绑定，仍需容器网络出口策略防御 DNS 重绑定。
- Shell allowlist 不能替代 seccomp、只读根文件系统、资源配额和独立执行容器。
- 当前没有认证、RBAC、多租户隔离、审计日志外部归档和公网 TLS。
- 外部服务如果不支持幂等键，系统不能提供通用 exactly-once。
- 人工填写的 `committed:<结果>` 是审计决策，不是对外部系统的密码学证明。

因此阶段二适合本机学习、演示和可靠性实验；不得直接作为面向不可信用户的公网执行平台。
