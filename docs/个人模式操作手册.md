# 个人模式操作手册

> **这份文档是从配置到首条任务的权威操作说明。** 端口、命令和排障步骤以本页为准；带日期的验收记录见[当前状态](当前状态.md)和[开发进度与决策记录](开发进度与决策记录.md)，本页不重复抄写历史回归数字。
>
> 适用版本：`0.4.0.dev0`（`c3` 分支）。本页只描述 Docker 个人模式；会话操作流程见[用户手册](用户手册.md)，Windows 本机命令见[可信本机模式](可信本机模式.md)。
>
> 本手册由原《个人模式启动与诊断》和《网页对话与真实模型运行说明》合并而成；两份原件分别保留原文件名作为历史记录（见第 12 节）。

需要直接登记 Windows 路径并在逐次审批后运行本机命令时，使用[Windows 可信本机模式](可信本机模式.md)。下文的 `/app/projects` 与容器命令只适用于 Docker 个人模式。

## 1. 这个入口是什么

个人模式复用现有 API、Worker、PostgreSQL、Redis 和网页，只把模型配置改为真实 OpenAI-compatible 服务。端口仍仅绑定 `127.0.0.1`。

个人配置样例选择无密钥的 `ddgs` 真实搜索；已有私有配置须自行检查 `EVOAGENT_SEARCH_PROVIDER`。Embedding、记忆、MCP、Shell 仍分别配置，默认关闭。它也不表示个人通用 Agent 已整体完成——当前缺口见[当前状态](当前状态.md)第 3 节。

需要准备：

- Python 3.12 或 3.13、Docker（含 Compose v2）；
- 一个支持 tool calling 的 OpenAI-compatible `/chat/completions` 服务，以及它的 API Key、Base URL、模型名和**该模型实际支持的**上下文窗口。

## 2. 首次配置

在仓库根目录把样例复制为私有配置：

```powershell
Copy-Item .env.personal.example .env.personal
```

然后填写 `.env.personal`：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `EVOAGENT_API_KEY` | 是 | 模型服务密钥 |
| `EVOAGENT_BASE_URL` | 是 | 服务地址，例如 `https://api.deepseek.com` |
| `EVOAGENT_MODEL` | 是 | 模型名 |
| `EVOAGENT_CONTEXT_WINDOW_TOKENS` | 是 | 该模型**文档给出的**上下文窗口，不是猜测值 |
| `EVOAGENT_SEARCH_PROVIDER` | 否 | `ddgs`（个人样例，无需密钥）、`brave`（需 Key）或 `mock`（程序默认，离线）；拼错会被预检拒绝 |
| `EVOAGENT_SEARCH_API_KEY` | 条件 | 选 `brave` 时必填 |
| `EVOAGENT_PROVIDER_THINKING_MODE` | 否 | 仅对需要关闭思考模式的兼容服务设置（样例中含已测试的 DeepSeek 取值）；其他服务不要盲目沿用 |

注意事项：

- `.env.personal` 已被 Git 忽略；**不要**把凭据放进命令行参数、提交到仓库，或使用会打印完整环境的 `docker compose config` 输出。
- 模型、搜索、Embedding 是**三个独立服务**。DeepSeek 的对话密钥不提供 Embedding 接口；把对话接口当向量接口会失败。
- `ddgs` 不用搜索密钥，但仍需联网；其公共后端可能限流、返回空结果或受网络环境影响。已有 `.env.personal` 不会随样例自动更新，需手动选择 `ddgs`。

## 3. 本地检查（不访问远端、不消耗额度）

```powershell
$env:EVOAGENT_PROJECTS_HOST_ROOT = 'D:/work'  # 改成实际要授权的共同父目录
.\.venv\Scripts\python.exe scripts/personal_preflight.py
docker compose -f docker-compose.yml -f deploy/personal/compose.yml config --quiet
```

`personal_preflight.py` 只检查私有文件中的必需字段和 `Settings` 约束，成功时输出模型名与搜索模式，**不输出密钥或 Base URL**。它不证明模型可连通，也不检查 Docker、数据库或 Worker 是否已启动；提示缺字段、非法窗口或 Brave 缺 Key 时，先改私有配置。配置文件可保留在本机供下次启动使用。

## 4. 启动与关闭

个人模式会把一个**显式指定**的宿主目录挂到所有应用容器的 `/app/projects`，供 API 检查项目、Worker 读取和修改同一批文件。启动前必须在当前 PowerShell 会话设置项目共同父目录（只挂载你准备授权的范围）：

```powershell
$env:EVOAGENT_PROJECTS_HOST_ROOT = 'D:/work'
```

这个变量用于 **Compose 路径插值**，不能只写在 `.env.personal` 的 `env_file` 里。启动或重建服务时必须保留相同取值；改变挂载根后，应重新核对已登记的项目。页面登记的是**容器内路径**：例如宿主 `D:/work/my-project` 对应 `/app/projects/my-project`，不能填 Windows 路径。`run_command` 在 Worker 容器中执行，白名单程序也必须是容器内实际存在的程序；它不是直接运行宿主 PowerShell。不要把包含 `.env.personal`、密钥或个人凭据的目录直接授权给 Agent；分析 EvoAgent 仓库时可使用不含私有配置的工作副本。

**命令执行边界**：`run_command` 只在 Linux 容器内运行；启动时必须成功安装 Landlock 项目文件视图与单进程 CPU/内存限制，所有 Linux 项目命令都安装 seccomp，禁止后代 setsid/setpgid/unshare/setns；`allow_network=false` 另阻断非 Unix socket 及 `connect()`。缺少内核能力或过滤库时命令直接失败，不会退回无隔离执行；进程树使用 50ms `/proc` 会话轮询软配额，可短暂超额，不是单命令内核 pids/cgroup 硬上限；需要创建新会话的命令会失败。白名单仍默认空；可识别的离线测试/静态检查可自动执行，其它命令（包括构建、安装和通用解释器）逐次审批，联网另须显式请求。直接的 `git push`、`npm publish` argv 被拒绝；获批通用解释器内的行为不能靠 argv 分类完全识别，尤其是批准 `allow_network=true` 后。镜像已内置 Python/pytest、Node/npm、Git 与 ripgrep。当前不是 Windows 宿主命令。详见[安全边界说明](安全边界说明.md)。

启动（`-p` 指定独立的 Compose 项目名，避免与验收环境互相影响）：

```powershell
docker compose -p evoagent-personal -f docker-compose.yml -f deploy/personal/compose.yml up -d --build --wait
```

打开 `http://127.0.0.1:8000/ui/`。

这个覆盖层会把同一份 `.env.personal` 注入 API、普通 Worker、维护 Worker 和评测 Worker，并把 `EVOAGENT_PROVIDER` 固定为 `openai_compatible`。四个应用容器也共享同一个 `/app/projects` 宿主挂载；API 与 Worker 因此看到相同的授权项目内容。两侧模型配置不一致时任务会以 `provider_configuration_mismatch` 失败，而不是被 Mock Worker 静默执行。

关闭时使用**相同项目名和两个 Compose 文件**执行 `down`，不要附加 `-v`，以保留会话、任务与 Workspace：

```powershell
docker compose -p evoagent-personal -f docker-compose.yml -f deploy/personal/compose.yml down
```

默认占用本机 8000、5432、6379 端口。若这些端口已被占用，请使用单独的端口覆盖层并保持本机环回绑定，**不要**直接修改已有验收环境或业务库。

## 5. 第一条任务怎么发

1. 首页显示当前模型和搜索模式；先发一条普通对话，确认收到的是真实模型回复而不是 Mock 演示。
2. 再发一条明确要求使用工具的任务，例如“用 calculator 计算 137×29，并写出结果”。
3. 打开“查看执行过程”，核对模型、工具调用与结果、最终状态和答复。
4. 刷新页面，确认会话、任务与回复仍在。

要点：

- `/health/ready` 只证明 API 能查询数据库；模型远端连通性与 API/Worker 一致性以**实际 Task**为准。
- 任务长时间处于队列时，先用 `docker compose -p evoagent-personal ... ps` 检查 Worker 是否在运行；任务失败时在执行过程和 Trace 中查看错误码。
- 页面通过 SSE 展示已提交的步骤事件，断线后用游标续传，并以状态轮询兜底；**不提供逐字流式输出**。
- 前一任务运行时仍可用“排队下一任务”发送后续目标；同一会话依序执行，后项开始时可看到前项终态答复。运行中补充约束仍发送给当前执行的任务。

### 5.1 显式验收条件（可选）

对可以客观核对的任务，可以在输入框展开“设置可核对的验收条件”，填写：回答必须包含的文本、必须成功调用的工具、必须生成的文件（可带 SHA-256）。API 同样支持：

```json
{
  "session_id": "<现有 Session UUID>",
  "goal": "搜索资料并生成 report.md，回答中写出结论 391",
  "acceptance": {
    "answer_contains": ["391"],
    "required_tools": ["web_search", "file_write"],
    "required_files": [{"path": "report.md"}]
  }
}
```

语义与边界：

- 条件不会自动注入模型提示，用户应在任务文字中说明要求；条件只承担**独立核对**。
- 不满足时任务以 `acceptance_failed` 失败，Trace 保留模型原答；文件读取或条件解析失败记 `acceptance_check_error`，不当作通过。
- 条件通过只证明**这些显式条件**，不证明回答其余内容正确、资料真实或开放式目标已达成；未填写条件时页面明确提示“未独立核验”。
- 无条件完成任务时，`completed` 只表示模型给出了回答。

完整契约见[运行模式与任务验收条件](Agent运行模式与任务验收条件-2026-09-26.md)。

## 6. 现在可以用哪些能力

内置工具（都由 ToolExecutor 统一校验参数、风险、超时与结果长度）：

| 工具 | 作用与边界 |
| --- | --- |
| `calculator` | 受限算术表达式计算，不使用 `eval` |
| `file_read` | 只读 Workspace 内大小受限的 UTF-8 普通文件 |
| `file_write` | 原子写入当前 Run 的受控目录，覆盖需要审批 |
| `artifact_write` / `artifact_read` | 只创建当前 Run 的新 Artifact（不覆盖同名文件）并读回 |
| `web_fetch` | 只读公开 HTTP/HTTPS 文本，校验每一跳重定向，拒绝私网与元数据地址 |
| `web_search` | 通过可替换的 SearchProvider 搜索；程序默认 Mock，个人样例用无密钥 `ddgs`，也可配置 Brave |
| `ask_user` | 通过数据库审批流暂停任务并取得用户答复 |
| `shell` | 独立容器沙箱的可选工具，默认关闭；与项目内的 `run_command` 不是一条执行路径 |
| `list_dir` / `find_files` / `search_text` / 项目 `file_read` | 在已登记项目中发现目录、按路径/内容查找及分段读取；只读授权可用 |
| `edit_file` / `apply_patch` / `delete_file` / `move_file` | 精确编辑与项目内文件操作，需 `read_write` 授权；审批与冲突检查按工具风险执行 |
| `run_command` | 有白名单且项目可写时，在 Linux Worker 内运行项目命令；离线检查与需审批的构建/安装分档 |
| `extract_text` / `organize_files` | 抽取明确编码的文本或文本型 PDF；先预览再整理目录，扫描 PDF 不支持 |
| 已审核的 MCP 工具 | 需先在页面审核目录并显式激活执行；卸载后新任务不再获得 |

运行模式：普通任务可选择 `baseline` 或默认的 `retrieval`（检索 Skill）。`pinned_skill` 不向普通任务 API 开放，只用于内部 EvalCoordinator 的配对评测。

对话与上下文：同一 Session 的后续提问按任务创建时冻结的历史截止点注入模型，不同 Session 互不读取；Runtime Eval 使用自己的固定样本历史，不会回退读取普通会话。Skill 候选提炼入口为 `/api/v1/skills/extractions`；配置 `EVOAGENT_SKILL_EXTRACTOR_MODEL` 时使用真实模型，否则应用不会假装已完成模型提炼。

页面已有 SSE 步骤展示、文件输入和产物预览/下载；它展示的是**已提交事件**，不是模型逐字流。跨浏览器断线、Worker 强杀和取消晚到结果的联合验收仍待完成，见[当前状态](当前状态.md)第 3 节。

## 7. 模式与状态怎么判断

| 页面提示 | 含义 | 不能推断 |
| --- | --- | --- |
| Mock 演示 | 当前是默认的确定性演示配置 | 不代表已经接入真实 AI |
| 真实模型已配置 | API 侧配置有效、模型名已加载 | 不代表远端可连通，也不代表 Worker 一致 |
| 任务成功且显示验收状态 | 该次运行终止且指定条件已核对 | 不代表开放任务的回答正确 |
| `Worker 在线` | API 最近从 Redis 读到 Worker 的带过期时间存活标记 | 不是远端模型探针，也不保证本任务能成功 |
| `未检测到在线 Worker` | Redis 可读但没有有效标记 | 不代表数据库或模型故障 |
| `Worker 状态无法判断` | 未配置 Redis 或暂时无法查询 | 不代表 Worker 已停止 |

任务排队超过 30 秒时页面另给 Worker 检查提示；这个提示只表示任务尚未被领取。

## 8. 错误码排障

| 页面或 Trace 错误码 | 先核对什么 |
| --- | --- |
| `provider_auth_error` | 模型服务的 Key、账户权限和 Base URL；错误信息不会显示远端响应正文 |
| `provider_rate_limit` / `provider_server_error` | 服务额度、限流或服务端状态；查看任务的重试记录 |
| `provider_network_error` / `provider_timeout` | 容器到模型服务的网络、代理与超时配置 |
| `provider_configuration_mismatch` | API 与 Worker 是否读取同一份 `.env.personal`，修改后是否都已重启 |
| `context_budget_exceeded` | 输入是否超出冻结的上下文窗口；该错误在发起模型请求前出现 |
| `acceptance_failed` | 显式验收条件是否满足；Trace 的 `acceptance.checked` 逐项记录结果 |
| `acceptance_check_error` | 文件读取或条件解析是否失败；这不是通过 |
| `acceptance_evidence_missing` | 有条件但缺少 `passed=true` 的验收事件；属拒绝成功 |
| `search_auth_failed` / `search_forbidden` | Brave 搜索 Key 与访问权限；只在 Brave 模式下出现 |
| `search_rate_limited` / `search_service_unavailable` | 搜索服务额度与状态；当前适配器不会自动退避重试 |
| `search_timeout` / `search_network_error` / `search_invalid_response` | 搜索网络或返回格式；不能把失败结果当成来源 |

### 8.1 搜索与来源的三个易错点

1. 搜索工具返回 `[]` 表示该次查询没有结果，应更换查询或说明资料不足；它**不是**已核对的引用。
2. 工具成功不等于网页正文已经读取。执行详情中的“网页来源证据”会列出搜索查询、提供方、结果 URL，以及已读取页面的最终 URL、访问时间和原始字节 SHA-256。
3. 答复中的 HTTP(S) 链接被标为“已读取正文”“仅见搜索摘要”或“未见检索或读取记录”。这只核对链接与工具记录的对应关系；即使标为“已读取正文”，仍要人工核对该网页是否真的支持相关结论。

### 8.2 审批、取消与未知副作用

- 需要人工确认时，任务详情显示风险、原因和工具参数，由用户明确批准或拒绝。
- 不确定副作用（UNKNOWN）必须**先核对外部状态**，再按原协议提供 `retry` 或 `committed:<结果>`；裸“拒绝”无法说明外部动作是否已发生，API 会拒绝该操作，页面也不再提供该按钮。
- 取消运行中的任务只是提出请求，Worker 收尾后才进入终态；取消任务不等于撤销已经发生的外部操作。
- 已失败且无法安全重放的工具检查点，不允许在原任务盲目 `retry`；核对确认未提交后应取消并新建任务。

## 9. 可选能力（默认关闭，按需启用）

| 能力 | 启用方式 | 说明 |
| --- | --- | --- |
| 真实公开搜索 | `EVOAGENT_SEARCH_PROVIDER=ddgs`（无密钥）或 `brave` + `EVOAGENT_SEARCH_API_KEY` | `ddgs` 单独联网试搜已取得 URL，真实模型多来源任务仍待验收，见[当前状态](当前状态.md)第 3 节 |
| 混合检索 | `EVOAGENT_RETRIEVAL_BACKEND=hybrid` | 默认仍是词法 Skill 检索 |
| 记忆注入 | `EVOAGENT_MEMORY_RETRIEVAL_ENABLED=true` | 记忆需先在页面确认；作用域为 Session 或 Workspace，撤销后新任务不再使用 |
| 本地语义检索 | 叠加 `deploy/acceptance/compose.embedding.yml` | 独立 ONNX 服务，模型 `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`，原生 384 维；首次启动会下载模型到独立卷 |
| 受信 MCP fixture / 记忆覆盖层 | 叠加 `deploy/acceptance/compose.mcp-fixture.yml`、`compose.memory.yml` | 用于本机验收；MCP 需在页面审核目录并显式激活，卸载后新任务不再获得该工具 |
| Shell 与独立容器 | `deploy/sandbox/compose.yml` | Shell 默认关闭，无宿主 fallback；容器固定禁网 |

这些覆盖层面向**本机受控验收**。使用前请确认当前 Compose 项目名指向你自己的数据库和卷，不要对日常数据执行清理。

## 10. 数据、凭据与边界

- 会话、消息、任务、Trace 存在 PostgreSQL 卷中；Workspace 与 Artifact 在独立卷中。正常 `down` 不会删除它们。
- 页面不保存也不显示 API Key。真实调用会消耗你自己的 API 额度。
- 本机语义服务占用 CPU/内存，未计量 Token 成本。
- 本部署是本机可信界面，**没有账户认证**：不要当作访问控制使用，也不要直接暴露到公网。真正的记忆召回隔离由服务端按 Session 的 Workspace 身份执行。
- 网页、搜索结果、文件和 MCP 返回内容一律按不可信资料处理；其中的指令无权取消审批、扩大文件范围或改变副作用语义。

## 11. 已验证与待验证

## 13. 从任务经验到 Skill 复用

以下流程对应 c3 的新个人学习入口。功能开关与费用审批是不同条件；没有批准额度时保留候选审查或离线契约验证，不能把 Mock 报告当作真实有效性验证。

### 13.1 启用学习入口

`.env.personal.example` 新增三个独立开关：

- `EVOAGENT_LEARNING_ENABLED`：后台候选提炼及学习请求。
- `EVOAGENT_PERSONAL_VALIDATION_REAL_ENABLED`：注册宿主当前模型的真实验证配置；预检同时要求 learning_enabled、全局/Task 数字预算和已知价格。
- `EVOAGENT_PERSONAL_TRIAL_ENABLED`：开放限定试用控制，仍须满足真实独立验证、来源有效性与健康门禁。

默认均为 false。实际启用后，对 API、普通 Worker、维护 Worker、评测 Worker 保持同一私有配置；按第 4 节重建所选个人部署，不修改其它部署。维护 Worker 处理候选与安全观察；评测 Worker 派生隔离验证任务，普通 Worker 执行它们。所有路径仍使用 PostgreSQL、租约、epoch fencing 和恢复。

预检只在本机计算冻结配置，不联系模型、不确认模型能用、不确认工作区费用已批准。页面“学习”先选择工作区，保存模式和独立的日费用/单请求额度；没有数字学习额度不能发送真实提炼/验证。manual 只接受显式请求；suggest 允许受限发现已成功且有持久验收证据的任务。关闭学习不会关闭已启用试用的安全挂起。

### 13.2 提炼与审查

完成个人任务后，在任务上显式选择“记成方法”，或反馈“方法需要纠正”并明确勾选从反馈学习。单纯点赞、未知意图、事实纠正与未授权反馈不自动提炼。学习页显示持久请求、来源状态、已知与未知费用、候选版本和静态审查报告。只生成草稿不会改变正式版本或让普通任务采用它。

同版本、三个不同输入的同类明确归因失败会在使用证据中提示修订；提示不自动收费。请回到参考任务，说明如何纠正并明确授权学习。新修订绑定原 Skill/base_version；过时候选不覆盖较新的版本。

### 13.3 独立验证与限定试用

候选页面先冻结不同输入的正例和反例、任务类型、明确业务判据及来源审查。相同输入只改标题不会成为独立案例；completed 或工具没有报错不等于业务正确。资料任务必须有人工核对事实支持的业务判据。

默认选择 offline-mock-v1，只验证工程合同且永远不能获得真实试用资格。只有宿主注册和工作区额度均满足时才出现 host-real-v1；选择后会显示该验证消耗批准额度。**冻结输入不会启动任务**；再次显式点击开始才入队。模型、接口、限制或价格改变时旧配置不能被悄悄替换，需要重新冻结验证身份。

文件输入只能选择登记的公共 fixture，各对照臂/每次重复使用不同私有目录。项目候选保留原项目 scope，但不挂载或复制原用户项目；不要把这一机制当成真实仓库副本评测。普通任务仍在其自身授权项目内执行。

机械判据自动评估；人工判据要逐项明确判断并绑定可核对证据。报告分别显示目标版本、实际是否采用、正例应采用/反例应排除、业务结论与真实费用完整性。满足所有门禁后才可检查就绪并由你确认限定试用。它仅影响相同工作区/项目的后续适用任务，正式 active_version 指针不会移动。

### 13.4 查看效果与回退

在“限定试用管理”显式选择项目范围，加载试用记录。查看使用证据可看到近 30 天被选择次数、最新反馈结论、未投影数量和分页历史。观察目前覆盖限定试用；被选择只表示上下文装配，不能证明步骤被执行或技能改善了结果。token 只统计已结算账本；耗时均值只含完整样本，不与因果效果混同。

任务反馈的技能判据必须选真实版本/步骤和当前有效产物；普通评价保留 unknown。冻结健康规则对同版本、24 小时内连续三个不同输入的明确技能相关失败自动挂起；安全来源撤销优先阻断。人工挂起或回滚须填写依据，提交当前 lock_version。并发改变返回冲突时刷新重查；不会自动解封或自动重启旧任务。

### 13.5 当前验收边界

真实模型净收益、三类真实业务任务及干净部署验收仍需单独批准额度和实际证据。本轮没有执行付费模型评测。P5 自动修订入队/受控合并仍在推进，优化开关保持默认关闭；当前交付与 exact-SHA CI 证据以[当前状态](当前状态.md)顶部和新批次记录为准。


### 13.6 个人验证依赖的服务

个人 DEV 验证同时依赖普通 Worker 执行任务、Eval Worker 协调/收集实验、学习 Worker 推进请求。使用第 4 节完整 Compose 启动方式；只启动 API 与普通 Worker 能完成日常任务，却可能使验证一直停在等待实验阶段。确认这些进程及数据库/Redis就绪后，再在页面刷新请求；不要为排障重复创建相同付费验证。

2026-10-11 干净容器验收已跑通真实 HTTP 的任务—反馈—候选—离线验证链路，见[部署验收记录](reports/P7干净容器个人学习部署验收-2026-10-11.md)。Mock 验证不能授予试用资格；真实模型的业务有效性仍需数值额度和用户判定。


### 13.7 人工合并与验证后替换

在 Skill 目录选择 2–4 条可用且同范围的方法，点击“读取并冻结所选版本”。展开原方法供参考，人工编辑合并方法 JSON（使用新名称）、填写合并依据后创建候选。编辑起点只复制第一条，不会替你自动整理其他方法。该操作无模型费用、保留旧方法；到个人学习页刷新后审查，并用未用于任一来源的新输入完成独立验证与限定试用。

新方法的同范围 trial 已通过独立验证且健康状态核实时，旧方法详情可执行“用合并方法替换旧方法”。加载有效试用、检查版本、填写依据，再确认弃用。服务器最后复查健康、来源和三个版本；任何变化都会拒绝并保留旧方法。普通静态候选或 Mock 验证不能替换。弃用后旧方法不可直接重新启用；历史版本与来源保留，不属于删除或跨 Skill 一键回滚。

此处的真实配置路径必须先批准数字费用额度；离线开发测试的合成费用与人工判据不代表真实效果。高级 API 请求结构与具体边界见 `docs/reports/P5人工合并与验证后替换-2026-10-11.md`。


### 13.8 查看方法库整理建议

在 Skill 目录选定方法，点击“查看整理建议”。查询范围与所选方法相同：工作区级方法与项目级方法分别整理。最多覆盖排序前 20 条，页面会提示覆盖不完整。来源失效的方法不会被建议合并。

文字相似只提示你比较方法，不能证明两个方法可以合并；有需要再在下方“合并方法候选”人工选择、整理并确认。创建至少 30 天、最近 30 天未被选择的方法仅提示长期未用，不会自动删除或停用。工作区级方法在项目任务中的选择也计入使用。


### 13.9 个人方法与正式发布

个人新输入验证通过后，仍先按限定 trial 的范围与健康门禁复用。若申请正式发布，个人来源使用 GateReport v2：无验收成功证据的 completed 任务仅作辅助，已知失败不能计为成功，文件内容相同的来源不能靠改名或改提示凑独立样本。Mock 结果不能授予个人方法的正式发布资格；还需批准的真实模型实验、至少一次 treatment 成功、全部正确性与安全硬门禁、人工审查。修订/合并的祖先来源仍被检查，旧 v1 报告不能替代个人来源门禁。

来源撤销或隔离后，冻结来源图复查失败，正式选择/发布/回滚会拒绝。已冻结历史报告保留原 hash，不覆盖正文重新伪造一个通过结论。实现证据见 [正式门禁来源合同](reports/正式门禁v2个人来源合同-2026-10-11.md)。

### 13.10 重复问题的自动修订候选

Workspace 的学习策略为 `suggest` 时，后台按同一项目范围、同一 Skill 版本、同一判据和受影响步骤查找重复问题。至少三个不同输入须有明确技能相关失败、最新反馈逐条同意学习，而且经验已经通过此前学习请求冻结。没有来源的历史不会被自动补写；相同文件内容不能通过改名或换提示凑独立输入。

每日候选上限、冷却时间、已有待处理修订和模型数值额度同时约束自动入队。每批最多十条冻结来源；生成中任一来源撤销、反馈撤回、项目授权或目标版本改变都会阻断结果。候选在个人学习页审查，保留全部来源和父版本，不修改 active 指针，不自动授予 trial；仍需新输入验证、审查、限定试用和健康门禁。

只读“修订建议”接口仍不启动学习。只有运行中的学习 Worker、开启的全局学习配置与 `suggest` 策略共同启用自动扫描；`manual` 或 `off` 不进行自动修订。付费生成仍受现有真实费用账本控制，未知费用不自动重发。
