# 前四阶段补完与用户场景验收计划

> 制定日期：2026-09-25。本文是阶段一至四的补完与重新验收清单，不改写各阶段当时的实现记录。实施与验收结果应追加到[开发进度与决策记录](开发进度与决策记录.md)；未取得证据的项目保持待验收。

## 1. 为什么需要补完

前四阶段建立了 Agent Loop、持久化任务、Skill 生命周期、记忆/MCP/多 Worker 等工程能力，但原验收偏重模块、Mock 测试和管理接口。直到 2026-09-25 才补上网页对话入口；真实多轮调用还暴露并修复了普通任务未向模型传入本 Session 历史的问题。这说明“内部功能已实现”不能直接等同于“用户能够完整使用”。

当前网页已能用本地 DeepSeek 配置发送消息、查看终态回复并连续追问；这是基本对话路径的证据，不证明所有工具任务、故障处理、Skill 使用及长期记忆都已从用户入口验收。制定本计划时真实 Embedding 语义实验未完成；后续已完成小样本实验，结果与剩余联合验收缺口见[阶段性报告](前四阶段补完阶段性验收-2026-09-25.md)。版本保持 `0.4.0.dev0`。

后续每项能力分别记录三级状态：**代码/契约已实现**、**可由用户入口操作**、**真实环境端到端验收通过**。单元测试、Mock、浏览器固定响应、真实模型调用和容器故障实验必须分别标注，不能相互替代。

## 3. 共同的用户验收脚本

以全新 Session 开始，提交需要模型选择工具的任务，查看模型决策、工具结果和最终答案；刷新页面，再追问上一轮具体内容。随后运行需审批或较长时间的任务，观察状态、审批、取消和故障恢复。将成功任务作为 Skill 来源，检查评测和发布后在另一普通任务中复用。最后在新 Session 验证已确认记忆的允许召回、跨作用域拒绝和撤销，再使用已审核 MCP 工具并卸载。每一步必须记录实际配置、Run/Task ID、可复现输入、预期和实际结果，凭据与私有正文只保存在本地受控证据中。

用户入口不必把所有内部调试字段暴露到聊天气泡；但用户必须能从任务状态进入相应的 Trace、审批、Skill、Memory 或 MCP 证据，并知道下一步该做什么。默认 `mock` 配置只能称为演示模式；真实智能回答与效果验收需标明真实 Provider 和模型。

## 4. 依赖与完成判定

- 真实 DeepSeek 对话配置已用于本机对话验证；真实调用消耗 API 额度。其对话接口不能充当 Embedding 接口。
- Embedding 优先评估可复现的本地或独立兼容服务。必须确认模型的**原生维度**与检索质量；若不是当前数据库固定的 1536 维，应设计版本化 schema/profile 迁移及重建，不截断/补零伪造 1536 维向量。
- 测试使用独立数据库与卷，保留原始失败 Trace 和既有 `output/` 数据；报告脱敏且不提交密钥。
- 完成一个阶段的补完，仅表示该阶段用户场景通过；四阶段联合验收、真实语义检索和发布门禁全部通过前，不把整个项目标为正式 v0.4 或生产可用。

当前结论：**基本网页对话与部分真实工具/Skill/记忆/MCP 场景已可用；前四阶段的用户场景联合验收仍待完成；正式 v0.4 未放行。** 2026-09-26 的整体核查见[Agent 能力核查](整体Agent能力核查-2026-09-26.md)。
