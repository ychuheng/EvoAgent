# ADR-012：独立执行容器与受控网络出口

- 日期：2026-09-21
- 状态：接受；代码、本地契约及 Docker Desktop Linux Engine 实机验收完成
- 范围：阶段四模块 10；不宣布阶段四完成

## 背景

阶段二的宿主 ShellSandbox 只能限制入口和工作目录。阶段四模块 8/9 的 stdio fixture 是受信测试程序，不能作为第三方程序隔离方案。需要将 Docker 控制权移出模型工具所在 Worker，并把租约、产物提交和容器清理衔接起来。

## 决策

采用单实例 sandbox-controller，API/Worker 仅持有私有接口 token，不持有 Docker socket。controller 属于受信计算基，负责固定 digest 镜像、类型化 Profile、资源参数、创建后 inspect、执行记录和回收。模型请求只允许 argv 与同 Run Artifact ID，不能覆盖镜像、挂载、网络、用户或安全参数。

执行容器固定非 root、只读根、drop ALL、no-new-privileges、默认 seccomp、network=none 和有界 tmpfs；AppArmor 作为可选部署 Profile。CPU、内存、swap、PIDs、输出、文件与时间分别限制。Docker 参数语义参考官方[资源限制](https://docs.docker.com/engine/containers/resource_constraints/)与[容器创建接口](https://docs.docker.com/reference/cli/docker/container/create/)。输出另设流读取上限，Docker 日志关闭，避免后台日志绕过上限；参见[日志驱动配置](https://docs.docker.com/engine/logging/configure/)。

输入复制到 Run/epoch/execution staging，只读挂入容器；输出仅收集有界单层普通文件，controller 二次校验，并在确认容器移除和租约有效后交 ArtifactService 发布。产物命名包含 epoch 和内容 hash。多个文件不是同一原子事务，失败时保留可追踪的部分产物。

执行记录先于创建容器写入。超时、取消、断连与 LeaseLost 都要求停止整个容器并确认移除；无法确认时记录 cleanup_pending。重启扫描数据库与 label，清理遗留执行，不自动重放。ToolEffect UNKNOWN 的判断与处置继续由原效果账本负责，不能根据容器已删除推断业务无副作用。

公开网页工具采用 EgressTransport，每一跳验证全部 DNS 地址并绑定实际连接 IP，同时保留域名 Host/SNI，禁用环境代理与自动地址重试。Provider 秘密通道保持独立。执行容器当前完全禁网；不使用单纯 HTTP_PROXY 约定假装实现网络隔离。

第三方 stdio 进入固定容器 Profile，通过私有认证 WebSocket 转送官方 MCP SDK 的 JSON-RPC。该通道不是 MCP 标准传输扩展；不支持容器 secret_ref、任意网络或无限期会话。原宿主 fixture 必须显式 trusted_fixture，不能用于第三方程序。

## 替代方案与取舍

| 方案 | 取舍 |
|---|---|
| Worker 直接操作 Docker | 权限边界过大，不采用 |
| 宿主进程加超时 | 无内核资源与网络隔离，仅保留受信 fixture |
| 允许容器联网并设置 HTTP_PROXY | 任意代码可直连绕过，不采用 |
| 自建联网出口网关 | 需要独立网络强制路径、DNS/协议治理，当前范围不实现 |
| microVM / 独立宿主 | 可提供不同隔离强度，当前未引入运维栈 |
| 多 controller | 与本地 active/回收所有权冲突，当前只支持单实例 |

## 后果与验收

本地配置默认关闭 Shell；缺少 controller 或 Docker 时拒绝执行，不自动退回宿主。部署需要 Linux Docker、预拉取审查后的 digest 镜像、固定 staging 根以及内部 token。controller 是高权限组件，应与公开入口分离；当前方案不是公网认证或多租户产品。

新增迁移 `20260921_0010` 和 Trace.sandbox_executions。单元及集成测试覆盖请求、审批绑定的兼容路径、租约、文件、实际控制通道和网络请求构造；独立 Docker 测试覆盖真实资源/网络/清理。2026-09-21 已在 Docker Desktop 4.91.0 的 Linux Engine 29.8.0、amd64、默认 seccomp 环境通过 11 项实机测试；固定测试镜像 digest 为 `sha256:dbd3a85d745459abdb13d363899c075b5df14ae82437080c9ca4fcb52f557c34`。该结果证明声明范围内的测试场景，不扩展为敌对多租户或生产高可用承诺。逐项运行步骤见[模块 10 验收说明](阶段四-模块10验收与运行说明.md)。
