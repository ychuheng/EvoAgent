# 阶段四模块 6～7：验收与运行说明

版本 `0.4.0.dev0`；实现日期 2026-09-20。详细讲解见[源码手册第 69～73 章](EvoAgent-源码讲解与学习手册.md)，决策见 [ADR-009](ADR-009-派生向量索引与检索冻结.md)。模块 0～5 的行为和部署前提继续有效。

## 1. 交付范围

| 模块 | 入口 | 已实现行为 |
|---|---|---|
| 6 | EmbeddingProvider | 确定性 Mock、真实 HTTP、数量/模型/维度/有限值/非零校验 |
| 6 | migration 0007 / PGVector | vector(1536)、显式来源外键、Profile/Document/Embedding/Generation |

## 2. 升级数据库

先停止旧 Worker，再升级数据库与应用。旧活动 Run 的配置/快照不自动改写；不兼容时返回 `snapshot_incompatible`，通过新 Task 使用新检索配置。

PostgreSQL 必须具备 vector 扩展。Compose 与 CI 服务使用 `pgvector/pgvector:0.8.1-pg17`；已有普通 PostgreSQL 安装需要先安装对应扩展，创建扩展的账号需要权限。不要删除现有数据卷来绕过升级。

```powershell
# 使用项目已配置的 EVOAGENT_DATABASE_URL
.\.venv\Scripts\alembic upgrade head
.\.venv\Scripts\alembic current
```

最新 revision：`20260920_0007`，依赖 `20260919_0006`。新增六张表和 `maintenance_jobs.next_attempt_at`。downgrade 删除本次表/字段，不删除可能被其他业务使用的 vector 扩展。

容器部署沿用现有 Compose 启动方式：

```powershell

```

## 3. 开启检索

离线功能验证使用以下配置，并在 API 与 Worker 进程中保持一致：

```dotenv
EVOAGENT_SNAPSHOT_SCHEMA_VERSION=2
EVOAGENT_CONTEXT_POLICY=bounded
EVOAGENT_RETRIEVAL_BACKEND=hybrid
EVOAGENT_MEMORY_RETRIEVAL_ENABLED=true
EVOAGENT_ARCHIVE_RETRIEVAL_ENABLED=false
EVOAGENT_EMBEDDING_MODEL=mock-hash-v1
EVOAGENT_MEMORY_RETRIEVAL_TOP_K=3
EVOAGENT_RETRIEVAL_MIN_LEXICAL_SCORE=0.1
EVOAGENT_RETRIEVAL_MAX_VECTOR_DISTANCE=0.35
EVOAGENT_RETRIEVAL_RRF_K=60
EVOAGENT_RETRIEVAL_SKILL_BUDGET=4000
EVOAGENT_RETRIEVAL_MEMORY_BUDGET=2000
```

也可以保持 `lexical`，仅开启 Memory，验证事实注入和冻结而不进行 Query Embedding。仅开启 `hybrid` 不会自动打开 Memory/Archive。完整请求窗口检查依赖默认 bounded 策略；显式选择 legacy 时只保留检索分区预算，不提供 bounded 的完整窗口保证。

真实 Embedding 另设模型与连接信息，例如使用支持 1536 维返回的 `text-embedding-3-small`、对应服务 Base URL 和 `EVOAGENT_EMBEDDING_API_KEY`。真实 HTTP 实现采用 `/embeddings` 的 float 响应协议，必须验证服务返回 model 与配置身份一致；本次没有真实 Key 调用结果。API Key 不进入 Profile、RunConfigSnapshot 或检索证据响应。

模型空间固定 1536 维，不提供 `EMBEDDING_DIMENSION` 参数。更换模型后提交 rebuild，为新 Profile 建立向量。不能拿旧模型向量继续比较，也不能通过改数据库 model 字段“转换”旧空间。

Compose 的环境来自文件中 `app-environment`，不会自动把宿主机所有 `EVOAGENT_*` 变量传入容器。若通过 Compose 启用检索，应在共享 environment 或本地 override 中显式传入上述变量，确保 API/Worker 相同；真实密钥使用本地环境或秘密管理，不提交仓库。

## 4. 验证索引生命周期

按[模块 3～5 说明](阶段四-模块3至5验收与运行说明.md)创建并完成普通 Task，提议并人工确认来源原话中的事实。确认事务会同时创建 `index_source` Job；常规 Worker 轮询维护任务，不需另启一套索引守护进程。

为升级前已有的已发布 Skill/已确认事实/合法归档显式提交重建：

```powershell
$retrievalApi = 'http://127.0.0.1:8000/api/v1'
$rebuildJob = Invoke-RestMethod -Method Post -Uri "$retrievalApi/retrieval/rebuild"
Invoke-RestMethod -Uri "$retrievalApi/maintenance-jobs/$($rebuildJob.job_id)"
Invoke-RestMethod -Uri "$retrievalApi/retrieval/profiles"
```

返回 202 只代表入队。Job `completed`、result.written 和 Profile.active_generation 才说明构建已提交。重复提交同一 Profile 的 pending/running rebuild 会返回现有 Job；成功后再提交会创建新 generation。

当前边界：每来源一个 Document，索引文本取前 12000 字符；每批最多 16 条，单次调用上限 15 秒，重建最多 64 个合法来源。超限失败，不静默截断整套来源。没有 HNSW、并行大规模重建或旧 generation 自动回收。

索引确认/撤销与来源生命周期独立：新事实可先通过 BM25 使用，向量稍后就绪；撤销/禁用立即使旧向量失效，晚返回的模型结果不能恢复它。

## 5. 验证实际选择和恢复

创建新的 retrieval Task，使用与已确认事实相关的目标。若选择成功，Memory/Archive 作为低可信 user 资料进入请求，Skill 保持原规程区。

```powershell
# 用实际 Run UUID 替换占位文本
$retrievalRunId = '<run UUID>'
Invoke-RestMethod -Uri "$retrievalApi/runs/$retrievalRunId/retrieval"
```

应检查：

- selected_count、generation、degraded 与 config 是否符合预期。
- selections 中 source_hash/text_hash、两路 rank/distance/score 是否可解释。
- 未注入候选是否记录 top_k、partition_budget 或 request_budget，且没有正文。
- 零命中也存在 Batch，恢复不会因新确认或新发布自动变成命中。

GET 只读取现有证据，不生成向量、不创建 Job、不返回冻结正文。默认旧词法 Skill 路径没有新 Batch，继续使用原 Skill 选择记录；不能将这类 Run 的“没有 Batch”误读成新链路故障。

冻结初始选择不等于每轮永远发送相同消息数量。后续请求增长仍由 ContextPolicy 管理，具体发送内容看各轮快照/Trace；来源撤销或归档擦除则阻止后续发送。

## 6. 故障与恢复操作

| 情况 | 持久化证据 | 操作 |
|---|---|---|
| Embedding 无法连接/响应不完整 | index Job failed、error_code | 修复连接后显式 retry |
| 尚无 Profile/索引文档 | Batch degraded=index_not_ready | 启动 Worker 或 rebuild；当前允许词法降级 |
| Query Embedding/向量查询故障 | degraded=vector_unavailable | 修复后新 Task 可重新选择；旧 Batch 保持冻结 |
| 仅部分来源有向量 | degraded=partial_index | 排查增量 Job，必要时 rebuild |
| 构建来源 manifest 变化 | rebuild_manifest_changed / rebuild_sources_changed | 提交新的 rebuild；旧 manifest 不改写 |
| 增量过程中活动代切换 | index_generation_changed | retry 重新读取当前 generation |
| 旧重建代已落后 | index_generation_obsolete | 使用当前索引；需要时新建 rebuild |
| 租约丢失 | index_lease_lost | 等待合法 Worker 接管，旧 Worker 不可完成 |
| 来源撤销/损坏 | context_source_revoked / hash mismatch | 不放宽过滤，不自动替换旧选择 |
| 新配置与旧冻结配置不同 | snapshot_incompatible | 使用新 Task，保留旧证据 |

显式重试：

```powershell
Invoke-RestMethod -Method Post -Uri "$retrievalApi/maintenance-jobs/$($rebuildJob.job_id)/retry"
```

只有 failed 可重试。`next_attempt_at` 为失败后建议时间，当前没有 failed 自动重试扫描；手动 retry 清空该时间并立即重新排队。业务运行与辅助索引用量没有在本模块合并成效果实验报告。

## 7. 擦除验证

erase 仍先撤销，再由维护 Job 物理清理。新版本索引立即失效；维护任务进一步清理覆盖来源的 Archive，以及使用这些 Archive 的后续 Run 的冻结文本、快照和其他派生正文。清理通过引用闭包扩展，不只检查直接 Memory 引用。

检查 erase Job completed、版本 content 为空、Archive erased、相关 Document inactive、Selection.text 为空。保留 hash/状态/关联 ID，恢复旧 Run 会被来源检查拒绝。用户原始消息、远端服务与备份不属于这项擦除范围。
