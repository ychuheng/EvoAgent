# EvoAgent 用户手册

> **适用版本**：`0.4.0.dev0`（`c2` 分支）。**发布状态：候选版，`v0.4` 未放行**——
> 发布级四层检查里"真实模型任务"与"人工审查"两层还没拿到证据，理由见
> [M7 发布准备与分层检查](evaluations/M7发布准备与分层检查-2026-09-27.md)。
>
> 本页是**发布级**手册：从零装起来、发第一条任务、升级、备份恢复、卸载与数据保留。
> 私有配置、错误码逐条排障等细节以[个人模式操作手册](个人模式操作手册.md)为准；
> "现在哪些能力真的可用"以[当前状态](当前状态.md)为准；本页不重复抄写历史回归数字。

## 1. 这个程序是什么

一个**单人本地**通用 Agent：网页对话里给它一个任务，它在**你登记过的项目目录**内读代码、
改文件、跑命令、处理文件、做公开调研，并把每一步记进可回看的 Trace。默认只绑定
`127.0.0.1`，没有公网多租户、认证/RBAC、多 Agent 编排与定时任务。

允许与禁止的边界写在[安全边界说明](安全边界说明.md)，动手前请先读那份。

## 2. 从零跑起来（Mock 模式，不联网、不花钱）

准备：Python 3.12/3.13、Docker（含 Compose v2）、PowerShell（Windows）。

```powershell
# 1) 依赖与虚拟环境
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e .

# 2) 数据库与队列（只起 Postgres/Redis，端口仅绑本机）
docker compose up -d postgres redis

# 3) 建表（迁移到 head）
.\.venv\Scripts\alembic.exe upgrade head

# 4) 起 API 与 Worker（两个窗口）
.\.venv\Scripts\evoagent-api.exe
.\.venv\Scripts\evoagent-worker.exe
```

浏览器打开 `http://127.0.0.1:8000/ui/`。自检：

| 检查 | 期望 |
| --- | --- |
| `http://127.0.0.1:8000/health/ready` | `200`，数据库与迁移就绪 |
| `http://127.0.0.1:8000/api/v1/runtime-info` | 返回模式、模型、搜索、记忆摘要与 Worker 存活（`ready`/`missing`/`unknown`），**不含密钥或 Base URL** |
| 页面"运行模式"角标 | 显示 `mock` |

Mock 模式用脚本化的假模型作答，**只能验证链路**（任务能建、能跑、Trace 能看、审批能点），
不能用来判断 Agent 聪不聪明。

## 3. 换成真实模型（个人模式）

细节见[个人模式操作手册](个人模式操作手册.md)第 2～4 节。最小步骤：

```powershell
Copy-Item .env.personal.example .env.personal   # 填 EVOAGENT_API_KEY / BASE_URL / MODEL / CONTEXT_WINDOW_TOKENS
.\.venv\Scripts\python.exe scripts/personal_preflight.py            # 本地校验，不联网、不花钱
docker compose -f docker-compose.yml -f deploy/personal/compose.yml up -d
```

**付费闸门默认是关的**：`EVOAGENT_BUDGET_*` 额度与价格假设没填时，付费模型调用会被
**直接拒绝**（这是设计意图，不是故障）。要跑真实模型，先按[付费与漂移闸门](evaluations/付费与漂移闸门-M0c.md)
填好 `EVOAGENT_BUDGET_SCOPE`、`EVOAGENT_BUDGET_TRIAL_LIMIT_MICROS`（或 `EVOAGENT_BUDGET_TOTAL_LIMIT_MICROS`）、
`EVOAGENT_BUDGET_TASK_LIMIT_MICROS`、`EVOAGENT_BUDGET_INPUT_PRICE_MICROS_PER_MILLION`、
`EVOAGENT_BUDGET_OUTPUT_PRICE_MICROS_PER_MILLION` 与 `EVOAGENT_BUDGET_STOP_RATIO`。
**这些金额由你决定**，程序不会替你编一个默认值；每次扣费都写进 `spend_records` 台账。

## 4. 发第一条任务

1. **登记项目**：页面"项目"里填项目根目录（例如 `D:\work\my-project`），选档位
   `read`（只读）或 `read_write`（可写），提交后目录被冻结成授权根。
2. **选项目并建任务**：对话页选该项目，写下任务与（可选的）显式验收条件，例如
   "回答里必须包含 `def render_summary(`"。验收条件不满足时任务终态是 `acceptance_failed`，
   不会算成功。
3. **看进度**：任务卡会显示步骤与当前动作；运行中可以在输入框补充约束
   （I-03），它会从下一个迭代边界生效。
4. **审批**：写文件、跑命令等动作按风险等级走审批；页面会出现待审批项，你也可以撤销项目授权
   （撤销后下一次工具调用即被拒绝，任务终态 `authorization_revoked`）。
5. **看证据**：任务详情里有 Trace（工具调用、结果摘要、审批决定、来源观察）。
   产物可在产物页预览并核对 SHA-256，哈希不一致会拒绝导出。

## 5. 能做什么、做不到什么

| 能力 | 现状 |
| --- | --- |
| 项目内只读理解（目录、搜索、分段读取） | 机制完整、受控测试通过；**真实模型的"读懂项目"未验证** |
| 精确修改（唯一匹配替换、补丁、冲突检测、dry-run diff） | 同上 |
| 受控命令执行与失败后修正 | 同上；宿主受限执行而非容器挂载 |
| 运行中补充约束、审批、取消、时间线 | 同上；真机断线重连与强杀一致性未验证 |
| 文件输入冻结与产物下载（含哈希核对） | 同上 |
| 编码/PDF 文本抽取与目录整理 | 本机目录整理验收 7/7（Mock）；真实模型未验证 |
| 公开资料调研与来源追溯 | 部分真实证据；完整多来源报告未通过 |
| Skill 自进化（提炼→评测→人工发布→回滚） | **机制完整、收益未证实**：M6 正式配对实验尚未运行 |
| 发布级回归（24 正常 + 8 故障/越权） | 样本已登记 32/32，**一次都没执行** |

完整缺口清单见[当前状态](当前状态.md)第 3 节。

## 6. 升级

```powershell
git fetch --all
git checkout <目标提交或标签>
docker compose build            # 前端与依赖一起重建
docker compose up -d postgres redis
.\.venv\Scripts\alembic.exe upgrade head    # 迁移；只前进，不回退
docker compose -f docker-compose.yml -f deploy/personal/compose.yml up -d api worker maintenance-worker eval-worker
```

- **先备份再升级**（下一节）。迁移脚本**不做数据回填猜测**；升级前的工作树与数据库要成对保留。
- 升级后核对 `http://127.0.0.1:8000/api/v1/runtime-info` 与 `alembic current`（应等于 `head`）。
- 演练记录（从零、迁移、备份恢复）见[M7 发布准备与分层检查](evaluations/M7发布准备与分层检查-2026-09-27.md)。

## 7. 备份与恢复

```powershell
# 备份（写入你自己选的位置）
docker compose exec -T postgres pg_dump -U evoagent evoagent > evoagent-backup.sql

# 恢复到一个新库（示例名 evoagent_restore），避免覆盖正在用的库
docker compose exec -T postgres psql -U evoagent -d postgres -c "CREATE DATABASE evoagent_restore"
docker compose exec -T postgres psql -U evoagent -d evoagent_restore < evoagent-backup.sql
```

- **工作区也要一起备份**：`evoagent-workspace` 卷里是产物与文件（`docker run --rm -v evoagent-workspace:/data ...` 或直接备份宿主目录）。
- 恢复后先用 `psql -c "select count(*) from tasks"` 之类核对行数，再切流量；`alembic_version` 表必须与备份前一致。
- 恢复演练的实际命令与结果见上述 M7 报告；**没有备份就等于没有发布版**。

## 8. 卸载与数据保留

```powershell
docker compose down          # 停容器，保留卷
docker compose down -v       # 连卷一起删：数据库、工作区、产物全部丢失，不可恢复
```

- 删卷前请确认已备份；`.env.personal`（私有配置）与宿主项目目录不在卷里，需自行处置。
- 记忆条目可以逐条撤销；Skill 版本可以禁用或回滚，都保留审计决策行。

## 9. 出问题先看哪里

| 症状 | 先看 |
| --- | --- |
| 页面打不开、`/health/ready` 失败 | [运营故障指南](运营故障指南.md)第 1 节（API/数据库/迁移） |
| 任务一直 `queued` | 同上第 2 节（Worker/Redis） |
| 任务失败并提示预算 | 同上第 3 节（付费闸门） |
| 工具被拒绝（越界/授权/命令） | 同上第 4 节（安全拒绝是预期行为） |
| 搜索或网页读取失败 | 同上第 5 节 |
| 编码/PDF 报错 | 同上第 6 节 |

## 10. 这份手册的边界

本手册的命令在本机与本次演练中跑过（第 6、7 节对应 M7 报告里的实测记录）；
**它不声称**：真实模型任务已通过、发布门槛已达标、或已在新装 Windows 上验证。
`v0.4` 的放行条件写在[M7 发布准备与分层检查](evaluations/M7发布准备与分层检查-2026-09-27.md)第 5 节。
