# EvoAgent 用户手册

> 适用 `0.4.0.dev0` 候选版。本页讲使用流程；安装命令分别见[Windows 可信本机模式](可信本机模式.md)和[Docker 个人模式操作手册](个人模式操作手册.md)。功能是否已通过真实任务验证，以[当前状态](当前状态.md)为准。

## 1. 开始前选择运行方式

Windows 可信本机模式在 Windows 用户会话中运行 API 和 Worker。页面可以登记 `D:\...` 这样的目录；获批的本机命令能使用你的 Windows 工具链，也可能访问项目外资源。Docker 个人模式把指定宿主父目录挂到容器的 `/app/projects`；页面应登记容器内路径，项目命令在 Linux Worker 中执行。两套模式使用不同的数据库和页面端口，数据不会自动同步。不要在一个模式的页面里照搬另一个模式的路径。

| 想做的事 | 选择 | 启动说明 |
| --- | --- | --- |
| 操作 Windows 项目、本机 Python/PowerShell 等工具链 | Windows 可信本机模式 | [配置与启动](可信本机模式.md)；页面 `http://127.0.0.1:18020/ui/` |
| 在容器内读改测项目，使用 Linux 工具链 | Docker 个人模式 | [配置与启动](个人模式操作手册.md)；页面 `http://127.0.0.1:8000/ui/` |
| 不花模型费用，只检查任务链路 | Mock 演示 | 根 README 的 CLI 或默认 Compose；结果不能证明 Agent 能力 |

真实模式需要支持 tool calling 的 OpenAI-compatible 对话模型、有效凭据、实际上下文窗口，以及你设置的试跑额度和价格假设。对话模型与搜索、Embedding 是不同服务。`.env.personal` 已被 Git 忽略，不要把密钥写入任务文本或提交。程序没有默认付费额度；未配置完整预算时会拒绝真实模型调用。

## 2. 发起任务

1. 打开相应页面，先检查运行模式、模型名和 Worker 状态。`ready` 只说明 Worker 在线；用一条实际任务确认模型能回答。
2. 可以直接创建**不绑定项目**的对话。需要文件能力时，先登记一个已存在的目录，选择 `read` 或 `read_write`。会话可以长期绑定一个项目；也可选“仅下一任务使用”，让这一条任务获得目录授权而会话保持不绑定。
3. 写清目标与可检验结果。例如：“读取这个项目的目录和测试，修复失败用例；复测相同命令，说明改动与退出码。”任务创建时冻结所用的项目和授权版本；此后切换页面项目不会改变在跑任务。
4. 任务卡会展示已提交的步骤。运行中可补充要求、排队后续任务或取消；补充要求从下一个 Agent 迭代边界生效，不会撤销已发生的动作。页面刷新后可回到同一会话和 Trace。
5. 工具需要审批时，核对工具名、目标路径、命令 argv 和预览差异，再决定。撤销项目授权会阻止在跑任务的**下一次工具调用**；已经发生的外部动作不会自动回滚。
6. 完成后看最终回答、工具结果、退出码、来源观察和产物。`completed` 表示任务运行完成，不保证开放式目标的事实正确性。

只读授权不会提供编辑与项目命令工具。可写授权让这些工具可用，但不意味着所有动作自动批准。Windows 本机命令始终逐次 R2 审批，且以当前用户权限运行；文件工具仍受登记根约束。详细边界见[安全边界说明](安全边界说明.md)。

## 3. 验收条件、来源与产物

可在任务上设置回答必须包含的文字、必须成功调用的工具、必须生成的文件及可选哈希。不满足时任务为 `acceptance_failed`；条件通过只证明**写明的条件**，不证明其余回答正确。任务文字仍须告诉模型具体要求，验收条件不会自动替你写提示。契约见[运行模式与任务验收条件](Agent运行模式与任务验收条件-2026-09-26.md)。

搜索结果的摘要和网页正文是两种证据：Trace 会区分“已读正文”“仅见摘要”“未观察到”。引用了真实 URL 也不代表来源支持结论；正式报告仍需逐条人工核对。`ddgs` 不用密钥但依赖公共网络，可能限流或不可用。

通过 `file_write` 或 `artifact_write` 登记的产物可在页面预览和下载。页面显示登记的 SHA-256，下载响应头 `X-Content-SHA256` 应与之相同；磁盘内容与登记哈希不符时导出会拒绝。文本提取支持明确的编码与文本型 PDF；扫描件没有 OCR。项目文件编辑不会自动把所有改动变成可下载产物，要交付文件时应让 Agent 使用产物工具。

## 4. 常见结果怎么理解

| 结果 | 含义与下一步 |
| --- | --- |
| `budget_exceeded` | 额度或价格假设未填、已到阈值；检查预算状态与账本，不要删账本绕过。 |
| `project_authorization_denied` / `authorization_revoked` | 根外路径、只读档位或运行中撤销；确认项目及授权后发新任务。 |
| `edit_conflict` / `input_changed` | 文件或冻结输入已变化；重新读取并基于新版本操作。 |
| `waiting_user` / `side_effect_unknown` | 副作用可能发生但结果不确定；先核对真实文件/外部状态，再在页面处理，不能盲目重试。 |
| `dependency_unavailable` / `rate_limited` | 前者是 Redis 等依赖不可用，后者是明确限流；排障方向不同。 |
| 产物下载 409 | 磁盘字节与登记哈希不一致；核对原因后重新生成。 |

按症状和部署模式排查见[运营故障指南](运营故障指南.md)。

## 5. 升级、备份与停机

`0.4.0.dev0` 未完成发布级验收。升级前保存**数据库与 Workspace 两部分**，同时记录当前 Git 提交、迁移 head、配置和 Docker 镜像。只备份数据库会丢失产物字节；只备份目录会丢失任务、会话与登记哈希。先在独立库/卷演练恢复并校验产物哈希，再升级日常实例。迁移使用 `alembic upgrade head`，不要手改 `alembic_version`。

Docker 个人模式停止应用而保留卷：

```powershell
docker compose -p evoagent-personal -f docker-compose.yml -f deploy/personal/compose.yml down
```

Windows 本机模式在运行窗口按 Ctrl+C 退出 API/Worker；若要停独立数据库：

```powershell
docker compose -p evoagent-host -f deploy/host/compose.yml down
```

两种模式都不要随手加 `-v`：它会删除对应数据库卷。Windows 本机模式的工作文件在 `output/host-mode/workspace`；Docker 个人模式的工作文件在 Compose 的 `evoagent-workspace` 卷。登记的宿主项目目录另行备份。带数据的旧版升级、数据库与工作区卷恢复的实测步骤见[M7 发布演练](evaluations/M7发布准备与分层检查-2026-09-27.md)第 8 节；那是同机演练，还不是新装 Windows 验收。

## 6. 产品边界

EvoAgent 是单人本地服务，没有公网认证/RBAC、多租户隔离、桌面 GUI 自动化或定时任务。Skill 机制具备提炼、审核、发布和回滚，但净收益未证实；M6 正式配对实验与 M7 的 24+8 发布任务、人工审查尚未完成。需要判断哪些已有真实证据、哪些只有代码与测试，请看[当前状态](当前状态.md)，不要用旧阶段报告推断当前成熟度。
