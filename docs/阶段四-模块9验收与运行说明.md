## 2. 发现与本地审核

先按[模块 8 运行说明](阶段四-模块8验收与运行说明.md)设置受信 fixture 或预设 HTTP Profile，创建 Server，显式 discover，保存返回的 server_id、catalog_id、配置版本和目录修订号。

本地批准某个工具：

```http
POST /api/v1/mcp/catalogs/{catalog_id}/reviews
Content-Type: application/json

{
  "expected_lock_version": 0,
  "tool_name": "fixture_echo",
  "approved": true,
  "risk": "R0",
  "effect": "read_only",
  "reviewer": "local-operator",
  "reason": "已核对受信 fixture 的文本回显实现"
}
```

上述风险仅适用于已核对的回显 fixture。新目录默认未批准、R3、non_idempotent_write；远端 `readOnlyHint=true` 不会替你批准。写分类至少 R2，仍需每次语义动作的运行时审批。一次工具审核只证明其固定目录契约可供选择，不代表批准所有具体参数。

## 3. 显式激活目录

```http
POST /api/v1/mcp/servers/{server_id}/execution
Content-Type: application/json

{
  "expected_lock_version": 0,
  "expected_execution_version": 0,
  "state": "active",
  "catalog_id": "填写刚审核的目录 UUID"
}
```

初始 execution_version 为 0，成功后加 1。响应返回当前版本；后续更新使用响应值。409 `mcp_execution_conflict` 表示执行状态已经改变，需要重新读取 Server 状态。`mcp_catalog_stale` 表示目录不属于当前配置的最新修订，重新发现并审核。

只有新普通 Run 会选择 active 目录中 approved 的工具。已冻结为空的 Run 不会因为此操作新增工具；baseline/pinned Skill 评测不接入 MCP。不存在“直接调用该 MCP 工具”的管理 API。模型必须在正常持久化 AgentLoop 中通过 ToolExecutor 调用稳定映射名。

映射名示意：`mcp_<UUID前8位>_fixture_echo_<16位hash>`。以模型实际工具清单、Trace 的 tool_name 为准，不用 Server 展示名拼接。

## 4. 调用与审批证据

一次成功调用可以在 Trace 中核对：

1. ToolCall.arguments 是实际 JSON 参数，没有 payload 包装。
2. execution_binding 含 Server、目录 UUID/hash、config_version、review_id、risk、effect、tool 原始定义和 policy_hash。
3. R2/R3 调用先进入审批等待，批准后才发送远端请求。
4. 写调用先创建 ToolEffect，再访问外部系统；成功后 COMMITTED。
5. 文本与 structuredContent 规范化成字符串结果；长正文走现有 Artifact / 预览机制。

审批操作沿用 `/api/v1/tool-approvals/{id}/approve` 或 reject。目录、审核或策略已变更时，旧批准不能跨契约复用。当前实现不自动把活动 Run 升级到新目录；需要按新目录重新审核、激活并新建 Run。

## 5. UNKNOWN 处理

写调用超时、连接断开、业务 isError 或输出不合约，都可能发生在外部已提交之后。系统不会因为收到错误就再次写入。重复语义动作被 Task 范围的旧账本拦截，并要求人工确认。

沿用现有审批响应约定：明确需要重试时使用 `response: "retry"`；已查明外部提交成功时使用 `response: "committed:<结果>"`。retry 是一次性确认，不是开启自动重放。若目录已经失效，应先核查旧外部动作，再按新契约安排后续任务，不以修改 hash/账本状态绕过检查。

## 6. 卸载和紧急禁用

正常卸载发送以下请求，版本替换为最新值：

```json
{
  "expected_lock_version": 0,
  "expected_execution_version": 1,
  "state": "draining"
}
```

目标仍是 `/api/v1/mcp/servers/{server_id}/execution`。先停止新 Run 选择和新调用；已有调用可以完成，本地连接随后关闭。其他执行进程在调用期间轮询数据库，空闲 Run 连接最迟随 Run 关闭；数据库 execution_state 保留 draining，便于管理者看见卸载意图。

紧急情况将 state 改为 `disabled`。本进程连接立即关闭，其他进程下一次检查取消调用；写结果未知仍保留 UNKNOWN。`/disconnect` 仅关闭当前管理进程连接，不是跨进程撤销执行授权，不能代替 disabled。

## 7. 故障定位

| 错误码 | 含义 | 处理 |
|---|---|---|
| invalid_arguments | 参数不符合冻结 Schema | 修正参数，不会发出 tools/call |
| mcp_persistence_required | 没有统一持久化执行中间件 | 使用 Worker/持久化 Runner |
| permission_denied | 本地 PermissionPolicy 拒绝 | 核查本地授权 |
| tool_manifest_changed | 配置、目录、审核或复用结果契约变化 | 重新审核并创建符合新契约的 Run |
| mcp_server_draining | 已停止新调用 | 等待卸载完成或显式恢复 |
| mcp_server_disabled | 已撤销执行 | 核查 Server 状态 |
| mcp_protocol_error | SDK 收到协议错误 | 核查 Server 实现，不自动重试 |
| mcp_tool_error | result.isError | 查远端业务回执；写可能已提交 |
| mcp_output_invalid | 输出不符合固定 Schema | 修复 Server，写结果人工核查 |
| unsupported_mcp_content | 返回图片/音频/资源等未支持类型 | 改用文本/structuredContent，不自动下载 |
| mcp_timeout / mcp_connection_closed | 超时/断连 | 只读有限重试，写进入 UNKNOWN |
