# ADR-001：阶段一运行时边界与安全策略

- 状态：已接受
- 日期：2026-09-06
- 适用版本：v0.1

## 背景

阶段一需要交付一个可以真实运行、可以确定性测试的最小 Agent。模型输出、文件路径和网络地址都属于不可信输入；同时，Agent 的循环控制、工具执行和一次任务的生命周期不能混在同一个对象中，否则错误、超时和终态事件很容易重复处理。

## 决策

### 1. 分离三层运行职责

- AgentRunner 管一次 Run：run_id、任务总超时、取消、唯一终态事件和 RunResult。
- AgentLoop 管模型与工具之间的迭代，不写 Run 终态事件。
- ToolExecutor 管单次工具调用：查找、参数校验、超时、错误规范化、截断和执行事件。

每个 Run 只能由 AgentRunner 写入一个终态事件。

### 2. Provider 使用统一事件协议

AgentLoop 只依赖 ModelProvider 协议。OpenAICompatibleProvider 负责把 SSE 文本增量、ToolCall 分片、Usage 和完成响应转换为 ProviderEvent，并拒绝不完整或自相矛盾的流。

v0.1 不做自动重试。是否重试取决于错误类型、幂等性和预算，留到后续阶段统一设计。

### 3. 工具调用默认顺序执行

只有一批工具全部满足以下条件时，ToolExecutor 才并发执行：

- `has_side_effects` 为 false；
- `parallel_safe` 为 true。

无论内部是否并发，ToolResult 都按原 ToolCall 顺序返回，保证模型消息关联稳定。

### 4. 文件工具限制在 Workspace

file_read 只能读取配置 Workspace 内的现有 UTF-8 普通文件。WorkspaceGuard 同时检查普通路径解析结果和符号链接解析结果，拒绝 `..` 穿越、绝对路径越界与符号链接逃逸。

### 5. 网络工具实施最低 SSRF 防护

web_fetch 只允许 HTTP/HTTPS，拒绝 URL 凭据、localhost 和解析到非公网地址的主机。每次重定向都重新校验目标，并限制重定向次数、请求超时、响应类型和响应大小。

### 6. 防止无进展循环

AgentLoop 对一批工具的名称、参数以及返回结果生成稳定指纹。连续得到相同指纹达到配置阈值时，以 `repeated_tool_calls` 结束，避免模型无限重复同一动作。

## 后果

优点：

- 各层可以独立测试和替换；
- 超时、取消和失败的归属清晰；
- 模型无法绕过 Executor 直接调用工具；
- 安全并发不会改变工具结果与调用 ID 的对应关系；
- 阶段一具备可演示的完整链路，同时保留后续扩展空间。

代价：

- Provider 适配器需要严格维护流式状态；
- 当前只支持 OpenAI-compatible Chat Completions 子集；
- 默认顺序执行牺牲了一部分性能；
- 安全检查不能替代操作系统级沙箱和网络隔离。

## 已知限制

v0.1 会先解析并校验域名，再由 HTTP 客户端建立连接。这两个动作之间存在时间差，尚未把已校验 IP 强绑定到实际连接，因此不能宣称完全防御 DNS 重绑定。后续版本应通过受控 DNS、固定连接目标、代理或网络出口隔离解决。

file_read 也不是进程沙箱。未来加入写文件、命令执行等高风险工具时，仍需要权限审批、独立工作目录和操作系统级隔离。
