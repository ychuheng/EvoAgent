### 3.1 已知缺陷（2026-09-27 校对源码与 CI 时发现）

| 位置 | 现象 | 影响 / 状态 |
| --- | --- | --- |
| `pyproject.toml` 的 pytest `pythonpath` | 只有 `["src"]`，而 `tests/unit/test_personal_preflight.py` 会 `from scripts.personal_preflight import validate`。本机用 `python -m pytest` 时仓库根恰好进了 `sys.path`，CI 直接调用 `pytest` 则不会 | CI 的 `test`（3.12/3.13）在**收集阶段**中断：`ModuleNotFoundError: No module named 'scripts'`，Python 测试矩阵自工作包 A 起一直失败。**已修**（`["src", "."]`），并在 CI 调用方式下复跑本机全量通过 |
| `scripts/phase4_migrations.py` | 升级到 `head`，但断言写死 `revision == "20260922_0012"`；当前 head 是 `20260926_0014` | 直接运行必然 AssertionError；`docs/reports/phase4-final-migrations.json` 里的“迁移通过”已不可复现。**未修**，改法是与 `alembic heads` 比较 |
| `api/routes/memory.py` + `memory/maintenance.py` | `POST /maintenance-jobs/{id}/retry` 只把 `failed` 改回 `pending` 并清错误，不重置 `attempts`；领取逻辑对 `attempts >= 3` 的任务直接再次置为失败 | 用满 3 次尝试的归档/擦除任务无法通过 retry 恢复，清理永久停住；测试只覆盖“首次失败即重试”。**未修** |
| `sandbox/client.py` | Worker 侧响应体上限 8 MiB，小于 guest 产物 base64 后的体积（8 MiB 原始 → 约 10.7 MiB） | 理论上会出现“controller 已发布 Artifact 并记 succeeded、Worker 报工具失败”的不一致；读到 `sandbox_output_limit` 时应按已发布产物核对。**未修** |

后三项属于产品代码缺陷，本轮只做记录与文档校正，未改动实现。

## 4. 下一步

按[个人通用 Agent 当前实现计划](EvoAgent-项目设计与分阶段实现计划.md)的 M0～M7 推进；每项只在拿到真实证据后才移入第 2 节。

1. **M0a 最小开发基线**：先建三条项目 dev 任务和 Mock 证据采集器，就可以启动 M1 开发。**M0b/M0c 正式验收闸门**再落实独立 holdout 台账、评分/第三方复核、M6 样本量、数值预算和状态漂移检查；旧 16 项不混算。
2. **M1 项目只读**：登记并冻结授权根，提供目录发现、搜索和分段读取；首个用户级验收是让 Agent 为真实仓库写有路径证据的模块地图。
3. **M2→I-01/I-02→M3 编辑/执行闭环**：精确补丁、冲突检测、可审查 diff；先接通最小 SSE 进度视图，再在同一项目视图运行测试，让 Agent 依据失败修正并复测。
4. **M4～M5 交互与日常任务**：完成运行中消息、重连与控制，再完成公开资料与文件输入/输出。旧 B-04 真实调研评测仍暂缓；无 Brave Key 可先用 `ddgs`。
5. **M6～M7 效果与发布**：真实轨迹验证 Skill 净收益，然后做冻结任务、故障、迁移、备份恢复和干净环境发布演练。
