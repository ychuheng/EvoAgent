## 1. 本次可运行的内容

| 模块 | 实际入口 | 关键行为 |
|---|---|---|
| 3 | PersistentAgentRunner → ContextStore | 超过输入预算 80% 时尝试压缩旧工具组，成功提交后才发送 |
| 3 | ToolExecutor → ToolOutputStore | 完整脱敏输出先归档，模型拿到受限预览与 ID |
| 3 | artifact_read | 仅当前 Run，按字符偏移分页，验证正文哈希 |
| 4 | TaskService / EvalCoordinator / finalize | 原子 goal 投影、稳定序号、终态幂等投影 |
| 5 | Memory API | 提议、确认、拒绝、撤销、词法查询、归档和 erase |
| 5 | JobWorker → MaintenanceWorker | 消费持久化维护任务，过期可接管，失败显式重试 |

没有自动向模型加载历史或长期记忆。`history_for_task()`、`bind_version()` 已提供后续模块需要的边界，当前不会因为确认了一条记忆就改变所有任务的提示词。

## 2. 升级

先停止旧 API/Worker，备份数据库和 Artifact 根目录，再运行：

```powershell
.\.venv\Scripts\alembic upgrade head
.\.venv\Scripts\alembic check
```

最新迁移为 `20260919_0006`。它新增九张表和消息/会话/任务字段，把所有旧 Session 归入默认 Workspace；旧 messages 按 `created_at,id` 编号并标记 `backfill=true`。它不从 run_events 重建全文，也不推断旧 Task 的历史截止点。

配置示例已将 `EVOAGENT_SNAPSHOT_SCHEMA_VERSION` 改为 `2`。若本地 `.env` 仍为 1，应先处理完旧任务再切换到 2。新运行默认使用 v2；旧活动快照没有转换器，配置或 Schema 不匹配时得到 `snapshot_incompatible`，应重新提交任务，不要修改旧哈希绕过检查。

正常启动原有 API 和 Worker 即可。维护任务由 `evoagent-worker` 在每轮领取普通 Task 前执行一次，不需要第二个常驻进程。API 单独运行只入队，不会自动完成 archive/erase。

## 3. 本地 API 操作

以下示例假设 API 在 `http://127.0.0.1:8000`，已有一个完成的普通任务及 Session。先设置真实的 Session ID：

```powershell
$base = 'http://127.0.0.1:8000/api/v1'
$sessionId = '<已有 Session UUID>'
$messages = Invoke-RestMethod "$base/sessions/$sessionId/messages"
$source = $messages | Where-Object kind -eq 'goal' | Select-Object -First 1
```

选取来源中确实存在的原话；例句必须出现在该用户 goal 中：

```powershell
$body = @{
    source_message_id = $source.id
    fact_key = 'response.language'
    content = '以后都用中文'
    kind = 'preference'
    scope = 'session'
} | ConvertTo-Json
$proposal = Invoke-RestMethod "$base/sessions/$sessionId/memories" -Method Post -ContentType 'application/json' -Body $body
$decisionUrl = "$base/sessions/$sessionId/memories/$($proposal.version_id)/decision"
$decision = @{ action = 'confirm'; expected_lock_version = $proposal.lock_version } | ConvertTo-Json
$confirmed = Invoke-RestMethod $decisionUrl -Method Post -ContentType 'application/json' -Body $decision
Invoke-RestMethod "$base/sessions/$sessionId/memories?query=中文"
```

不带 `query` 的 GET 用于管理所有候选和版本；带 `query`（可为空）只返回当前、确认、未过期、来源仍有效的版本。`expected_lock_version` 不匹配返回 409；先重新 GET，再由用户决定是否提交新操作。

候选提取：`POST /sessions/{sid}/memory-extractions/{message_id}`。默认识别明确长期意图。可选设置 `EVOAGENT_MEMORY_EXTRACTOR_MODEL` 并配置兼容 Provider；无论使用哪一种生成器，结果都停留在 proposed。

归档：`POST /sessions/{sid}/archives` 返回 job_id；通过 `GET /maintenance-jobs/{id}` 查询状态，再用 `GET /sessions/{sid}/archives` 读取结果。归档范围在入队时冻结，新消息不进入旧任务。

撤销：向 decision 接口提交 `action=revoke` 和当前锁版本。删除记忆正文：提交 `action=erase`；响应带 `maintenance_job_id`，表示已撤销并入队，不表示文件已经清理。检查维护任务 completed 后才可认为本次在线清理完成。失败任务使用 `POST /maintenance-jobs/{id}/retry` 重新入队。`GET /sessions/{sid}/memories/{version_id}` 可读取来源引用、审计事件和清理任务 ID。

## 4. 输出归档与压缩诊断

大型工具结果预览的第一行包含 `artifact_id`、`hash`、`total_chars` 和 `read_tool`。artifact_read 的 offset/limit 按 Unicode 字符计算，默认 2000，最大 8000；不接受路径或外部 Run ID。所谓完整输出是脱敏后的完整内容，不存在用于恢复密钥的私有副本。

如果文件保存失败，预览会明确标记 `artifact_store_failed`。若结果预算太小，可能无法携带完整引用；这会显示预算不足提示，不伪造“可回读”的 ID。工具外部动作是否成功仍由 ToolEffect 管理。

`context.summarized` 记录 revision_id 和压缩前后计数；`context.summary_degraded` 记录输入过大、达不到目标或归档失败。摘要失败时旧上下文仍需经过 ContextPolicy，超限则停止请求。恢复发现文件丢失或哈希错误返回 `context_artifact_invalid`。

压缩事务前失败：旧快照继续有效，磁盘可能留下未登记文件。事务后失败：读取已提交 v2 快照，复用冻结摘要与原计数，不重新消费已完成工具组。

## 5. 遗忘的验收边界

- revoke 使新查询失效；已绑定 Run 在每次请求前重新校验，旧快照不能恢复使用撤销版本。
- erase 清除指定 MemoryVersion 正文、相关会话归档，以及已绑定 Run 的快照、上下文 revision 正文、Artifact 文件和 Trace/结果正文；保留身份、内容哈希、序号和状态墓碑。
- 旧来源被 erase 后，归档任务拒绝从该来源重新生成摘要。已有用户原始 Message 不删除；这是会话记录，删除原始对话需要另一项明确操作。
- 已发送模型请求、外部工具动作、备份和存储介质历史不属于这次清理保证。文件删除失败时任务是 failed，不能显示 completed。
- 不自动删除未登记文件；需要独立的运维保留期和引用核查。
