# ADR-004：权限、副作用与数据库事件投影

- 状态：已采纳
- 日期：2026-09-08
- 范围：阶段二模块 9～12

## 背景

阶段二后半段需要同时解决高风险工具授权、Worker 崩溃时的副作用不确定性，以及客户端断线后的进度恢复。如果这些问题分别在具体工具、Worker 内存和 HTTP 连接中临时处理，系统会出现规则不一致、重复外部动作和事件丢失。

## 决策

1. ToolExecutor 通过可选 Middleware 统一调用 PermissionPolicy；阶段一纯内存执行不强制依赖数据库。
2. R2/R3 默认进入持久化 Approval，Task/Run 使用 WAITING_USER 表达暂停，用户决定后重新排队。续跑产生的新 call_id 不改变授权语义，同一 Task 中工具名和规范化参数相同的决定可以复用。
3. 有副作用的工具使用 Task 范围语义键维护 ToolEffect。COMMITTED 结果直接复用；EXECUTING 在恢复时转 UNKNOWN，只有人工确认后才能重试或视为已提交。
4. SSE 和 Trace 均从 PostgreSQL 的已提交记录投影，不直接消费 Worker 内存消息。RunEvent.sequence 同时作为 SSE 事件 ID 和续传游标。
5. Policy 与 Sandbox 分层：前者决定权限，后者强制资源边界。Shell 默认关闭，allowlist 不被描述为生产级进程隔离。

## 结果

- API 与 Worker 可以独立重启，客户端断线不会丢失已提交历史。
- 审批和 UNKNOWN 处理有数据库证据，可以审计并确定性测试。
- 系统可以避免重复执行已确认 COMMITTED 的动作，但不宣称对任意外部系统提供通用 exactly-once。
- 引入了更多持久化记录和恢复分支；每次工具调用的事务成本高于纯内存阶段一实现。

## 被否决的方案

- 在 Worker 中调用 `input()`：无法跨进程、无法在无人值守部署中恢复。
- 所有副作用失败后自动重试：无法区分“调用失败”和“调用成功但本地提交前崩溃”。
- 直接把内存事件推送给 SSE：API 或 Worker 重启后无法可靠补发。
- 只依赖 Shell 可执行文件白名单：允许的解释器仍可能执行任意代码，不能替代操作系统或容器隔离。
