## 3. 四条可重复 Demo

```powershell
.venv\Scripts\python.exe scripts/phase4_demos.py --demo all --output output/phase4-demos.json
# 也可分别指定 context、memory、mcp、workers
```

此入口是**自动化验收演示**，以 pytest 驱动真实业务服务和故障注入，不是额外的聊天页面。每条包括下表中的连续场景与补充回归，报告保存名称、结果和部分业务证据，不保存连接密码或完整测试异常文本。pytest stdout 留在本地终端，公开 JSON 只输出白名单内容。

| Demo | 正常路径 | 失败/阻断路径 | 环境 |
| --- | --- | --- | --- |
| context | 长工具历史压缩，估算 26583→12312；新建 CheckpointStore 恢复，迭代 5/累计 Token 15 保持 | Artifact 缺失拒绝恢复；提交前故障不产生半份修订；legacy feature-off 可运行 | 主场景 PostgreSQL；补充 SQLite/纯内核 |
| memory | Workspace 事实在第二 Session 可检索 | 跨 Workspace 不可见；撤销后新检索为空、旧绑定 Run 被阻断；删除失败可重试 | 主场景 PostgreSQL；清理补充 SQLite |
| mcp | 官方 SDK 启动 stdio fixture，发现、审核、激活、真实 tools/call | 目录变化不修改旧 manifest；旧契约拒绝；卸载拒绝新调用；写入不确定记 UNKNOWN | PostgreSQL + 真实 stdio 子进程；HTTP/故障补充 fixture |
| workers | PostgreSQL 双真实 Worker 进程处理 8 个任务；杀进程后替代 Worker 从恢复链路继续 | COMMITTED 不重放、UNKNOWN 等待人工；Redis 真实连接拒绝下 DB 任务仍可领取、外部配额 fail-closed | 双竞争 PostgreSQL；进程崩溃场景 SQLite；Redis 真服务/真实网络故障 |

“Redis 故障”通过占住但不监听的 loopback 端口制造真实连接拒绝，不关闭共享 Redis。它验证应用故障策略，不代表完成跨机器网络分区或 Redis 集群高可用验收。压缩使用确定性计数器，26583→12312 是该 fixture 的估算，不是模型账单。

脚本逐组执行，任何失败或 skipped 使该组 incomplete，最终非零退出；不会因为前三组通过就把缺依赖的 Worker 组算作通过。CI 已增加四组重放和每个 Python 版本的报告上传。

## 4. 新库、旧库与部署

```powershell
$env:EVOAGENT_FRESH_DATABASE_URL='postgresql+asyncpg://evoagent:evoagent@127.0.0.1:15432/evoagent_fresh'
$env:EVOAGENT_LEGACY_DATABASE_URL='postgresql+asyncpg://evoagent:evoagent@127.0.0.1:15432/evoagent_legacy'
.venv\Scripts\python.exe scripts/phase4_migrations.py
docker build -t evoagent:phase4-final .
docker compose -p evoagent-v04-final -f deploy/acceptance/compose.yml --profile app up -d --wait
.venv\Scripts\python.exe scripts/phase4_deployment_probe.py
```

迁移脚本拒绝有表的目标。fresh 直接 base→head，legacy 先到 0005，插入两条旧格式消息再升级，检查内容、顺序、backfill、哈希与 vector 扩展，并执行 alembic check。业务升级仍应先备份；本脚本的空库限制不能代替业务库备份。

部署 profile 使用 mock Provider、legacy 上下文、Memory/Archive 关闭、lexical 检索、无注册 MCP Server。probe 从 HTTP 创建 Session/Task，等待独立 Worker 终态，检查 committed 副作用、Context 和空 Memory/MCP 目录；再在 API 容器验证 `/app/workspace/artifacts/{run_id}/report.md` 存在且非空，确认共享卷。file_write 的文件不是已注册 ArtifactRecord，所以 artifact_count=0 不等于文件未生成。

生产数据库升级到 head 后再启动工作进程。API、普通 Worker、维护 Worker、Eval Worker 的职责与共享存储要求沿用[模块 11～12](阶段四-模块11至12验收与运行说明.md)。多主机共享 Artifact、认证/RBAC 和公网部署不在本阶段承诺内。

## 6. 真实模型结果与复现

`scripts/phase4_skill_eval.py` 在独占的新迁移库中运行；检测到已有 Run 会拒绝，防止误领用户任务和无意重复付费。脚本只使用当前进程环境配置，不读取或输出密钥文件内容；凭据在本地环境注入，不加入 Git。

```powershell
# 本地安全配置 Provider、API Key、base_url、model；不要把密钥写入脚本。
$env:EVOAGENT_DATABASE_URL='postgresql+asyncpg://evoagent:evoagent@127.0.0.1:15432/evoagent_quality'
.venv\Scripts\alembic.exe upgrade head
.venv\Scripts\python.exe scripts/phase4_skill_eval.py --repeats 2 --output output/real-skill.json
```

本轮使用 deepseek-flash、thinking=disabled；固定 384 输出上限、最多 4 轮、每 Run 累计预算 10000。两个 TRAIN 来源真实执行、确定性验证与脱敏冻结，再注入预先固定的人工算术 SOP；6 个 HOLDOUT 覆盖正常、边界、无定义和恶意引用，重复两次，baseline/pinned 唯一变量仍由旧比较规则校验。

26 个任务（2 训练+24 配对运行），已知用量 **71952 Token**。成功率两臂均 11/12，安全回归为 0，质量门禁通过，候选为 review_required，未发布。这只表示满足当前门禁，不表示成功率提升、统计显著性或整个任务域的效果都已合格。

两条失败答案都实际给出了 `−1.5`（U+2212）；字面验证器要求 `-1.5`（ASCII），属于验证器覆盖不足。原始 11/12 结果不改写，失败分析单独存档。下一版可增加数值等价验证，但必须版本化，不能用改规则后的分数替换当前冻结报告。

既有真实 Runtime 记忆实验两臂均 5/6；4K 上下文实验 bounded 两例均在调用前拒绝。它们仍是负面/边界证据，本次收尾没有宣称已修复。真实 Embedding 未配置；DeepSeek 官方公开文档目前未提供可用于本项目的 embeddings 接口。需要独立的兼容服务和 1536 维模型，再进行固定语义数据集与检索对照。

## 7. 发布门禁和剩余项

```powershell
.venv\Scripts\python.exe scripts/phase4_release_check.py

.venv\Scripts\python.exe scripts/phase4_release_check.py --allow-pending

```

manifest 的 SHA256 用于检测报告被改动，不签名、不自动判断报告内容正确，也不替代人工阅读。缺文件/哈希变化退出 1；缺验收退出 2；只有无缺口才允许正式完成标记。版本仍为 dev0，不自动打标签或发布软件包。

阶段四工程能力、四条验收 Demo、迁移、容器与页面回归已交付；**真实 Embedding 语义验收完成之前，不能登记正式 v0.4 全部完成**。后续效果改进还包括记忆无收益原因、受限上下文完成率及数值验证器完善。这些改进不通过降低门禁或删失败样本解决。

证据哈希统一将报告中的 CRLF 换行转换为 LF 后计算 SHA-256，避免 Windows 和 Linux 检出换行差异造成误报；其他内容变更仍会触发校验失败。发布门禁单元测试覆盖这一跨平台行为。
