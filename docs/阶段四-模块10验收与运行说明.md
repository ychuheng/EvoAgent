# 阶段四模块 10：独立执行容器与网络出口验收

## 1. 交付范围与证据边界

模块 10 已实现固定容器规格、独立 controller、Shell 接入、输入 staging、输出 Artifact、租约/取消清理、孤儿回收、MCP 容器 stdio 通道以及 web_fetch 的实际 IP 绑定。迁移为 `20260921_0010`，包版本继续为 `0.4.0.dev0`。

本地 Windows / Python 3.13 验收为 **378 passed、22 skipped**。其中 11 项是显式启用的 Linux Docker 测试，10 项需要 PostgreSQL 环境，1 项需要 Windows 符号链接权限。本机没有 Docker，未获得真实容器隔离通过证据。CI 已增加真实 sandbox 验收任务，但配置存在不等于该任务已通过。阶段四总验收中的 Docker 项保持未勾选。

本版仅支持 `network=none` 执行容器。公开网页由 Worker 的受控 web_fetch 获取；没有任意联网容器、通用出口代理、容器凭据注入或长期后台 MCP 服务。controller 单实例，共享 Docker 内核不提供敌对多租户隔离承诺。

## 2. 先升级代码和数据库

```bash
python -m pip install -e ".[dev]"
alembic upgrade head
alembic current
```

应看到 `20260921_0010`。新表 sandbox_executions 保存容器与租约证据。升级前保留数据库备份；不要在仍有执行或 UNKNOWN 效果时降级删除证据。依赖新增 websockets 15，原 MCP SDK 继续固定 1.30.0。

默认 `.env.example` 不启用 Shell。`EVOAGENT_SHELL_ALLOWED_EXECUTABLES` 只保留旧受信 fixture 兼容，不能启用持久化 Worker 的宿主执行。

## 3. 准备 Linux Docker 执行镜像

在 Linux Docker 主机执行，registry 地址替换为自己的可信仓库。构建前审查镜像内容，生产构建还应固定基础镜像 digest。

```bash
docker build -f deploy/sandbox/Dockerfile -t REGISTRY/evoagent-sandbox:reviewed .
docker push REGISTRY/evoagent-sandbox:reviewed
docker image inspect REGISTRY/evoagent-sandbox:reviewed --format '{{index .RepoDigests 0}}'
```

复制输出的 `REGISTRY/evoagent-sandbox@sha256:...`，不能把示例占位符或 tag 放进运行 Profile。目标 daemon 必须事先 pull 该 digest，controller 不会自动拉取。CLI 和 daemon 必须使用同一台主机的 `/var/run/docker.sock`；不支持远程 Docker context 或 Windows daemon。

镜像包含只依赖 Python 标准库的 `/opt/evoagent/runner.py`。脚本在 `/output` 下运行，根目录只读；不要将依赖安装安排到执行阶段。预检拒绝镜像 VOLUME，并要求 Linux cgroup 的 CPU、内存、swap、PIDs 及默认 seccomp 支持。

## 4. 配置 Profile、私有 token 与目录

设置如下变量；以下 JSON 中的镜像需要替换为上一步的真实 digest：

```dotenv
EVOAGENT_SANDBOX_PROFILES='{"python":{"image":"REGISTRY/evoagent-sandbox@sha256:REPLACE_WITH_64_HEX","mode":"job","allowed_executables":["/usr/local/bin/python"]}}'
EVOAGENT_SHELL_SANDBOX_PROFILE=python
EVOAGENT_SANDBOX_CONTROLLER_URL=http://sandbox-controller:8090
EVOAGENT_SANDBOX_CONTROLLER_TOKEN=REPLACE_WITH_RANDOM_TOKEN_AT_LEAST_32_CHARACTERS
EVOAGENT_SANDBOX_STAGING_ROOT=/var/lib/evoagent-sandbox
EVOAGENT_MCP_LAUNCH_PROFILES={}
```

可用 `python -c "import secrets; print(secrets.token_urlsafe(48))"` 在部署终端生成 token，然后保存在私有配置中，不提交仓库。API、Worker 和 controller 使用相同 Profile 与 token；Profile hash 比较完整规范配置，不只比较名字。

在宿主创建 staging 目录，容器内外必须使用同一个 Linux 绝对路径。仅 controller 挂载它和 Docker socket。不要映射 controller 端口到公网。叠加文件还给 controller 访问 Artifact 卷所需的 DAC_OVERRIDE；执行容器本身仍 drop ALL。

```bash
sudo install -d -m 0700 /var/lib/evoagent-sandbox
docker compose -f docker-compose.yml -f deploy/sandbox/compose.yml config --quiet
docker compose -f docker-compose.yml -f deploy/sandbox/compose.yml up -d --build
```

避免把完整 `compose config` 输出上传日志，其中可能包含 token。迁移服务成功后 controller 才启动。controller 启动必须能访问 Docker；同一 daemon 只运行一个 controller，并始终使用同一 staging 根。

## 5. Shell 正常路径与输出核查

Shell 仍经过原有 Policy、Approval 与 ToolEffect。R2 动作按既有规则审批，不能把 controller 的内部接口作为业务调用捷径。模型工具参数示例：

```json
{"argv":["/usr/local/bin/python","-c","from pathlib import Path; Path('answer.txt').write_text('hello', encoding='utf-8'); print('done')"],"input_artifact_ids":[]}
```

成功后工具结果包含 stdout 和 Artifact 摘要，Run Trace 增加 sandbox_executions。检查 execution_id、container_id、lease_epoch、profile_hash、status；Artifact attributes 应包含相同 execution_id/epoch 和 original_name。确认没有遗留执行容器：

```bash
docker ps -a --filter label=evoagent.sandbox=1
```

需要输入时先使用当前 Run 已有 Artifact，并把 UUID 放入 input_artifact_ids；程序读取 `/input/<UUID>`。跨 Run、hash 不匹配、超限或越界的输入会拒绝。输出只接受单层普通文件，目录、链接、FIFO、设备及路径穿越全部拒绝。多个文件逐个发布，不承诺整组原子性。

## 6. MCP 容器 stdio 配置

将第三方 Server 的依赖和固定入口预先安装进经过审查的镜像，然后配置一个 mode=stdio 的 SandboxSpec，例如：

```json
{
  "offline-mcp": {
    "image": "REGISTRY/offline-mcp@sha256:REPLACE_WITH_64_HEX",
    "mode": "stdio",
    "stdio_command": ["/usr/local/bin/python", "-m", "your_reviewed_server"],
    "timeout_seconds": 30
  }
}
```

将它合并进 EVOAGENT_SANDBOX_PROFILES；EVOAGENT_MCP_LAUNCH_PROFILES 设置为 `{"offline-server":{"sandbox_profile_id":"offline-mcp"}}`。API 仍只保存 launch_profile_id，沿用模块 8 的注册/发现/审核和模块 9 的显式目录激活步骤。Profile 变化进入目录 hash，旧契约不得静默继续。

容器 stdio 不接受 secret_ref，不继承宿主环境，不联网，连接受总时限约束。需要联网或凭据的 Server 尚不支持这条路径。原受信宿主 fixture 需要显式 trusted_fixture=true；不得借此启动第三方程序。内部 WebSocket 只搬运官方 SDK 的 JSON-RPC，不是新的 MCP 标准协议。

## 7. 自动测试与真实验收

本地契约回归：

```bash
ruff check .
ruff format --check .
pytest
```

Linux Docker 正式测试：

```bash
export EVOAGENT_RUN_DOCKER_TESTS=1
export EVOAGENT_TEST_SANDBOX_IMAGE='REGISTRY/evoagent-sandbox@sha256:REAL_DIGEST'
pytest -q tests/integration/test_docker_sandbox.py
```

该组共 11 项，包含 cgroup 参数及 CPU 实际节流、内存/进程/磁盘/输出耗尽、进程树超时、直连公网及 IPv4/IPv6 元数据阻断，以及链接/FIFO/目录拒绝。显式开启后缺少环境直接失败。保留测试日志、镜像 digest、Docker/内核版本和执行后容器列表，才能登记真实验收。

CI 的 sandbox job 在 job 本地 registry 推送测试镜像以取得 RepoDigest，不发布项目生产镜像。其结果与 PostgreSQL 测试 job 分别记录；FakeDriver、MockTransport 和受信 MCP fixture 不证明容器隔离、公网 TLS 或敌对第三方程序安全。

## 8. 故障恢复与关闭功能

| 现象 | 检查和处置 |
|---|---|
| Shell permission denied | 检查是否选择了 job Profile；不要启用宿主 fallback |
| controller 请求被拒 | 核对私有 token、Profile hash、租约与 Trace 记录 |
| 启动失败 | 检查 daemon、固定 digest、资源支持、staging 锁 |
| sandbox_command_failed | 命令返回非零；执行记录为 failed |
| cleanup_pending | 恢复 Docker 通道，确认 rm 与不存在检查完成；清理器会重试 |
| UNKNOWN | 核对 ToolEffect 与 Artifact，按既有人工结果确认流程处理 |
| 旧 epoch 发布失败 | 属于租约隔离预期行为；不能复活旧执行者 |
| MCP 通道中断 | 检查时限、消息预算、启用状态与配置版本，确认容器回收 |

正常重启先取消在途执行并清理。强制崩溃后，controller 根据执行记录与 label 回收遗留容器，不重新运行命令。终态写入后立即崩溃可能残留 staging 文件，停机核对记录及路径后再清理，不能删除整个 Workspace。

关闭 Shell 时清空 shell_sandbox_profile，并先处理在途任务；关闭第三方 MCP 时按模块 9 流程 draining/disabled。确认无遗留容器后才能停止 controller。不要仅删除 socket 挂载或停止 controller，留下无法确认的在途执行。
