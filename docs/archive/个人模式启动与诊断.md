## 首次配置

在仓库根目录将 `.env.personal.example` 复制为 `.env.personal`，填写模型服务的 API Key、Base URL、模型名和**该模型实际支持的**上下文窗口。私有文件被 Git 忽略。不要将凭据放入命令行参数、提交到仓库，或使用会打印完整环境的 `docker compose config` 输出。

若服务与已验收的 DeepSeek 工具调用配置相同，可参考 `.env.personal.example` 中的 `EVOAGENT_PROVIDER_THINKING_MODE` 注释；其他服务不要盲目沿用该选项。DeepSeek 对话密钥不提供 Embedding。真实网页搜索另需将 `EVOAGENT_SEARCH_PROVIDER` 设为 `brave` 并填写 `EVOAGENT_SEARCH_API_KEY`；未配置时保持 Mock，页面会明确提示。

先做不访问远端、不消耗模型额度的本地检查：

```powershell
Copy-Item .env.personal.example .env.personal
# 编辑 .env.personal 后：
.\.venv\Scripts\python.exe scripts/personal_preflight.py
docker compose -f docker-compose.yml -f deploy/personal/compose.yml config --quiet
```

`personal_preflight.py` 只检查私有文件中的必需字段和 `Settings` 约束，成功时输出模型名及搜索模式，不输出密钥或 Base URL。它不证明模型可连通，也不检查 Docker、数据库或 Worker 是否已启动。若提示缺字段、非法窗口或 Brave 缺 Key，先修改私有文件。配置文件可保留在本机供下次启动使用。

## 启动与首条任务

```powershell
docker compose -p evoagent-personal -f docker-compose.yml -f deploy/personal/compose.yml up -d --build --wait
```

打开 `http://127.0.0.1:8000/ui/`。首页显示模型和搜索模式；先发一条普通对话，再发一条明确要求使用 calculator 的任务，在“查看执行过程”中核对模型、工具结果与最终状态。`/health/ready` 只证明 API 能查询数据库；模型远端与 API/Worker 的一致性以实际 Task 为准。若任务长时间处于队列，先用 `docker compose ... ps` 检查 Worker 是否在运行；若任务失败，在执行过程和 Trace 中查看错误码。

页面现在会显示任务 Worker 的探测结果。`Worker 在线` 表示 API 最近从 Redis 看到 Worker 的带过期时间存活标记；`未检测到在线 Worker` 表示 Redis 可读但没有有效标记；`Worker 状态无法判断` 表示未配置 Redis 或暂时无法查询。存活标记不是远端模型探针，也不保证 Worker 能成功执行本任务。任务排队超过 30 秒时，页面另给出 Worker 检查提示；这个提示只表示任务尚未被领取，不直接断定 Worker 故障。模型认证、网络和协议问题仍要依据任务执行后的错误码判断。

| 页面或 Trace 错误码 | 先核对什么 |
| --- | --- |
| `provider_auth_error` | 模型服务的 Key、账户权限和 Base URL；错误信息不会显示远端响应正文。 |
| `provider_rate_limit` / `provider_server_error` | 服务额度、限流或服务端状态；查看任务的重试记录。 |
| `provider_network_error` / `provider_timeout` | 容器到模型服务的网络、代理与超时配置。 |
| `provider_configuration_mismatch` | API 与 Worker 是否读取同一份 `.env.personal`，修改后是否都已重启。 |
| `search_auth_failed` / `search_forbidden` | Brave 搜索 Key 与访问权限；该错误只在真实搜索模式下出现。 |
| `search_rate_limited` / `search_service_unavailable` | 搜索服务额度及状态；当前适配器不会自动退避重试。 |
| `search_timeout` / `search_network_error` / `search_invalid_response` | 搜索网络或返回格式；不能把失败结果当成来源。 |

若搜索工具返回 `[]`，表示该次查询没有结果，应更换查询或说明资料不足；它不是已核对的引用。工具成功也不等于网页正文已经读取，仍需从执行过程区分 `web_search` 与 `web_fetch`。

执行详情中的“网页来源证据”会列出搜索查询、提供方、结果 URL，以及已读取页面的最终 URL、访问时间和原始字节 SHA-256。答复中的 HTTP(S) 链接被标为“已读取正文”“仅见搜索摘要”或“未见检索或读取记录”。这只核对链接与工具记录的对应关系；即使标为“已读取正文”，也仍要人工核对该网页是否真的支持相关结论。搜索返回的摘要和动态网页的可见内容可能不一致。网页读取失败时不会出现“已读取正文”记录，需查看对应工具失败原因。

关闭时使用相同项目名和两个 Compose 文件执行 `down`，不要附加 `-v`，以保留会话、任务与 Workspace。此入口默认占用本机 8000、5432、6379 端口；如这些端口已被其他服务使用，应使用单独的端口覆盖层并保持本机环回绑定，不能直接修改已有验收环境或业务库。
