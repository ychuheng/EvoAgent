# 阶段三演示与安全边界

本文用于复现 v0.3 的完整 Skill 生命周期，也明确演示没有证明哪些生产能力。所有命令都在项目根目录执行。

## 1. 演示前准备

创建虚拟环境、安装依赖并复制配置：

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python -m pip install -e ".[dev]"
Copy-Item .env.example .env
```

演示会创建数据库记录和 Artifact。为了不污染日常数据库，建议在 `.env` 中为演示设置单独的 PostgreSQL 数据库；学习时也可以使用 Workspace 内的 SQLite 文件。正式并发语义仍以 PostgreSQL 为准。

先升级 Schema：

```powershell
.\.venv\Scripts\alembic upgrade head
```

## 2. 数据集演示

仓库提供 `evals/datasets/open-source-research-v1.json`，共 24 条可重复 Case：12 条 TRAIN 用于来源资格，12 条 HOLDOUT 只用于候选评测。导入器只允许读取 `EVOAGENT_EVAL_DATASET_ROOT` 内的 UTF-8 JSON。

```powershell
.\.venv\Scripts\evoagent-eval-dataset open-source-research-v1.json --freeze
```

重复执行会按名称、版本和内容哈希返回同一数据集；同名同版本但内容不同会冲突。冻结后不能修改 Case。

## 3. 一条命令观察完整生命周期

```powershell
.\.venv\Scripts\evoagent-phase3-demo
```

演示按下列顺序运行：

```text
导入并冻结 24 条数据
→ 准备两个独立 passed TRAIN 来源
→ 清洗并冻结来源 Trace
→ 提炼第一版 DRAFT
→ 在 HOLDOUT 上运行 BASELINE/PINNED_SKILL 配对
→ 冻结报告并通过硬门禁
→ 人工批准为 ACTIVE
→ 提炼一个故意发生正确性回退的版本
→ 即使它 Token 更低，门禁仍拒绝
→ 提炼并发布第三版，旧版变为 RETIRED
→ 人工回滚到仍兼容、曾通过门禁的第一版
→ 普通 RETRIEVAL Task 只命中回滚后的 ACTIVE 版本
```

成功输出中的随机 UUID 每次不同，但以下事实必须稳定：`case_count` 为 24，第一版 `gate_passed` 与 `published` 为 true，回退版 `gate_passed` 为 false，回滚后的 `active_version_id` 等于第一版 ID，检索结果也只包含第一版 ID。

这个命令使用确定性生成器和模拟完成记录，用于验证生命周期与数据库契约，不把它包装成真实模型效果数据。真实效果必须启动 Worker，在相同配置下执行真实 paired Run 后读取报告。

## 4. 真实进程闭环

阶段三进程职责如下：

```text
API                 接收数据集、评测和人工管理命令
Eval Worker         持有实验租约、释放每对任务、验证和收尾
普通 Worker         真正调用 Provider 与工具执行每个 Task
PostgreSQL          保存任务、实验、状态、事件和报告引用
Artifact Store      保存冻结来源与不可变评测报告
React 管理页         展示 Skill、版本、diff、门禁、Pair 和人工操作
```

启动：

```powershell
.\.venv\Scripts\evoagent-api
.\.venv\Scripts\evoagent-worker
.\.venv\Scripts\evoagent-eval-worker
```

完整流程需要通过 API 创建/取得 DRAFT 后启动评测。实验完成后显式调用：

```text
POST /api/v1/eval-experiments/{experiment_id}/finalize
```

该写操作冻结 EvaluationReport、运行 QualityGate 并推进 SkillVersion。随后打开 `/ui/` 查看证据，在 Review 页面批准或拒绝。GET 报告接口只读取，不会偷偷推进生命周期。

## 5. 退化、未知和不可比较怎样显示

- Skill 成功率低于 baseline：正确性硬门禁失败；
- 任一任务族发生回退：即使总体持平也失败；
- DENIED 或 UNKNOWN Effect 增多：安全硬门禁失败；
- Provider 没报告 Usage：Token 为 `unknown`，不伪造为零；
- 两边配置指纹不一致：Pair 标记为 `not comparable`，不能拿来宣称改善；
- 两边没有同时通过：效率差不参与比较，但失败样本仍进入正确性统计。

## 6. 安全边界

阶段三已经保证：

- HOLDOUT 私有 Validator 参数不会进入 CandidateGenerator，也不会由数据集列表 API 返回；
- Skill 是声明式 JSON 数据，不执行模型生成的 Python；
- PINNED_SKILL 只由内部评测创建，普通 Task API 拒绝；
- Skill 上下文不能扩大 PermissionPolicy、Approval、ToolEffect、Sandbox 的权限；
- 发布必须同时满足已通过门禁、报告哈希一致和人工决定；
- 回滚必须同 Skill、已退休、曾通过门禁且当前兼容；
- 乐观锁冲突返回稳定错误，不静默覆盖另一位操作者的决定。

阶段三没有保证：

- 没有登录、身份认证、RBAC、多租户和多人审批；
- reviewer 是调用者填写的本地审计标签，不是可信身份；
- 没有生产级容器/进程强沙箱或完整网络出口隔离；
- 小数据集没有统计显著性承诺；
- 不会自动发布，Eval Worker 也没有发布权限；
- 不包含长期记忆、MCP、多 Agent 编排或多 Provider 自动路由。

因此管理 API 和 `/ui/` 当前只适合本地学习或受信网络，不应直接暴露到公网。
